# RCMS·통합 Ezbaro 개요 — 프롬프트 v4 단일 실행 비교

- 실제 Qwen 호출 1회, 재시도 0회, 35.427초. 동일한 원문·PDF·입력 범위(PDF 3–6페이지)를 사용했다.
- 출력 토큰: v3 2,655 → v4 964.
- 개요와 주요 과업의 text 글자수: 1,864 → 479.
- 전체 text 및 의견·확인사항·한계 글자수: 4,535 → 1,198. JSON 키와 evidence_pages 숫자는 제외했고 문장 속 페이지 표기는 포함했다.
- 사업 개요 3 → 1개 문단, 주요 과업 4 → 3개 업무 묶음.

## 내용 대조

RCMS 전환, Ezbaro 신규 연계, 통합 검증·운영 전환으로 과업이 묶였다. 사업금액 153,000,000원(VAT 포함), 계약 후 6개월, 기존 RCMS 일몰일 이전 전환, 운영기관 규격·일정 의존성이 남았다. 이전 출력의 월별 예시 일정 배치 추정과 분리발주 검토가 불필요하다는 과도한 의견은 사라졌다.

개요에 종료일이 들어가 일정 항목과 중복되고, 일정 미확정 설명도 핵심 조건과 추가 확인 사항에 반복된다. 참여연구원·증빙자료 연계는 과업 요약에 명시되지 않아 세부 범위는 PDF 4페이지 대조가 필요하다. 요약 품질을 승인된 것으로 판단하지 않는다.

## 검증 실패 원인

Qwen이 few-shot의 사람이 읽는 표기를 따라 text 끝에 `(PDF 3페이지)` 등을 넣으면서 evidence_pages도 함께 냈다. 숫자·영문 명칭 검사는 이 표시의 숫자와 PDF라는 단어까지 사업 사실로 검사해 실패했다. 원응답을 수정하거나 실패 상태를 통과로 변경하지 않았다.

원인 확인만을 위해 메모리 사본에서 문장 끝의 PDF 표기를 제외해 검사했을 때 나머지 동일한 기계 검사는 통과했다. 이는 진단이며 보정한 결과를 성공으로 발행한 것이 아니다. 후속 프롬프트에서는 text에 페이지 표시를 넣지 않고 evidence_pages에만 기록하도록 명시하고, 예시 표기와 JSON 변환의 경계를 더 분명히 해야 한다. 이번 실행 이후 추가 모델 호출이나 정책 변경은 하지 않았다.
