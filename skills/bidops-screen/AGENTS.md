# 1차 판정 모듈 작업 규칙

## 범위

이 모듈은 검증 표본을 회사 프로필과 대조해 구조화 1차 판정을 작성하고 `screening-decisions.json`을 `screening-results.json`으로 검증·병합하는 계약을 소유한다. 공고 수집, 첨부 심층 분석, 웹 DB 적재, HTML 표현은 이 모듈의 범위가 아니다.

## 경계

- 수집 JSON의 공고 사실을 고치거나 후보군을 재선정하지 않는다.
- 회사 프로필의 `unknown`을 외부 지식이나 모델 추론으로 확정하지 않는다.
- 보고서 또는 UI 편의를 위해 누락 관점·확인 항목·반론을 병합기가 만들어내지 않는다.
- 향후 Qwen 호출은 별도 오케스트레이터에서 수행하고, 이 모듈의 병합기는 모델 SDK나 웹 DB에 의존하지 않는다.

## 불변 조건

- 판정은 기술 적합성, 실적 정합성, 공공 SI 적합성, 사업성·자격 제약, 전략 부합을 정확히 한 번씩 포함한다.
- 각 관점은 관점 고유의 이유와 `confirmed|inferred|unknown` 상태의 근거를 최소 한 건 가진다.
- 등급과 참여 준비 상태는 독립적이며 교차 조건을 모두 검증한다. `부분 확인 필요`는 확인 항목 없이 통과할 수 없다.
- 공고별 반론은 최소 한 건이고 같은 상투문이 전체 판정의 40%를 넘으면 실패한다.
- 수행실적 신호가 있는 공고는 매칭 이유와 한계를 남긴다. 유사도가 법적 실적 인정을 뜻하지 않는다.
- 병합기는 표본과 판정 ID를 일대일 대조하고 값은 추가·보정하지 않는다.

## 구현 패턴

판정 스키마 변경은 새 버전으로 추가하고 기존 버전을 소급 변경하지 않는다. Qwen 연결 시 자유 Markdown보다 제한된 단계별 JSON을 사용하며 스키마·근거 위치·교차 필드 검사는 모델 밖 코드에서 수행한다. 검증 실패는 명시적 오류가 되고 자동 폴백이나 자동 보정으로 숨기지 않는다.

## 테스트

`python3 -m unittest discover -s skills/bidops-screen/tests -p 'test_*.py' -t skills/bidops-screen -v`를 실행한다. 다섯 관점 누락/중복, 각 enum, 제외와 준비 상태 조합, 차단 확인 항목, 반복 반론 40% 경계, 수행실적 연결 누락, 표본 ID 누락/중복을 포함한다. 계약 변경은 `./run-tests.sh`의 교차 단계 테스트도 통과해야 한다.
