# 보고서 렌더링 모듈 작업 규칙

## 책임

이 모듈은 검증된 선별 결과를 사람이 읽는 HTML과 호환 피드백 YAML로 결정적으로 변환한다. 등급 산정, 누락값 보정, DB 리뷰 저장, 첨부 분석, 알림 전송은 수행하지 않는다.

## 경계

- 수집·판정 규칙을 import하거나 다시 구현하지 않는다.
- 입력 JSON을 수정하지 않고 순수 렌더링으로 표현한다.
- `unknown`, `null`, `값 없음`, `계산 불가`를 0이나 확정값으로 바꾸지 않는다.
- YAML 파일로 DB의 기존 리뷰를 덮어쓰지 않는다. YAML은 비어 있는 양식, 호환 가져오기, 내보내기 형식이다.
- HTML에 내부 파일 경로, 자격증명, prompt, 모델 원응답, 회사 프로필 전문을 넣지 않는다.

## 표현 불변 조건

- 같은 입력은 timestamp처럼 계약상 허용된 가변 필드를 제외하고 같은 내용을 만든다.
- 등급, 참여 준비 상태, 다섯 관점, 근거 상태, 반론, 반론 처리, 확인 항목, 부분 실패 경고를 입력 의미 그대로 표시한다.
- 등급과 준비 상태를 하나의 배지나 색으로 합치지 않는다.
- 색만으로 등급·경고·차단을 전달하지 않고 문자 라벨과 구조적 표시를 함께 제공한다.
- evidence locator와 사람이 확인할 다음 행동을 읽을 수 있게 유지한다. excerpt는 허용된 짧은 범위만 표시한다.
- 과거 결과에 필드가 없으면 누락으로 표시하고 호환 판단을 생성하지 않는다.

## 피드백 계약

- YAML schema는 `bidops.feedback.v2`다.
- 모든 공고의 안정 ID와 빈 리뷰 자리를 포함한다.
- 빈 답변은 등급·준비 상태 변경으로 해석하지 않는다.
- 사람이 입력한 review field를 정렬·표현할 수는 있지만 의미를 바꾸거나 자동 채우지 않는다.

## 검증

```bash
python3 -m unittest discover -s skills/bidops-report/tests -p 'test_*.py' -t skills/bidops-report -v
```

한글 UTF-8, HTML escaping, 미확인·null·0 구분, 등급·준비 상태 문자 라벨, evidence locator, 부분 실패, 피드백 schema, 같은 입력의 재현성을 검사한다. 연결 계약 변경은 루트 `./run-tests.sh`도 실행한다.
