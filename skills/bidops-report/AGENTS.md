# 보고서 렌더링 모듈 작업 규칙

## 범위

이 모듈은 검증된 판정 결과를 사람이 읽는 HTML과 호환 피드백 YAML 양식으로 결정적으로 변환한다. 등급 산정, 누락값 보정, DB 리뷰 저장, 첨부 분석은 이 모듈의 범위가 아니다.

## 경계

- 수집·판정 기준을 import하거나 다시 구현하지 않는다.
- 화면을 보기 좋게 만들기 위해 `unknown`, `null`, `계산 불가`를 확정값이나 0으로 바꾸지 않는다.
- 기존 DB 리뷰를 YAML 파일로 덮어쓰지 않는다. DB 연동은 웹 API의 내보내기 책임이다.

## 불변 조건

- 같은 입력은 바이트 수준의 시간 가변 필드를 제외하고 같은 내용의 보고서를 만든다.
- 등급, 준비 상태, 다섯 관점, 근거 상태, 반론, 확인 항목을 입력 의미 그대로 표시한다.
- 색상만으로 상태를 구분하지 않고 모든 등급·경고에 문자 라벨을 제공한다.
- 피드백 YAML은 `bidops.feedback.v2` 스키마와 모든 공고의 안정 ID를 포함하며 빈 답변을 판정값으로 만들지 않는다.

## 구현 패턴

표현 변경은 입력 모델을 변형하지 않는 순수 렌더링으로 구현한다. 새 필드가 없을 수 있는 과거 결과는 누락 상태를 명시적으로 표시하되, 호환 기본 판단을 생성하지 않는다.

## 테스트

`python3 -m unittest discover -s skills/bidops-report/tests -p 'test_*.py' -t skills/bidops-report -v`를 실행한다. 한글 UTF-8, HTML 이스케이프, 빈/미확인 표시, 등급·상태 라벨, 피드백 스키마, 동일 입력 재현성을 포함한다. 전체 연결 변경은 `./run-tests.sh`도 통과해야 한다.
