# 수집·표본 모듈 작업 규칙

## 범위

이 모듈은 나라장터 공개 API 원문 수집, 정규화, 고재현율 후보 신호 생성, 감사층을 포함한 검증 표본 선정을 소유한다. 회사 적합성의 의미 판정, 첨부 본문 해석, 최종 등급, HTML 표현은 이 모듈의 범위가 아니다.

## 경계

- `web/backend`의 DB 모델이나 서비스를 import하지 않는다. 출력 JSON이 유일한 연결 경계다.
- `bidops-screen`의 판정 enum이나 리포트 표현을 이용해 후보를 잘라내지 않는다.
- 예산·지역·자격의 미확인을 자동 제외 조건으로 바꾸지 않는다.
- API 원문을 정규화 결과로 대체하거나 API 키를 원문·로그·산출물에 남기지 않는다.

## 불변 조건

- `BIDOPS_G2B_API_KEY`는 환경에서만 읽고 오류 메시지와 저장 파일에서 마스킹한다.
- 수집 결과는 안정 `notice_id`, `source_type`, 원문 상대 경로, `unknown_fields`, 후보 편입 신호와 그 출처를 보존한다.
- `focus_matches`는 제목·분류·기타 출처를 구분한다. 일반적인 조달 분류 라벨을 제목 근거와 같은 강도로 취급하지 않는다.
- `candidate_sources`가 비어 있지 않은 공고만 `candidate_pool`이고 나머지는 `audit_pool`이다. 후보군은 적합 판정이 아니다.
- 표본은 분석층과 감사층을 모두 가지며 감사층을 제외 정답으로 해석하지 않는다.
- 동일 원문과 설정으로 실행한 정규화·표본 선정은 같은 결과를 내야 한다. 무작위 표본은 고정 가능한 시드를 사용한다.

## 구현 패턴

새 API 필드는 원문 값을 보존한 뒤 명시적 정규화 함수에서 변환한다. 의미가 불확실하면 빈 기본값보다 `unknown_fields`로 노출한다. 후보 규칙은 사용자가 편집할 정책 계층으로 옮길 수 있도록 신호 추출과 편입 판단을 분리하되, 기존 스크립트 출력 의미를 제자리에서 바꾸지 않는다.

## 테스트

`python3 -m unittest discover -s skills/bidops-collect/tests -p 'test_*.py' -t skills/bidops-collect -v`를 실행한다. API 페이지네이션·재시도·빈 응답, 시간대, 안정 ID, 제목과 분류 신호의 구분, 임계값 경계, 감사층 구성, 원문 재분류, 키 마스킹을 포함한다. 파이프라인 계약에 영향이 있으면 프로젝트 루트의 `./run-tests.sh`도 통과해야 한다.
