# 백엔드 모듈 작업 규칙

## 범위

이 모듈은 FastAPI REST 계약, SQLAlchemy·PostgreSQL 17 정본, 산출물 적재, 회차·리뷰·첨부·기관 포털·프로필·지표, 로컬 파이프라인 프로세스 실행을 소유한다. SQLite는 migration input/격리 테스트만 허용한다. 수집·판정 규칙의 원본 구현과 React 화면 표현은 이 모듈의 범위가 아니다.

## 경계

- `skills` 코드를 서비스 모듈로 복사하거나 내부 함수를 import하지 않는다. 파일 계약과 별도 프로세스로 연결한다.
- 프론트엔드 요구에 맞춰 DB 모델을 API 응답으로 그대로 노출하지 않는다. Pydantic 응답 모델에서 계약을 정의한다.
- 모델 호출기나 변환기에 DB 세션과 임의 파일 시스템 쓰기 권한을 넘기지 않는다.
- 사용자 제공 파일명으로 저장 경로를 만들거나 첨부 루트 밖 경로를 반환·삭제하지 않는다.

## 불변 조건

- PostgreSQL `bidops` schema가 live 정본이며 사용자 리뷰와 Lean report는 append-only DB 기록이다. SQLite WAL backup은 one-time migration input이고 YAML 재적재가 기존 기록을 덮어쓰지 않는다.
- 회차와 정책·문서 버전 결과는 불변이다. 재실행은 새 행을 만들고 이전 행에는 관계만 기록한다.
- 핵심 식별자·등급·준비 상태가 없는 판정은 적재하지 않는다. 비핵심 누락은 경고와 실제 값만 저장하고 생성값으로 채우지 않는다.
- `null`, 0, 빈 문자열, 계산 불가는 서로 다른 상태다. 응답 직렬화에서 임의로 합치지 않는다.
- 업로드는 HWP/HWPX/PDF, 50MB 이하, 서버 생성 경로를 강제하고 요청 실패 때 생성된 파일을 정리한다. `origin=manual`만 삭제한다.
- 파이프라인 하위 프로세스의 API 키와 키 파라미터는 로그 저장 전에 마스킹한다.
- 사용자 이름 입력이 구현되면 변경·정책 승인·외부 전송 승인에는 비어 있지 않은 이름과 감사 이벤트가 필수다. 이름을 권한 인증으로 사용하지 않는다.

## 구현 패턴

설정은 `pydantic-settings`와 `BIDOPS_` 환경변수로 주입한다. 라우터는 얇게 유지하고 파일·적재·분석 상태 전이는 서비스에서 처리한다. 다중 파일 업로드는 모든 파일 저장과 DB 반영을 하나의 논리 작업으로 취급해 중간 실패 시 해당 요청의 파일과 트랜잭션을 되돌린다. 장시간 변환·모델 실행은 요청 스레드에서 끝날 때까지 기다리지 않고 실행 ID와 단계 상태를 반환한다.

## 테스트

`cd web/backend && .venv/bin/pytest`를 실행한다. API 변경은 성공 응답과 400/403/404/409/422 실패를 함께 검증한다. DB 변경은 기존 데이터 복사본의 기동·적재·리뷰 보존, 회차 불변성을 포함한다. 첨부는 확장자·크기 경계·경로 이탈·심볼릭 링크·부분 실패 정리·제공 첨부 삭제 거부를 포함한다. 모델/변환 작업은 타임아웃, 잘린 JSON, 검증 실패, 재시도 멱등성, 무승인 OpenAI 차단을 포함한다.
