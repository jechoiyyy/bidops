# 엔지니어링 노트

## 대형 단일 Qwen 호출이 끝나지 않거나 숫자를 틀린다

- 증상: 약 81페이지 HWP를 한 프롬프트로 `qwen3.8:27b`에 넘겼을 때 입력이 11만 토큰을 넘고, 사고 모드 출력이 길이 제한에 걸리거나 요구사항 수·하드게이트 수가 원문과 달라진다.
- 원인: 문서 구조화, 전 영역 판단, 보고서 서술, 자기검증을 한 호출에 맡기면 긴 문맥에서 계수와 분류 경계가 약해진다. 모델의 자연어 자기검증은 결정적 검사가 아니다.
- 대응: 문서 구조화 → 자격 → 요구사항 묶음 → 평가 → 위험 → 종합 순으로 나누고 각 단계는 제한된 JSON 스키마로 받는다. 요구사항 ID·배점·금액·기간은 코드로 원문과 대조한다. 고정 파일에서 단계별 결과가 재현되고 오류가 검증기에 잡히는지 확인한다.

## 소방예방정보시스템 사례의 요구사항 수가 54와 55로 갈린다

- 증상: 모델 분석은 54개 요구사항이라고 쓰지만 HWPX 구조에서 유일한 요구사항 ID를 세면 55개가 나온다.
- 원인: 긴 표의 행 경계와 페이지 경계를 모델이 병합하거나 하나를 누락했다. 원문 HWPX에는 `COR-006`, `555.2`, `Requirement`처럼 기존 텍스트 파싱에서 잘리던 내용도 남아 있었다.
- 대응: 요구사항 표를 먼저 ID 기준으로 추출하고 유일 개수·중복·누락을 결정적으로 계산한 뒤 모델에는 ID 목록과 해당 원문 범위를 함께 준다. 이 사례는 검증 픽스처로 유지하고 결과가 55개인지 확인한다.

## HWP 텍스트 파서와 HWPX 변환 결과가 다르다

- 증상: HWP 직접 파싱 결과의 일부 문장이 잘리고 표 셀 또는 요구사항 ID가 빠지는 반면 변환된 HWPX에서는 내용이 복원된다.
- 원인: HWP 바이너리 스트림 해석과 문서 레이아웃 병합 방식이 복잡하고, 사용한 직접 파서가 모든 구조를 보존하지 못했다.
- 대응: 운영 경로는 원본 HWP 보존 → 헤드리스 HWPX 변환 → HWPX 구조 추출로 고정한다. 변환기 버전과 파일 해시를 기록하고 대표 HWP를 한컴 변환 결과와 대조한다. 표 수만 맞추지 말고 요구사항 ID와 알려진 절단 문구가 보존되는지 확인한다.

## 새 클론에서 대시보드 수집 건수가 0이 아니라 값 없음이다

- 증상: 표본과 판정은 보이지만 수집 건수와 후보 수가 `값 없음`으로 표시된다.
- 원인: `data/runs/*/raw`와 `collected-notices.json`은 용량 때문에 커밋되지 않으며, 실제 0건과 파일 부재를 구분해 DB에 `null`로 남긴다.
- 대응: 화면이나 지표 코드에서 `null`을 0으로 치환하지 않는다. 수집 통계가 필요하면 API 키로 새 수집을 실행하고 적재한 뒤 건수를 확인한다.

## 부분 과거 산출물이 적재되지만 경고가 남는다

- 증상: 관점·반론·확인 항목이 부족한 과거 판정도 화면에 보이고 수집 실행 화면에 계약 경고가 표시된다.
- 원인: 생성 파이프라인은 엄격하지만 표시 계층까지 통째로 거부하면 축적된 판정을 검토할 수 없다.
- 대응: 식별자·등급·준비 상태가 없으면 해당 판정을 거부하고, 나머지는 존재하는 값만 적재한다. 누락을 만들어 채우지 말고 경고 수와 세부 항목이 API와 화면에 남는지 확인한다.

## 리뷰 YAML과 DB가 다르면 DB가 정본이다

- 증상: `review-feedback.yaml`을 손으로 바꿔도 이미 적재된 리뷰가 화면에서 바뀌지 않거나, 내보낸 YAML이 원본 파일과 다르다.
- 원인: 수동 YAML 입력이 지속되지 않아 리뷰 정본을 SQLite로 옮겼고 YAML은 초기 가져오기·호환 내보내기 수단만 남았다.
- 대응: 리뷰 수정은 API를 사용한다. 외부 워크플로에 파일이 필요하면 `/api/reviews/export`로 새로 내보내고, 재적재가 기존 DB 리뷰를 덮어쓰지 않는지 확인한다.

## 프론트엔드가 없어도 백엔드는 기동된다

- 증상: `/api/health`는 정상인데 화면 경로는 `빌드된 프론트엔드가 없습니다`라는 503을 반환한다.
- 원인: FastAPI는 `web/frontend/dist/index.html`이 있을 때만 SPA를 마운트하고, API 진단을 막지 않도록 빌드 부재를 비치명 상태로 둔다.
- 대응: `web/frontend`에서 `npm run build` 후 다시 접근한다. 백엔드 장애로 오인하지 말고 `/api/health`와 `dist/index.html`을 각각 확인한다.

## `계산 불가`와 0을 합치면 지표 의미가 뒤집힌다

- 증상: 관점이 하나뿐인 과거 산출물이나 리뷰가 없는 회차의 지표가 0%로 보여 품질이 나쁜 것으로 해석된다.
- 원인: 분모나 비교 대상이 없는 상태와 측정 결과가 실제 0인 상태를 같은 숫자로 표현했다.
- 대응: 계산 전 필요한 입력 존재를 검사하고 없으면 값과 사유를 함께 `null`로 반환한다. 프론트엔드는 빈 게이지와 `계산 불가` 문구를 표시하는지 확인한다.

## Docker 산출물 파일 소유자가 달라진다

- 증상: 컨테이너가 만든 `data`·`reports` 파일을 호스트 사용자가 수정하거나 지우지 못한다.
- 원인: 컨테이너 UID/GID와 호스트 사용자가 다르다.
- 대응: `id -u`, `id -g`를 확인해 `.env`의 `BIDOPS_UID`, `BIDOPS_GID`에 설정하고 컨테이너를 다시 만든다. 새 파일 소유자가 호스트 사용자와 같은지 확인한다.

## 파이프라인 로그에 키처럼 보이는 문자열이 섞일 수 있다

- 증상: 하위 프로세스가 환경변수 또는 `serviceKey` 파라미터를 출력하면 수집 로그에 비밀이 남을 수 있다.
- 원인: 웹 실행기는 API 키를 하위 프로세스 환경에 전달해야 하고 외부 오류 메시지를 그대로 수집할 수 있다.
- 대응: 키 실제 값과 알려진 키 파라미터 형식을 저장 전 마스킹한다. 성공·실패 테스트 모두에서 실제 키 문자열이 로그 응답과 DB에 없는지 확인한다.

## 컨테이너에서 만든 venv가 호스트에서 실행되지 않는다

- 증상: 컨테이너에서 `python -m venv web/backend/.venv`를 만든 뒤 호스트의 `./web/run-web-tests.sh`가 `.venv/bin/python`을 실행하지 못한다.
- 원인: venv의 Python 링크가 컨테이너 안의 `/usr/local/bin/python`을 가리키며, 그 절대 경로가 호스트에는 없다.
- 대응: host 검증용 venv는 host Python 3.12+로 만들고 잠금 파일을 설치한다. 컨테이너 검증은 venv를 bind mount로 만들지 말고 이미지 안 Python으로 fresh SQLite migration과 pytest를 실행한 뒤, 저장소에 깨진 `.venv`가 남지 않았는지 확인한다.
