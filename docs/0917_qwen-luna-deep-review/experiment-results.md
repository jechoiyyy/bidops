## 1. Qwen v2 페이지 계획

결과 위치:

```text
/mnt/c/Users/rootlab/Downloads/sample/qwen-v2-page-plan-20260917-172202
```

최신 Luna 수정안과 동일한 입력 JSON, 시스템 프롬프트와 `local.page-plan.v2` 스키마로
`qwen3.8-27B`를 실행했다. generation은 사설 vLLM 승인값인 thinking 비활성,
temperature 0.7, top_p 0.8, top_k 20, seed 0이었다.

| 문서 | 구간 수 | 입력 토큰 | 출력 토큰 | 합계 | 시간 |
|---|---:|---:|---:|---:|---:|

| 반도체 | 16 | 26,825 | 2,769 | 29,594 | 96.95초 |
| 대구 | 9 | 9,364 | 2,027 | 11,391 | 63.37초 |
| 합계 | 45 | 84,829 | 9,211 | 94,040 | 321.90초 |

검증 결과는 3건 모두 schema와 문서 ID가 유효했고, 범위 오류·설명되지 않은 페이지·선택과
제외 충돌이 없었다.

| 문서 | Qwen overview | Qwen deep_review | 확인 사항 |
|---|---|---|---|
| 소방 | 3~8쪽 | 5~94쪽 | 기존 Luna 심층 근거를 모두 포함했고 5~6·62쪽이 추가됨 |
| 반도체 | 3~6쪽 | 4~60쪽 | 심층에서 3쪽 과업 개요가 빠져 기존 요약 항목 1개에 영향 가능 |
| 대구 | 1~5쪽 | 1~20쪽 | 필요한 원문을 보존하지만 심층 입력은 문서 전체 |

Qwen 분할은 구형 Qwen 결과의 개요 현황 누락과 소방 50~54쪽 누락을 해소했다. 다만 심층
선택 범위가 대부분의 문서를 포함하므로 이 결과만으로 분할 비용이 절감된다고 말할 수 없다.

## 2. Luna medium 개요·심층 요약

결과 위치:

```text
/mnt/c/Users/rootlab/Downloads/sample/luna-medium-review-summary-20260917-144029
```

실행 조건:

- 모델 `gpt-5.6-luna`
- reasoning `medium`
- 격리된 `codex exec`

모델 호출을 사용하지 않았다.

## 3. HWPX와 PDF 비교

주요 결과 위치:

```text
/mnt/c/Users/rootlab/Downloads/sample/qwen-hwpx-pdf-overview-ab-20260917-173725
/mnt/c/Users/rootlab/Downloads/sample/hwpx-pdf-overview-ab-20260917-173238
```

양산문화재단 127쪽 원본 HWPX/PDF 쌍의 분할·개요 A/B에서 두 입력 모두 개요 3~11쪽을
선택했다. PDF 텍스트는 페이지 경계에서 표 행 순서가 바뀌어 문화예술인 공동창작소 상태를
잘못 연결했고 HWPX는 원문 상태를 보존했다.

| 형식 | 분할 입력/출력 | 개요 입력/출력 | 전체 토큰 | 전체 시간 |
|---|---:|---:|---:|---:|
| HWPX | 56,288 / 3,267 | 4,331 / 2,146 | 66,032 | 196.14초 |
| PDF | 57,138 / 4,481 | 4,233 / 2,295 | 68,147 | 238.33초 |

HWPX는 이 단회 실행에서 PDF보다 전체 토큰이 2,115개(3.1%) 적었다. 출력 차이에는 생성
변동이 포함되므로 형식만의 절감률로 일반화하지 않는다.

기존 HWP 3건을 rhwp로 변환했을 때 HWPX 페이지 수와 페이지 텍스트가 이전 PDF 실험 입력과
완전히 같았다. 이전 PDF 시험 입력 자체가 rhwp 페이지 텍스트에서 만들어졌기 때문이다.
동일 JSON 직렬화와 프롬프트라면 입력 토큰도 같다.

해당 변환 실험은 당시 사용자 결정에 따라 검증 옵션 없이 수행됐다. 후속 공식 입력은 새 합의에
따라 `rhwp export-hwpx --verify`로 다시 만들고 그 결과를 별도 snapshot으로 기록한다.

## 4. 현재 제품 코드에서 확인한 사실

정본 심층 정책 `analysis-policy-lean-v1.json`은 `qwen3.8-27B`와 세 단계를 사용한다.

| 단계 | 실제 모델 입력 |
|---|---|
| `requirements_and_evaluation` | 모든 문서 페이지의 전체 텍스트를 excerpt로 만들고 bounded slice로 분할 |
| `delivery_risk_economics` | 모든 문서 페이지의 전체 텍스트를 다시 분할하고 회사 profile slice를 추가 |
| `synthesis_and_validation` | 앞 두 단계의 검증된 claim과 evidence만 전달 |

1단계와 2단계의 source slice 상한은 각각 약 18,000자와 15,000자이고, 개별 페이지 excerpt는
최대 약 8,000자다. 현재 코드에는 Qwen page plan의 `purposes`를 이용한 단계별 페이지 routing이
없다.

현재 개요 정책도 `qwen3.8-27B`를 사용한다. 과거 Luna 결과는 운영 정책이 아니라
`unmeasured_reference` 참조 실행이다.

## 5. 품질 판정 한계

- 모든 모델 실행은 단회 참조 실행이다.
- 사람 gold 기반의 완전한 채점이 없다.
- 분할 페이지 recall은 기존 Luna 선택 범위와 요약 근거에 대한 비교이며 원문 전체의 정답
  recall이 아니다.
- 일정표 시각 표시, 시스템 구성도와 일부 이미지 내용은 텍스트만으로 충분히 검증되지 않았다.
- Qwen 심층 요약과 같은 입력의 Luna 재실행이 없으므로 현재 산출물끼리 모델 우열을 확정할 수
  없다.
