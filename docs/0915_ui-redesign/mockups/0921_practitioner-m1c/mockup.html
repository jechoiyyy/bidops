③ 바뀌는 것과 고를 것

두 안 모두에서 바뀌는 것

  1. 1분할 틀을 공용 `SplitWorkspace`로. 화면별 틀과 복제 CSS를 지웁니다. 비율(38%)은 그대로라 눈에 보이는 차이는 작습니다.
  2. 2상세 머리가 스크롤해도 위에 붙습니다. 발주계획·사전규격과 같은 `StickyDecisionHeader`. 긴 상세에서도 어느 사업인지 놓치지 않습니다.
  3. 3발주기관 강조 블록을 같은 부품으로. `AgencyFeature` — 네 화면의 상세 머리가 같은 모양.
  4. 4네 화면 교차 검사의 빈칸을 채웁니다. `explore-workspace-consistency.spec`이 두 화면을 "아직 통일하지 않은 화면"으로 비워 두었습니다.
결정 — 목록 행 (위 `목록 행` 단추로 비교) A안 · 표 유지(권장). 지금처럼 열 머리가 있는 표(Astryx `Table`)를 두고 글자 크기·행 간격만 공용 값에 맞춥니다. 사업 추적은 행마다 `다음 확인` 단추가 있고 Go/No-Go는 `사람 결정` 열이 있어 열 구조가 뜻을 가집니다. 바뀌는 코드가 적어 회귀 위험이 작습니다. B안 · 발주계획과 같은 행. 사업명 → 발주기관 → 상태 줄 → 칩 줄의 네 줄 리듬으로 네 목록이 완전히 같은 모양이 됩니다. 대신 두 화면의 행 컴포넌트를 새로 써야 하고 키보드 이동(↑↓)·선택 표시를 다시 맞춰야 합니다. 뒤 작업(예산·마감 열 추가, 시안 M5)에서 열이 늘어날 예정이라 표 쪽이 받기 쉽습니다.
