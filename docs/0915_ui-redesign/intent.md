# Intent: 관리 화면 흰 바탕·초록 포인트 재설계와 사전규격 두 화면 재구성

작성: 기획부 사업기획(요청) · Claude(정리). 상태: 결정 반영(2026-09-15 권장안 승인). 기준일: 2026-09-15.
시안 정본: [`mockups/`](mockups/) (C 기준 8화면, Claude 디자인 캔버스
"사전규격 목록 재설계 시안" 첫 페이지와 동일). 시안과 이 문서가 어긋나면 시안이
이기고, 시안이 §제약의 업무 규칙과 어긋나면 업무 규칙이 이긴다. 이 폴더는 이전
`docs/` 문서 체계와 독립이다. 이전 문서는 2026-09-15에 의도적으로 삭제됐고, 이 작업의
근거는 이 폴더의 세 문서와 `mockups/`에서 새로 쌓는다.

## 문제

- 현재 관리 화면은 무드보드 파생 팔레트(짙은 남색 사이드바 `#161B2F`, 회색빛
  canvas `#F2F0EF`, slate accent `#5B687C`)를 쓴다. 사용자는 흰 바탕을 기본으로
  회사 포인트색 `#75A03B` 하나만 쓰는 밝은 화면을 원한다.
- `/pre-specs` 목록의 우측 정보 영역은 상세 화면을 탭 세 개로 축소해 넣은
  구조라, 담당자가 추적 여부를 판단하려면 탭을 오가고 스크롤해야 하며 추적
  조작은 대화상자 뒤에 숨어 있다.
- `/pre-specs/:noticeId` 상세는 2열(읽기 열 + 400px 판단 열)이라 사업 요약과 추적
  결정, 근거와 위험이 좌우로 흩어져 위에서 아래로 읽히지 않는다.
- 목록 선택 도구에 `전체 해제`만 있고 현재 페이지를 한 번에 선택할 수단이 없다.

## 제안하는 결과

- 모든 관리 화면이 같은 셸을 쓴다: 옅은 회녹 바탕 `#F6F7F4` 위에 흰 카드(그림자,
  반지름 14px), 밑줄형 탭, 선 최소화. 포인트 `#75A03B`는 활성 메뉴·선택 행·진행
  표시·완료 칩에만 쓰고, 단추 채움과 링크 글자는 한 단계 진한 `#587A2B`를 쓴다.
  레이아웃(사이드바 223.2px · 상단바 68.4px · 목록 38% 분할 · 각 화면의 구성)은
  그대로 둔다.
- 목록 우측 영역은 1280×800에서 스크롤 없이 사업명·기관·사업 설명, 주요 과업
  요약, 예산·일정, 주의사항 한 줄, 추적 조작과 상세 진입을 한 화면에 보여 준다.
- 상세는 세로 보고서형 6단으로 위에서 아래로 읽힌다: ① 사업명·기관·요약·예산·
  일정 → ② 추적 결정(요약 바로 아래, 본문과 함께 스크롤) → ③ 주요 과업과 수행
  범위 → ④ 참여 조건·회사 적합성·위험 및 미확인 사항 → ⑤ 근거 문서·첨부 →
  ⑥ 처리 이력·문서 준비·검토 실행.
- 목록 도구줄에 `전체 해제` 옆 `전체 선택`이 생기고, 현재 페이지에 표시된 건만
  기존 선택에 더한다.

## 제약

- 기존 수집·분석 데이터만 쓴다. 새 분석·모델 호출·정보 추출 방식 변경은 없다.
  값이 없으면 `미확인`(또는 계약이 정한 `판정 없음`·`번호 미확인` 등)으로 남긴다.
- 적합성 등급 · 추적 결정 · 참여 준비 · 최종 Go/No-Go는 서로 대신하지 않는다. 이 두
  화면이 정하는 것은 추적 시작 하나이며, 보류·추적 종료는 사업 추적에서, 입찰 참여
  여부는 최종 Go/No-Go에서만 사람이 정한다.
- 화면은 테마 토큰만 읽고 `:root`나 화면 CSS에서 `--color-*`를 재정의하지 않는다.
  레이아웃은 프로젝트가 소유하고 Astryx 컴포넌트는 그 안에 놓인다. Astryx
  `TokenName`이 닫힌 union이라 새 색은 `--bo-*` 프로젝트 토큰으로 둔다. 텍스트 4.5:1, 상태를 식별하는 비텍스트 3:1을 대비 게이트가
  강제한다. `#75A03B`는 흰 바탕에서 3.07:1이라 **글자와 흰 글자 채움에 쓰지
  않는다.**
- 데스크톱·노트북 전용 1280~1920px, 검증 viewport 1280×800과 1440×900이다.
  기존 90% 표시 크기를 native compact CSS 치수로 유지한다. 전역 `zoom`은 쓰지 않는다.
  1280px 미만은 가로 스크롤이며 새 레이아웃 분기를 만들지 않는다.
- 기존 상세 순회(이전/다음), 첨부 접근(검증된 절대 HTTP(S) URL만), 근거 확인,
  검토 실행(범위 확정·문서 준비·개요 재실행), 미저장 입력 보호를 그대로 유지한다.
- 픽셀 기준선(`tests/pixel-screens.spec.ts-snapshots/`)은 게이트가 아니라 회귀
  기준선이다. 교체는 변경 사유·영향 화면·승인자·승인 시각 기록과 함께만 한다.

## 결정 (2026-09-15, 권장안 승인)

1. **성공 의미색은 포인트 초록 계열로 옮긴다.** `--color-success` `#3F5A1C`,
   `--color-success-muted` `#F1F6E8`. 경고·실패·정보의 의미색은 그대로 두어 포인트와
   경쟁하지 않게 한다. 종전 "의미색은 무드보드가 정하지 않는다" 규칙은 이 팔레트에서
   "성공만 포인트 계열, 나머지는 별도 hue"로 바뀐다.
2. **등급 ramp는 초록 4단이다.** 2단 `검토 권장`이 주 단추와 같은 `#587A2B`인 것을
   허용한다. 등급은 항상 글자를 동반하므로 채움색이 겹쳐도 뜻이 섞이지 않는다.
3. **`개요 검토 다시 실행` 단추는 그리지 않는다.** 개요 재실행은 지금처럼 문서 준비
   패널 안에서만 연다. 상세 ⑥의 머리 단추는 `문서 준비 열기/닫기`와
   `심층 검토 보고서 열기 →` 둘이다.
4. **최종 Go/No-Go의 `결정 전 확인` 목록과 `추정 가격` 칸은 이번 범위가 아니다.**
   필요하면 별도 요구로 받는다.
5. **이전 `docs/` 문서는 의도적으로 삭제됐다.** 되돌리지 않고, 이 작업의 문서는
   `docs/0915_ui-redesign/`에서 새로 쌓는다.
