# 모델 품질 게이트

이 문서는 `qwen3.8:27b` 판정 결과를 상시 운영에 사용할 수 있는지 확인하는 방법을 정한다. 품질 게이트는 판정 품질을 측정하고 정책·프롬프트·모델 버전의 활성화 여부를 판단하는 절차이며, 입찰 제출·발주처 연락·최종 참여 결정은 실행하지 않는다. 확인되지 않은 값은 `unknown` 또는 `계산 불가`로 남기며 통과값으로 바꾸지 않는다.

## 1. 기준선과 측정 범위

기준선은 2026-08-17~23 회차의 Claude 판정 파일이다. 기준선 파일은 [`data/runs/20260817-20260823/screening-decisions.json`](../data/runs/20260817-20260823/screening-decisions.json)이며, 확인된 `judgments` 항목은 40건이다. 이 파일의 판정과 입력 표본을 기준선으로 고정하고, 같은 입력 표본에 Qwen을 적용해 항목별로 비교한다.

| 구분 | 기준 |
|---|---|
| 기준선 모델 | Claude |
| 비교 모델 | 사내 Ollama의 `qwen3.8:27b` |
| 비교 표본 | 기준선 파일의 40건과 동일한 `notice_id` 표본 |
| 입력 조건 | 기준선이 사용한 공고 입력·회사 프로필 범위와 동일하게 고정한다. 입력 범위가 달라지면 같은 측정으로 취급하지 않는다. |
| 추적 버전 | 모델 이름·모델 버전·프롬프트 버전·정책 버전·회차를 기록한다. |

기준선과 Qwen의 일치율은 모델 이식 전후의 비교값이다. 재현성 게이트의 주 측정은 같은 Qwen 모델·프롬프트·정책·입력을 다른 시점에 두 번 실행한 결과의 일치율로 구한다. 따라서 Claude와의 일치율이 높다는 사실만으로 Qwen의 재현성을 통과한 것으로 보지 않는다. 반대로 Qwen 반복 실행의 불일치가 있으면 Claude 기준선과의 차이와 별도로 기록한다.

기준선 비교에서 표본 식별자가 빠지거나 입력·출력의 대응이 깨지면 분모에서 임의로 제외하지 않는다. 표본 대응이 확인될 때까지 해당 측정은 `계산 불가` 또는 미측정으로 남기고 사람 검토 대상으로 보낸다.

## 2. 다섯 항목의 측정 방법과 임계값

다섯 항목의 임계값은 [`docs/legacy/planning/project-overview.md` 9.3절](legacy/planning/project-overview.md)의 사전 확정 기준과 [`docs/standards.md`](standards.md)의 새 모델·프롬프트·정책 버전 활성화 조건을 그대로 따른다. 아래의 분모는 해당 필드가 있고 결정적 검증을 통과한 항목으로 한정하되, 분모에서 제외한 수와 사유도 함께 기록한다.

| 항목 | 측정 방법 | 사전 확정 임계값 또는 해석 |
|---|---|---|
| 재현성 | 같은 고정 표본을 두 번 판정해 다섯 관점 각각의 판단 일치율과 최종 `grade` 일치율을 별도로 계산한다. `일치율 = 일치한 판정 수 ÷ 비교 가능한 판정 수 × 100`이다. | 최종 등급 일치율 80% 이상이며, 불일치가 어느 한 관점에 절반을 넘게 몰리지 않는다. 관점별 수치는 원인 진단을 위해 따로 남긴다. |
| 변별력 | `변별력 = grade가 "우선 검토"인 유효 판정 수 ÷ 유효 판정 대상 수 × 100`으로 계산한다. | 유효 판정 대상이 10건 이상인 경우 10% 이상 25% 이하가 정상 구간이다. 10건 미만은 6절의 소표본 규칙을 적용한다. |
| 근거 타당성 | 담당자가 원문 위치와 모델 근거를 대조해 `동의` 또는 `근거 부족`으로 리뷰한다. `동의율 = 동의 건수 ÷ 유효 리뷰 건수 × 100`, `근거 부족률 = 근거 부족 건수 ÷ 유효 리뷰 건수 × 100`이다. | `동의` 70% 이상이고 `근거 부족` 10% 이하이다. 담당자 리뷰가 최소 운영 리뷰 수에 도달하지 않으면 측정값으로 인정하지 않는다. |
| 정보 충분성 | `정보 불충분 비율 = 첨부 문서 내용이 있어야 해소되는 확인 항목 수 ÷ 전체 확인 항목 수 × 100`으로 계산한다. 전체 확인 항목 수와 필수 확인 항목 수를 함께 기록한다. | 첨부 문서가 필요한 확인 항목의 비율을 정량화한다. 사전 확정된 합격 수치는 없으며, `계산 불가`를 0%로 표시하지 않는다. |
| 관점 분할의 타당성 | 한 공고의 다섯 관점 중 둘 이상이 서로 다른 `assessment`를 낸 판정 수를 센다. `분할율 = 관점 간 판단이 갈린 유효 판정 수 ÷ 유효 판정 수 × 100`이다. | 표본의 40% 이상에서 관점 간 판정이 갈린다. 항상 같은 판정만 내는 관점은 통합하거나 질문을 재정의할 검토 대상으로 남긴다. |

재현성의 80%는 다섯 관점별 수치를 하나의 평균으로 뭉개는 값이 아니다. 최종 등급 일치율을 주 게이트 값으로 두고, 다섯 관점별 일치율과 불일치 집중 여부를 함께 확인한다. 근거 타당성의 두 비율은 모두 충족해야 하며, 정보 충분성은 측정 결과를 다음 단계의 첨부 분석 우선순위로 사용한다.

## 3. 재현성의 단계별 측정

재현성 측정은 같은 고정 입력 표본 40건에 같은 Qwen 모델·프롬프트·정책 버전을 적용한 두 실행을 비교하는 방식으로 한다. 실행 시점만 달리하고 입력 원문, 회사 프로필, 정책·프롬프트 버전은 바꾸지 않는다. 기준선 Claude 40건과의 비교는 이 반복 측정과 별도의 기준선 정합성 자료로 남긴다.

| 단계 | 계산 | 기록 목적 |
|---|---|---|
| 기술 적합성 | 두 실행의 해당 `assessment`가 같은 건수 ÷ 비교 가능한 건수 × 100 | 기술 관점이 흔들리는지 확인 |
| 실적 정합성 | 두 실행의 해당 `assessment`가 같은 건수 ÷ 비교 가능한 건수 × 100 | 실적 유사성 해석이 흔들리는지 확인 |
| 공공 SI 적합성 | 두 실행의 해당 `assessment`가 같은 건수 ÷ 비교 가능한 건수 × 100 | 과업 유형 해석이 흔들리는지 확인 |
| 사업성·자격 제약 | 두 실행의 해당 `assessment`가 같은 건수 ÷ 비교 가능한 건수 × 100 | 자격 확인과 등급 판단의 경계를 확인 |
| 전략 부합 | 두 실행의 해당 `assessment`가 같은 건수 ÷ 비교 가능한 건수 × 100 | 전략 적합성 해석이 흔들리는지 확인 |
| 최종 등급 | 두 실행의 `grade`가 같은 건수 ÷ 비교 가능한 건수 × 100 | 종합 라벨이 재현되는지 확인 |

관점이 모두 일치해도 종합 판정이 다른 라벨을 붙일 수 있으므로, 최종 등급을 관점 일치율의 평균으로 대신하지 않는다. 최종 등급 일치율이 80% 미만이면 재현성 미달이다. 불일치가 한 관점에 절반을 넘게 몰리면 최종 등급이 기준을 넘더라도 해당 관점의 질문·입력·정책을 별도로 검토한다.

반론 검토는 별도 호출의 각 지적에 대해 종합 판정이 `수용`, `기각`, `추가 확인` 가운데 어떤 방식으로 반영했는지를 확인한다. `반론 반영률 = 종합 판정에서 처리 상태가 확인된 반론 수 ÷ 반론 검토 대상 수 × 100`으로 진단값을 남기고, 반론의 지적이 최종 `summary`, `verification_items`, `next_action` 중 어디에 연결되었는지도 기록한다. 이 값에 대해 기존 문서가 정한 별도 임계값은 없으므로 새 합격 수치를 만들지 않으며, 최종 등급 불일치의 원인 분석에 사용한다. 반론이 누락되었거나 연결을 확인할 수 없으면 `계산 불가`로 남긴다.

## 4. 사실 불일치와 판정 라벨 적용 차이

재현성의 원시 일치율은 실제 출력이 같은지 그대로 계산한다. 다만 불일치의 원인을 사실관계와 라벨 적용으로 나누어 기록한다. 원인을 나누지 않으면 프롬프트·원문 구조화·검증기를 고칠 상황과 등급 정의·정책을 고칠 상황을 구분할 수 없다.

| 구분 | 판정 기준 | 후속 검토 방향 |
|---|---|---|
| 사실 불일치 | 공고 사실, 수치, 요구사항, 회사 정보 또는 원문 위치가 서로 다르거나 한쪽에만 존재한다. | 입력 구조화, 원문 위치 연결, 요구사항·산술 결정 검증, 프롬프트를 점검한다. |
| 라벨 적용 불일치 | 사실과 근거는 대체로 같지만 `grade` 정의를 적용하는 규칙이 다르다. | 등급 정의와 정책 버전을 검토한다. 사실을 바꾸거나 모델 출력을 자동 보정하지 않는다. |
| 원인 확인 불가 | 근거 위치가 없거나 두 원인이 함께 있어 한쪽으로 분류할 수 없다. | `unknown`으로 남기고 담당자 검토로 보낸다. 재현성 통과로 세지 않는다. |

파일럿의 소방예방정보시스템 사례는 [`comparison-qwen3.8-27b.md`](deep-review-pilot/cases/2025-fire-prevention-system/comparison-qwen3.8-27b.md)에 기록되어 있다. 기존 검토의 `Conditional Go`와 Qwen의 `Hold`는 핵심 사실이 대체로 같고 등급 정의의 적용이 달라진 사례로 분류한다. 반면 요구사항 고유 ID가 55개인데 Qwen이 54개로 센 것은 사실·계수 불일치로 분류한다. 두 사례를 모두 단순 재현성 실패로만 세지 않고 원인 분포를 별도로 남긴다.

분류 절차는 다음과 같다.

1. 두 결과의 공고 사실, 수치, 요구사항 ID, 근거 위치를 먼저 대조한다.
2. 사실이 다르면 사실 불일치로 기록하고, 사실은 같은데 등급만 다르면 라벨 적용 불일치로 기록한다.
3. 둘 다 있거나 근거가 부족하면 어느 한 원인으로 강제 분류하지 않고 `unknown`으로 남긴다.
4. 원시 일치율은 낮추지 않고 그대로 보존하되, 원인별 건수와 비율을 함께 기록한다.

## 5. 두 축 혼입 지표

두 축 혼입은 재현성·변별력 등 다섯 게이트 항목과 별도로 센다. [`docs/agent-runtime.md` 12절](agent-runtime.md)의 결정적 검출 조건을 그대로 사용한다.

```text
사업성·자격 제약 관점의 assessment == "확인 불가"
그리고 종합 grade ∈ {"관찰 대상", "제외"}
```

해당 판정의 비율은 다음과 같이 계산한다.

```text
두 축 혼입 비율 = 위 조건에 해당하는 유효 판정 수
                 ÷ 자격 관점 assessment와 grade가 모두 있는 유효 판정 수 × 100
```

조건에 해당한 판정은 `확인 요망` 표시를 붙여 사람 검토 목록에서 확인할 수 있게 한다. 판정은 결과에 그대로 남기며, 혼입 표시를 이유로 등급을 자동 변경하거나 병합 입력에서 제거하지 않는다. 결과에 남아 있으므로 회차별 분자·분모와 비율을 계산할 수 있다.

이 지표는 `확인 불가`를 이유로 등급을 낮춘 가능성을 감시하는 별도 지표다. `관찰 대상` 또는 `제외`가 항상 잘못된다는 뜻은 아니며, 사업 영역이 명백히 다른 경우처럼 정상 판정일 수도 있다. 기존 문서에 이 지표의 별도 수치 임계값은 없으므로 새 임계값을 만들지 않는다. 표시된 건별 원문·근거 검토 결과와 추이를 게이트 기록에 남긴다.

## 6. 회차별 변별력 자동 계산

변별력은 품질 게이트를 측정하는 시점에만 계산하지 않고 상시 운영의 모든 회차가 검증·적재를 끝낼 때 자동 계산한다. 세부 임계 이탈 표시와 소표본 처리 방식은 [`docs/scheduling.md` 10절](scheduling.md)을 따른다.

회차의 대상은 해당 회차 후보 전량이다. 현재 회차에서 새로 만든 판정과 현재 계약 검증을 통과한 승계 판정을 모두 포함한다. 유효 판정 대상은 `grade`가 있고 결정적 검증을 통과한 판정으로 한정하며, 실패 공고를 분모에서 조용히 제거하지 않는다.

| 기록값 | 내용 |
|---|---|
| 전체 후보 수 | 회차의 규칙 필터 통과 대상 전량 |
| 유효 판정 대상 수 | 등급이 있고 결정적 검증을 통과한 신규·재판정·승계 판정 수 |
| `우선 검토` 수 | 유효 판정 중 `grade == "우선 검토"`인 수 |
| 실패 수 | 판정 실패·검증 실패 등 유효 판정에 들어가지 못한 수 |
| 변별력 | `우선 검토 수 ÷ 유효 판정 대상 수 × 100` |
| 계산 시각 | `Asia/Seoul` 기준 시간대가 포함된 값 |

유효 판정 대상 수가 0이거나 10건 미만이면 변별력을 `계산 불가(소표본)`으로 기록하고 10~25% 임계 이탈 경보를 만들지 않는다. 유효 판정 대상이 10건 이상이면 10% 이상 25% 이하를 정상 구간으로 보며, 구간 밖이면 값·분자·분모·전체 후보 수·실패 수·계산 시각을 회차 경고로 남기고 관리 화면에 알린다. `계산 불가(소표본)`을 0%로 치환하지 않는다.

변별력 경고는 관찰용이다. 경고만으로 회차를 실패로 바꾸거나 등급·참여 준비 상태를 자동 수정하지 않는다. 회차별 값은 시간순 추이로 남겨 정책·프롬프트 변경 전후의 변화를 비교한다. 메일·메신저 알림은 만들지 않고 관리 화면에서 확인한다.

## 7. 지난 회차의 결과와 이번 측정에서 달라질 점

지난 회차의 실제 결과는 [`docs/validation-runs/20260817-20260823.md`](validation-runs/20260817-20260823.md)에 있다.

| 항목 | 지난 회차 결과 | 이번 측정에서 달라질 점 |
|---|---|---|
| 재현성 | 미측정 | 같은 고정 입력에 Qwen을 두 번 실행하고 다섯 관점·최종 등급·불일치 집중을 따로 기록한다. |
| 변별력 | 30.0% (9/30), 임계 구간 10~25% 미달 | 고정 비교 표본과 상시 회차를 구분해 계산한다. 상시 회차는 6절의 유효 판정 분모와 소표본 규칙을 적용하고, 후보·유효·실패 수를 함께 남긴다. |
| 근거 타당성 | 미측정 | 원문 위치가 연결된 근거를 담당자가 리뷰하고, 최소 운영 리뷰 수를 충족한 경우에만 `동의`·`근거 부족` 비율을 측정한다. |
| 정보 충분성 | 확인 항목 48건 중 필수 27건, 첨부 문서가 있어야 해소되는 항목 12건 | 전체 확인 항목과 첨부 의존 항목의 분모·분자를 고정해 기록한다. |
| 관점 분할 | 65.0% (26/40), 통과 | 다섯 관점별 판단을 고정하고, 동일 판정만 반복하는 관점이 생기는지 회차별 추이로 본다. |

지난 회차의 변별력 30%는 공고명·메타데이터만으로 과업의 실제 범위를 좁힐 수 없어 판단이 관대해진 영향으로 분석되었다. 또한 분석 표본 30건 중 동일한 평생교육관리시스템 사업의 중복 공고 2건이 있어 고유 사업 기준은 8/29=27.6%였다. 중복을 제거해도 임계 구간을 넘었으므로, 중복 수치를 임의로 분모에서 빼서 통과시키지 않는다.

지난 회차는 첨부 문서 전문을 아직 분석하지 않았다. 따라서 같은 입력 표본에 Qwen을 적용하는 기준선 비교에서는 입력 범위를 바꾸지 않고 모델 차이를 측정하며, 첨부 문서를 포함한 운영 측정에서는 입력 범위가 달라졌다는 사실을 별도로 기록한다. 이번 측정은 모델 간 비교, Qwen 반복 재현성, 원문 근거 리뷰, 첨부 의존 확인 항목, 중복 여부를 서로 섞지 않아야 한다.

## 8. 감사 표본의 역할과 회차별 추출

감사 표본은 판정 대상을 줄이거나 정하는 수단이 아니다. 정기 실행에서는 규칙 필터를 통과한 후보를 전량 판정하고, 감사 표본은 1차 필터가 놓친 공고의 비율과 누락이 집중되는 층을 측정하는 데만 사용한다. 표본의 `sample_role`은 `audit`이고, `sample_stratum`은 [`skills/references/workflow-contract.md`](../skills/references/workflow-contract.md)의 기존 구분을 따른다.

상시 운영의 회차별 감사 표본은 운영 표본 수 10건으로 정한다. 이 수는 품질 관찰을 위한 운영 기준이며 통계적 대표성을 보장하는 임계값이 아니다. 다음 세 층에서 추출한다.

| 층(`sample_stratum`) | 회차별 운영 수 | 추출 대상 |
|---|---:|---|
| `분류 근접` | 4건 | 조달 분류가 디지털 사업군에 가깝지만 1차 후보에 들지 않은 공고 |
| `실적 유사 근접` | 3건 | 수행실적 유사도가 후보화 임계값 바로 아래인 공고 |
| `무작위` | 3건 | 위 두 층에 해당하지 않는 감사 풀에서 무작위로 뽑은 공고 |

해당 층의 모집단이 배정 수보다 적으면 있는 건만 뽑고 부족한 수를 다른 층에서 보충한다. 실제 추출 수와 층별 부족 사유를 기록하며, 없는 공고를 만들어 채우지 않는다. 층별 1차 필터 누락률은 다음과 같이 계산한다.

```text
층별 누락률 = 해당 층에서 후보로 분류되어야 한다고 확인된 건수
             ÷ 해당 층 감사 표본 수 × 100
```

표적 추출 표본의 층별 누락률을 감사 풀 전체 누락률로 환산하지 않는다. 층별 모집단과 추출 방식이 확인되고 필요한 가중치를 산출할 수 있을 때만 별도 추정으로 표시하며, 그렇지 않으면 층별 측정값으로 남긴다. 감사 표본은 검토 대기열에 올리지 않는다. 감사 결과 누락으로 확인된 공고도 해당 회차의 판정 대기열에 소급 추가하지 않으며, 1차 필터 규칙 검토를 위한 감사 결과로만 기록한다.

## 9. 게이트 결과의 기록과 활성화 연결

품질 게이트는 고정 표본·모델·프롬프트·정책 버전별로 별도의 불변 결과를 만든다. 원래 회차 판정이나 담당자 리뷰를 덮어쓰지 않는다.

| 기록 위치 | 기록 내용 |
|---|---|
| 품질 게이트 결과 파일 | 게이트 식별자, 대상 표본·회차, 기준선 경로, 모델·모델 버전·프롬프트 버전·정책 버전, 다섯 항목의 분자·분모·비율·판정, 두 축 혼입 지표, 라벨 적용 차이와 사실 불일치 분류, 담당자 리뷰 수와 시각 |
| 회차 품질 기록 | 회차별 변별력의 전체 후보·유효·우선 검토·실패 수, 계산 시각, 소표본 또는 임계 이탈 경고 |
| 관리 화면·관리 이력 | 게이트 통과·미달·측정 불가 사유, 스위치 변경 요청·거부·활성화 시각, 당시 모델·프롬프트·정책 버전 |

게이트 결과 파일은 측정이 끝난 뒤 수정하지 않고 새 측정마다 새 식별자를 만든다. 게이트 결과가 참조하는 기준선·입력 표본·버전이 달라지면 새 게이트 측정이다.

상시 운영 스위치와 정책 버전 활성화의 연결은 다음과 같다.

1. 다섯 항목 가운데 필요한 값이 미측정 또는 `계산 불가`이거나, 재현성·변별력·근거 타당성·관점 분할의 임계값을 충족하지 못하면 게이트는 미달 또는 보류다. 정보 충분성은 정량화 결과가 있어야 하며, 사전 확정된 별도 합격 수치로 바꾸지 않는다.
2. 게이트를 통과하지 못한 모델·프롬프트·정책 버전으로 `BIDOPS_SCHEDULER_ENABLED=true`를 설정할 수 없다. 요청을 거부한 사실과 사유를 관리 이력에 남긴다.
3. 게이트 통과는 새 정책 버전을 자동 활성화하지 않는다. 새 정책은 불변 버전으로 저장하고 `활성화 후보`로 표시한 뒤, 담당자가 명시적으로 활성화한다. 활성화 시 게이트 결과와 모델·프롬프트·정책 버전을 함께 기록한다.
4. 새 모델·프롬프트·정책 버전은 이전 활성 버전을 소급 변경하지 않는다. 자체 게이트를 통과하지 못하면 이전 활성 버전을 유지한다.
5. 게이트 통과 후에도 상시 운영 스위치는 담당자가 별도로 켠다. 스위치가 꺼져 있으면 예약은 `건너뜀`으로 남고, 게이트가 등급이나 참여 준비 상태를 자동으로 바꾸는 근거가 되지 않는다.

## 10. 자동 측정이 불가능한 항목과 리뷰 인정 기준

결정적 검증기는 모델 근거가 원문 위치를 가리키는지와 필수 필드가 있는지는 확인할 수 있지만, 담당자가 그 근거를 읽고 판정에 동의하는지는 자동으로 판단할 수 없다. 따라서 근거 타당성은 담당자 리뷰가 필요한 항목이다. 모델이 `confirmed`로 표시한 사실을 검증기가 그대로 타당한 근거로 인정하지 않는다.

고정 게이트 측정에서 현재 모델·프롬프트·정책 버전에 대한 유효 담당자 리뷰가 10건 이상 모여야 근거 타당성 측정치로 인정한다. 10건 미만이면 `미측정` 또는 `계산 불가(리뷰 부족)`으로 기록하고 통과로 취급하지 않는다. 리뷰는 공고 식별자, 판정 버전, 근거의 원문 위치, 담당자 판단을 연결해야 하며, 확인되지 않은 리뷰 결과를 추정해 채우지 않는다.

최소 10건은 운영상 측정 가능성을 판단하는 기준일 뿐 통계적 품질 보장이나 모집단의 오차 한계를 의미하지 않는다. 리뷰 수가 충분하더라도 `동의` 70% 이상과 `근거 부족` 10% 이하를 모두 만족해야 한다. 담당자가 판단을 보류했거나 원문 위치를 확인할 수 없는 리뷰는 유효 리뷰로 임의 변환하지 않고 별도 상태로 남긴다.

자동 계산되는 변별력·관점 분할·두 축 혼입 비율도 입력이 없거나 결정적 검증을 통과한 분모가 없으면 `계산 불가`다. 어떤 자동 지표도 누락된 사실·근거·등급을 생성하거나 자동 수정하지 않는다. 품질 게이트의 미달·보류 결과는 담당자 검토와 새 측정의 입력으로 남기며, 시스템이 최종 참여 결정을 대신하지 않는다.
