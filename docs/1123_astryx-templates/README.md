# Astryx 컴포넌트·템플릿 적용 시안 (2026-11-23)

운영 웹 전 화면을 검토해 Astryx 컴포넌트·템플릿을 적용한 시안 네 벌을 만들었고, 2026-11-23 사용자가 전체 배치를 **시안 1(표 작업대)** 로 정했다. 지금 시안은 시안 1 위에서 보기 편하게 만드는 방안 세 가지를 비교한다. **제안 단계이며 제품 코드(`web/frontend/src`)는 바꾸지 않았다.** 구현·배포는 사람이 정한다. 2026-11-23~24 제품 구현의 수정안과 단계별 검증 기록은 [plan.md](plan.md), 결정은 [ADR-0077](../tracking/decisions/0077-table-workbench-layout.md)에 있다.

- 시안 보기: <https://42-ax.tail0ab8c5.ts.net:8199/> (tailnet 전용, 호스트에서는 `http://127.0.0.1:5195/`)
- 위쪽 도구줄에서 보기 방안(시안 1 기준·1-A·1-B·1-C)과 화면 13개를 바꾼다. `분석·제안` 화면에 시안 1 보기 방안, 화면별 분석, 공용 템플릿 표, 앞선 네 안 비교가 있다.
- 앞선 비교안은 주소에 `?v=k`(유지안)·`?v=b`(시안 2)·`?v=c`(시안 3)를 붙이면 열린다.
- 값은 운영 화면에서 본 공개 공고 정보를 본뜬 예시이고 담당자 이름은 가명이다. API를 부르지 않으며 저장되지 않는다.
- 캡처: [`shots/`](shots/) — 정해진 시안 1 기준 `1-base-<화면>.png`(1440×900, 13장), 제품 구현 캡처 [`shots/product-20261124/`](shots/product-20261124/)(mock 데이터)·[`shots/product-prod-data-20261124/`](shots/product-prod-data-20261124/)(운영 API 읽기 전용). 비교용이던 보기 방안 1-A·1-B·1-C와 앞선 네 안의 캡처는 용량 때문에 저장소에 넣지 않았고 시안 앱에서 다시 찍을 수 있다.

## 시안 1 위의 보기 방안

시안 1 화면(1440×900, 13개 화면)에서 잰 것:

- 글자 요소 1,137개가 모두 바탕 대비 4.5:1 이상이다(투명도로 흐려지는 비활성 단추는 이 측정에 잡히지 않는다). 남은 과제는 색이 아니라 크기·잘림·찾기다.
- 글자의 26%가 12px이다. 표는 사업명을 한 줄로 자르고 사업명 열은 1440px에서 249px(한글 약 17자), 1280px에서 153px(약 10자)다.
- 마감·상태 열이 표의 오른쪽 끝에 있고 행 구분은 옅은 선뿐이다. 미리보기의 마감·금액은 다른 사실과 같은 크기로 섞여 있다.

| 방안 | 바뀌는 것 | 사전규격 한 화면 행 수 (1280 / 1440 / 1920px) | 대가 |
| --- | --- | --- | --- |
| 시안 1 기준 | 없음 | 16 / 19 / 25 | — |
| 1-A 크게 보기 | 글자 한 단 올림(최소 13px, 본문 15px), 행 넓힘, 사업명 두 줄 + 발주기관 아래 줄 | 6 / 8 / 12 | 보이는 행이 절반 아래로 줄어든다 |
| 1-B 훑기 길잡이 | 줄무늬 행, 고정 열 머리, 마감·상태 열을 사업명 옆으로, 급한 행 왼쪽 띠, 남은 날 굵게, 미리보기·레코드의 핵심 수치 띠 | 16 / 19 / 25 | 사업명 잘림과 12px 글자는 남는다 |
| 1-C 내 화면 맞춤 | 위치 줄의 보기 설정: 글자 크기, 행 밀도, 표시할 열, 미리보기 접기·너비 조절 | 촘촘일 때 16 / 19 / 25 | 설정을 기억하는 기능이 새로 필요하다 |

세 방안은 함께 쓸 수 있다. 제안은 1-B의 길잡이를 기본 화면으로 하고 1-C의 글자 크기·행 밀도 설정을 얹는 조합이다.

**밝은 글자(`#E8E4E2`) 수정.** 시안의 루트가 OS 다크 모드를 따라가 본문 글자색이 다크 테마 값으로 풀렸고, 그 색을 물려받는 목록 머리·요약 값·브랜드 이름·선택 건수가 밝은 바탕 위 밝은 글자로 나왔다. 루트를 라이트로 고정하고 해당 글자가 본문 먹색(`#1B1B1A`)을 직접 읽게 고쳤다. 다크 모드에서 네 방안 × 13화면을 훑어 밝은 바탕 위 밝은 글자가 0건임을 확인했다. 운영 웹은 본문 색이 고정이라 같은 문제가 없다(6개 화면을 GET 전용으로 확인).

## 검토 기준

- 대상은 2026-11-23 19시 기준 운영 웹(`127.0.0.1:18788`, 이미지 `bidops:list-review-sheets-20261123`)이다. 29개 주소를 1440×900으로 열었고 브라우저에서 GET 이외의 요청을 차단했다(차단된 요청 0건).
- 무드보드는 그대로다. 색은 `bidops` 테마 토큰만 읽고, 글꼴·셸(바탕 위 흰 패널, 사이드바 216px, 위치 줄 44px)도 그대로 둔다.
- 화면의 목적과 사람 결정 경계는 바꾸지 않는다. 추적 선택과 최종 Go/No-Go는 사람이 정하고, 값 없음·미확인·계산 불가·0을 구분하며, 참조 실행·표식 없음에는 성공·실패 색을 쓰지 않는다.
- 데모 경로(`/companies/*`)는 운영에서 꺼져 있어 대상에서 뺐다.

## 운영 화면에서 확인한 것

화면은 다섯 유형으로 묶인다. 같은 유형 안에서 같은 기능이 서로 다르게 그려지고 있었다.

| 유형 | 화면 | 갈라진 곳 |
| --- | --- | --- |
| 목록 \| 미리보기 | 발주계획·사전규격·사업기회·최종 Go/No-Go | 목록 머리 글자 13/16px, 행 2줄/3줄, 쪽 이동 3종, 결정 띠 배치 4종, 미리보기 사실 표시 3종 |
| 관리 목록 \| 상세 | 판정 기준·실행 상태 | 위 네 화면과 달리 안쪽 여백 배치, 2단 탭, 16px 상태 표식 |
| 읽기 상세 | 사전규격 상세·사업기회 레코드·입찰공고 상세 | 머리·사실·결정 위치가 세 가지. 입찰공고 상세는 옛 양식(본문 제목, 테두리 카드, 청록 테두리 표식) |
| 최종 결정 | 입찰 참여 결정 | 격자선 표, 화면 전용 담당자 입력 |
| 요약 | 오늘 할 일 | 구역마다 카드·채움·선 혼용, 숫자만 초록 |

공통으로는 상태 표식(주황·보라·회색 채움, 테두리형), 마감 표기 4종, 단계 진행을 직접 그린 원 4종, 빈 상태의 검정 주 버튼이 섞여 있다. 화면별 내용은 시안의 `분석·제안` 화면에 있다.

## 공용 템플릿 먼저

화면보다 먼저 공용 부품(T1~T13)과 화면 틀(P0~P5)을 만들고, 13개 화면은 틀에 내용만 넘긴다. 네 안의 차이는 틀 안에만 있고 화면 파일은 안을 모른다.

- 부품 `web/frontend/design/astryx-templates/kit.tsx`: 상태 표식(Token 채움+글자, 운영 상태 칩과 같은 색), 분류 표식(Token), 마감 글자, 사실 목록(MetadataList), 사업 흐름(Stepper), 구역, 채움 블록, 빈 상태(EmptyState), 주장 목록, 결정 띠, 단축키 안내(Kbd)
- 틀 `templates.tsx`·`templates2.tsx`: 셸, 작업 화면(보기 줄·목록·선택 도구·쪽 이동·미리보기), 읽기 상세, 최종 결정, 요약
- 화면 `pages.tsx`: 13개 화면의 내용

발주계획·사전규격·사업기회·최종 Go/No-Go·브리핑·회사 근거·판정 기준·실행 상태 8개 화면이 작업 화면 틀 하나를 쓴다.

| 안 | 요약 | 바뀌는 것 | 구현 부담 |
| --- | --- | --- | --- |
| 유지안 | 2026-11-21 승인 배치·격자 그대로, 부품만 교체 | 상태 표식, 사실 목록, 쪽 이동, 선택 도구, 단계 진행, 결정 띠 순서, 빈 상태 버튼 | 가장 작음 |

유지안에서도 결정 띠 안의 순서는 `[현재 상태] … [보조 행동][주 행동 1개]`로 맞췄다. 운영의 네 목록이 서로 달라 한 가지로 정할 수밖에 없고, 다섯 곳 중 세 곳(사업기회·Go/No-Go·사전규격 상세)이 이미 이 순서다. 운영에 없는 구역(사업기회 레코드의 하단 결정 띠, 사전규격 상세의 사업 흐름)은 유지안에 넣지 않았다.

## 적용하면서 확인한 Astryx 제약

- `Stepper`는 현재 단계 앞을 모두 완료로 그린다. 연결을 확인하지 못한 단계가 앞에 있으면 거짓 완료가 되므로, 그때는 진행 위치를 쓰지 않고 단계마다 표시(확정 ✓·미확인 –)를 직접 넣었다(`kit.tsx`의 `Flow`).
- `Table`의 데이터 방식(`data`·`columns`)은 행 요소에 속성을 내릴 수 없다. 조합 방식(`TableRow`)은 행이 HTML 속성을 받으므로, 제품 구현은 조합 방식으로 행이 `rowProps`·`aria-current`를 직접 받게 했다(ADR-0077). 시안 코드는 데이터 방식 그대로다.
- `List`의 선택 행은 브랜드 옅은 채움이다. 운영의 목록|상세 네 화면(2026-11-23)과 같아서 네 안의 선택 행을 모두 이 채움으로 맞췄다. ADR-0076 결정 7의 "선택 행은 fill" 문장과는 다르다.
- 테마 빌드가 `StatusDot`·`Badge`의 의미 변형에 Astryx 기본 파랑·노랑·초록 hex를 그대로 내보낸다. 상태 표식은 `StatusDot` 대신 운영 상태 칩과 같은 토큰 짝을 넣은 `Token`으로 그린다(`kit.tsx`의 `StatusMark`).
- 문서 준비 패널은 `Collapsible`을 쓰지 않는 기존 결정(`display:none`이면 폴링이 막힘)을 그대로 따른다.

## 확인한 범위와 한계

- 보기 방안 넷 × 13화면을 1280×800·1440×900·1920×1080에서 열었고 콘솔 오류, 문서 가로 넘침, 표가 목록 칸을 넘는 경우는 0이었다. 시안 코드의 타입 검사를 통과했다. 1-C의 글자 크기·행 밀도·미리보기 접기는 실제로 눌러 동작을 확인했다(열 선택과 너비 끌기는 눌러 보지 않았다).
- 시안은 정적 예시다. 키보드 행 이동, 선택 복원, 대화상자(일괄 추적·필터·확인), 로딩·오류 상태, 대비 게이트는 다루지 않았다. 제품 코드를 바꾸지 않았으므로 `test:screens`·`test:contrast`는 돌리지 않았다.
- 브리핑·회사 근거는 운영에 데이터가 없어 채워진 모습은 예시다. 회사 근거의 값은 모두 `미확인`으로 두었다.
