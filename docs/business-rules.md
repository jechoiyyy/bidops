# 업무 규칙

## 용어

- `등급`은 회사와 사업의 전략·기술 적합성을 나타내는 `우선 검토`, `검토 권장`, `관찰 대상`, `제외` 중 하나다.
- `참여 준비 상태`는 입찰 자격 확인 정도를 나타내는 `확인 완료`, `부분 확인 필요`, `참여 불가 확인`, `해당 없음` 중 하나다.
- `심층 검토`는 첨부 원문을 근거로 자격·요구사항·평가·이행 위험을 구조화하는 단계다. 시스템의 권고는 담당자 의사결정을 보조하며 최종 참여 결정을 대신하지 않는다.
- `정책 버전`은 후보 선정 조건, 관점·가중치, 모델·프롬프트, 검증 기준의 고정 묶음이다. 실행 중인 회차는 시작 시점의 정책 버전을 끝까지 사용한다.

## 후보 선정과 1차 판정

세 우선 축 `AI/데이터`, `블록체인·DID`, `공공 SI·통합관리`는 동등한 우선순위를 가진다. 현재 세 축 외에 공고를 즉시 제거하는 추가 하드 필터는 없다. 새 제외 기준은 사용자 승인 후 새 정책 버전으로만 추가하며 기존 회차에 소급하지 않는다. 제목·조달 분류·회사 수행실적 유사도는 후보 편입 신호이지 적합성의 확정 근거가 아니다. 예산, 지역, 업종, 실적 요건이 확인되지 않았다는 사실만으로 후보를 자동 제외해서는 안 되며 확인 항목으로 남겨야 한다.

후보에 들지 않은 공고는 부적합 정답이 아니다. 조달 분류 근접, 수행실적 유사도 임계값 근접, 무작위 층에서 감사 표본을 뽑아 1차 필터 누락을 측정한다. 감사 표본에서 `제외`가 아닌 판정이 나오면 누락으로 집계하고 후보 규칙 변경 제안의 근거로 사용하되, 한 사례만으로 기준을 자동 변경하지 않는다.

1차 판정은 `기술 적합성`, `실적 정합성`, `공공 SI 적합성`, `사업성·자격 제약`, `전략 부합` 다섯 관점을 모두 가져야 한다. 각 관점은 관점 고유의 이유와 최소 하나의 근거를 가지며 근거 상태는 `confirmed`, `inferred`, `unknown` 중 하나다. 회사 프로필에서 `unknown`인 사실을 모델이 추론해 `confirmed`로 올려서는 안 된다.

등급과 참여 준비 상태는 독립적으로 계산한다. 전략 적합성이 높고 자격이 미확인이면 등급은 `우선 검토`일 수 있고 준비 상태는 `부분 확인 필요`여야 한다. 자격이 확인되지 않았다는 이유만으로 등급을 내리거나, 등급이 높다는 이유만으로 준비 상태를 `확인 완료`로 올려서는 안 된다.

허용 조합과 예외는 다음과 같다.

| 조건 | 결과 | 금지되는 결과 |
|---|---|---|
| 등급이 `제외` | 준비 상태는 `해당 없음` 또는 `참여 불가 확인`, 제외 사유 필수 | `확인 완료`, 제외 사유 누락 |
| 등급이 `제외`가 아님 | 제외 사유는 `null` | 제외 사유 문자열 유지 |
| 준비 상태가 `부분 확인 필요` | 미확인 확인 항목이 최소 1개 | 확인 항목 없는 부분 확인 |
| 준비 상태가 `확인 완료` | 차단성 미확인 항목이 0개 | 차단 항목을 남긴 확인 완료 |
| 준비 상태가 `참여 불가 확인` | 확인된 차단 항목이 최소 1개 | 막는 근거 없는 참여 불가 |

수행실적 유사 신호가 있으면 판정은 그 신호를 검토한 흔적을 남겨야 한다. 연결된 실적마다 대응 이유와 유사도로 설명하지 못하는 차이를 함께 기록하며, 법적 실적 인정 여부가 확인되지 않았으면 `unknown`을 유지한다.

## 회차와 정책 변경

회차는 불변 스냅샷이다. 같은 기간을 새 규칙으로 다시 분류하면 새 실행 ID와 정책 버전을 가진 회차를 만들고 이전 회차를 수정하지 않는다. 판정이 없는 실행은 판정이 완성된 기존 회차를 대체하지 않으며, 새 회차가 필요한 판정을 갖춘 뒤에만 최신 유효 회차가 된다.

사용자가 관리 화면에서 선정 기준·가중치·프롬프트를 바꾸면 새 정책 버전이 생성된다. 변경은 이후 시작하는 실행에만 적용하고 진행 중이거나 완료된 회차를 다시 계산하지 않는다. 과거 결과를 새 기준으로 비교하려면 새 회차를 명시적으로 실행해야 한다.

## 심층 검토 진입과 문서 정본

등급이 `우선 검토`인 공고는 심층 검토 대상이 된다. 첨부가 확보되면 자동으로 변환·구조화 작업을 시작할 수 있고, 첨부가 없으면 분석 실패로 처리하지 않고 `첨부 확보 대기`로 둔다.

HWP 원본은 그대로 보존하고, HWP 분석에는 HWPX 변환 결과를 정본으로 사용한다. 변환 실패 또는 구조 손실 검증 실패 시 원본 HWP를 직접 LLM에 넣지 않고 `변환 확인 필요`로 보낸다. 이미 HWPX인 문서는 변환 없이 정본이 되며, PDF 등 다른 형식은 형식별 추출 결과와 원본 위치의 대응이 검증되어야 심층 분석 입력이 된다.

문서 집합은 파일명·해시·획득 출처·변환기 버전·변환 시각을 가진다. 같은 파일명이더라도 해시가 다르면 다른 문서 버전이며 기존 분석을 덮어쓰지 않는다.

## 심층 평가 기준

심층 리포트는 다음 항목을 모두 다룬다.

| 평가 영역 | 반드시 확인할 내용 | 판정 원칙 |
|---|---|---|
| 입찰 자격과 참여 구조 | 업종·면허, 기업 규모, 지역, 실적, 공동수급, 하도급, 보안·인력 증빙, 제출 마감 | 충족 근거가 없으면 `충족`으로 쓰지 않고 차단 여부와 확인 주체를 지정한다. |
| 과업 범위와 산출물 | 구축·고도화·운영 범위, 제외 범위, 단계별 산출물, 검수·승인 조건 | 요구사항 ID와 원문 위치를 기준으로 누락·중복·모순을 찾는다. |
| 요구사항 대응성 | 기능·성능·인터페이스·데이터·보안·품질·프로젝트관리·지원 요구 | 각 요구사항을 `대응 가능`, `추가 확인`, `갭`, `해당 없음`으로 분류하고 근거·대응안·담당을 남긴다. |
| 평가 전략 | 기술/가격 배점, 정량·정성 항목, 발표·시연, 감점·실격 조건 | 배점 합계와 필수 제출물을 결정적으로 다시 계산하며 모델 계산값만 믿지 않는다. |
| 수행 가능성 | 기간, 투입 인력, 선행 의존성, 전환·이관, 교육, 안정화, 유지보수 | 명시된 기간과 필요한 작업을 대조해 병목과 의사결정 기한을 제시한다. |
| 기술·통합 위험 | 목표 구조, 기존 시스템 연계, 데이터 이관, 표준·호환성, 비기능 요구 | 회사 역량 근거와 공고 근거를 분리하고 추론은 추론으로 표시한다. |
| 보안·법규 위험 | 개인정보, 접근통제, 망분리, 보안성 검토, 인증, 저작권·라이선스 | 법적 판단을 확정하지 않고 문서상 의무·미확인 사항·전문 검토 필요를 구분한다. |
| 사업성 | 예산, 원가 요인, 지급·검수 조건, 보증·지체상금, 제안 비용, 파트너 필요성 | 회사 목표 마진처럼 입력에 없는 숫자를 만들지 않으며 확인 가능한 금액과 가정을 분리한다. |
| 경쟁·제안 전략 | 발주 배경, 핵심 차별점, 예상 평가 초점, 레퍼런스 대응 | 원문 사실과 전략적 추론을 구분하고 반대 근거를 최소 하나 제시한다. |

위험은 `차단`, `중대`, `보통`, `낮음`으로 표시한다. `차단`은 현재 근거로 참여 또는 제안 유효성을 막는 조건, `중대`는 해결 계획 없이 추진하면 일정·원가·평가에 큰 손실이 예상되는 조건이다. 각 위험은 발생 근거, 영향, 확인/완화 행동, 담당 역할, 완료 기한, 잔여 위험을 가져야 하며 단순한 위험 나열로 끝나서는 안 된다.

권고는 `추진 검토`, `조건부 추진 검토`, `보류`, `검토 종료` 중 하나다. `조건부 추진 검토`는 해소해야 할 조건과 결정 기한이 있어야 하며, `보류`는 정보 부족 또는 선행 조건 미해결을 뜻한다. 이 권고를 최종 입찰 참여 승인이나 자동 제출 신호로 사용해서는 안 된다.

## 심층 리포트 필수 출력

심층 리포트는 다음 결과를 하나의 문서 묶음·분석 시점에 연결해 제공한다. 해당 정보를 계산할 근거가 없으면 절을 빼지 않고 `산정 불가`와 필요한 추가 자료를 쓴다.

- 한 화면 의사결정 카드: 권고, 자격 하드게이트, 평가 대응력, 기회 매력도, 수행 위험도, 분석 신뢰도와 조건부 권고의 전환 조건.
- 문서 묶음과 분석 한계: 공고·정정·RFP·과업지시서·내역·서식의 버전과 해시, 추출 실패, 회사정보 기준일, 사용한 추론.
- 사업 기본정보: 목적·범위·금액·기간·계약·평가 방식과 각 값의 원문 위치.
- 자격 매트릭스: 조건·코드, `충족/미확인/부적합`, 증빙 파일, 발급일·만료일, 입찰 마감일 기준 유효 여부, 확인 담당과 기한.
- 요구사항 매트릭스: ID, 원문 위치, 의무수준, 산출물, 회사 대응 근거, 담당 역할, `대응 가능/추가 확인/갭/해당 없음`, 발주기관 질문.
- 배점 매트릭스: 배점·평가문장, 제안 메시지, 증거, 예상 대응 범위, 상실 가능 점수. 배점 합계는 원문과 결정적으로 대조한다.
- 수행계획 초안: 역할별 인월, 일정·WBS, 외부 의존성, 상주·보안, 데이터 이관, 안정화와 하자 SLA. 입력이 없으면 인월을 모델이 임의 생성하지 않는다.
- 경제성 시나리오: 확인된 VAT·직접비·외주·클라우드·라이선스·출장·보증·하자충당·예비비를 이용한 기준/보수/최악 원가와 투찰 하한. 회사 마진 기준이 없으면 마진을 확정하지 않는다.
- 계약·법무 위험: 지식재산권, 손해배상, 보안위약, 과업변경, 검수·대금, 하도급의 원문 의무와 전문 검토 필요 여부.
- 발주기관 질의와 내부 액션: 질문/행동, 담당 역할, 마감, 완료 조건, 해결되었을 때 권고가 어떻게 달라지는지.

## 근거와 모델 검증

모든 수치, 자격 조건, 요구사항, 배점, 일정, 위험 근거는 문서 파일과 페이지·절·표·요구사항 ID 중 가능한 가장 구체적인 위치를 가져야 한다. 모델이 인용한 위치에서 내용을 찾을 수 없으면 해당 주장은 `미검증`이며 리포트의 확정 사실에 포함하지 않는다.

결정적 검증기는 최소한 요구사항 ID의 유일 개수와 중복, 금액·기간·배점 산술, 필수 분석 영역 누락, 자격 판정 간 모순, 원문에 없는 수치, 인용 위치 존재를 확인한다. 실패하면 결과 전체를 자동 승인하지 않고 실패 항목을 표시한 사람 검토로 보낸다. 자동으로 문장을 고쳐 검증을 우회하거나 OpenAI를 자동 호출해서는 안 된다.

개별 결과의 결정적 검증과 모델·정책 버전의 표본 품질 검증은 별개다. 동일 표본의 등급 재현성은 80% 이상이고 불일치가 한 관점에 절반 넘게 몰리지 않아야 하며, 담당자 리뷰의 `동의`는 70% 이상, `근거 부족`은 10% 이하여야 한다. 임계값은 실행 전에 정책 버전에 고정한다. 표본이 부족해 계산할 수 없거나 기준에 미달한 모델·프롬프트·정책 버전은 자동 활성화하지 않고 원인과 보완안을 사람에게 제시한다.

## 리뷰와 개선 순환

리뷰 작성자는 저장 전에 이름을 입력한다. 이름 입력은 작성자 식별일 뿐 신원 인증이 아니므로, 이름이 같다는 이유로 권한이나 실제 신원을 보장해서는 안 된다.

피드백은 `1차 판정 품질`, `심층 리포트 품질`, `실제 사업 결과`, `사용자 경험·처리 흐름`으로 구분한다. 등급 수정과 근거 부족은 공고·회차·정책 버전에 연결하고, 실제 결과는 참여 여부·제안 결과·실패 원인처럼 사후 확인 가능한 사실을 기록한다.

피드백은 지표와 변경 제안을 만들 수 있지만 선정 기준, 회사 프로필, 프롬프트, 모델 설정을 자동 변경하지 않는다. 담당자가 변경 제안을 검토하고 승인하면 새 정책 버전으로 이후 회차에만 적용한다.
