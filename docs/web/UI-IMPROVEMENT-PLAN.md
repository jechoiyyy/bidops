# BidOps Admin UI 개선 계획

> 외부 UI/UX 리뷰 피드백(2026-08-25)을 `web/frontend` 코드로 검증하고, 우선순위별 실행 계획으로 정리한 문서.
> 이 문서 작성 시점에 코드는 변경하지 않았다.

## 2. 피드백에 없던 추가 발견

검증 과정에서 리뷰가 다루지 않은 항목 네 가지를 찾았다.

### 2.1 breakpoint 난립이 반응형 문제의 근본 원인

`theme.css`의 미디어 쿼리 전환점이 **560 / 620 / 700 / 720 / 760 / 840 / 900 / 980 / 1080 / 1100 / 1160 / 1260 / 1279px** 13종이다. 컴포넌트별로 필요할 때마다 따로 추가된 결과라, 같은 화면 폭에서 사이드바는 축소되고(720) 대기열은 아직 가로 배치이며(980) 상단바는 이미 상태 문구를 감춘(1279) 어긋난 상태가 만들어진다.

개별 블록을 고치는 것보다 **전환점 집합을 먼저 4~5개로 확정**(예: 640 / 900 / 1180 / 1440)하고 기존 규칙을 그 위에 재배치하는 편이 P0 수정의 재발을 막는다.

### 2.2 `.master-detail-list`는 사용되지 않는 CSS

`theme.css:1102`에 정의되고 `theme.css:1108`의 `@media (max-width: 1279px)`에서 `display: none` 처리되지만, `src/` 전체 `.tsx`에서 이 클래스를 쓰는 곳이 없다. 즉 이 미디어 쿼리는 현재 아무 효과가 없다. 반응형 작업 시 살아 있는 규칙으로 오인하기 쉬우므로 정리 대상으로 표시해 둔다.

### 2.3 `--color-alert`와 `--color-error`는 이름만 둘이고 값이 같다

```css
--color-alert: #9a4a2f;
--color-error: #9a4a2f;
```

토큰 분리는 이미 시도됐지만 값이 동일해 경고와 오류를 화면에서 구분할 수 없다. semantic palette 도입은 새 체계를 얹는 작업이 아니라 **이미 있는 토큰에 서로 다른 값을 부여하는 작업**에 가깝다. 한편 `--color-success` / `--color-info` / `--color-warning` / `--color-focus`는 아예 정의돼 있지 않다.

### 2.4 "읽기 전용"은 모바일에서 잘리는 게 아니라 사라진다

리뷰는 모바일에서 문구가 잘린다고 봤지만, `theme.css:1116`이 1279px 이하에서 `.topbar-status { display: none }`으로 아예 감춘다. 잘림보다 **태블릿·모바일에서 화면 상태를 알 수 없는 것**이 실제 증상이다. 어차피 문구를 페이지별로 교체할 예정이므로 결론은 같지만, 검증 시 확인 대상이 달라진다.

## 3. 이슈 목록

### P0-1. 태블릿·모바일 레이아웃 붕괴

- **증상**: 390px에서 대시보드 "지금 처리할 일" 3개 항목이 가로 열을 유지해 문장이 한 글자씩 세로로 찢어진다. 판정 요약 배너도 동일. 1024px 대기열은 상세 영역이 과도하게 좁아 판정 요약 문장이 한 글자씩 줄바꿈된다.
- **원인**: `.dashboard-action-items`(4748)와 `.judgment-banner`(4556)에 미디어 쿼리가 하나도 없고, 대기열 세로 스택 전환점이 980px로 낮다.
- **수정 방향**:
  - 전환점 집합을 먼저 확정한다(2.1).
  - 대기열 세로 스택 전환을 1180px 전후로 올린다. 뷰포트 폭보다 상세 영역의 실제 콘텐츠 폭이 기준이므로, 가능하면 컨테이너 쿼리로 전환한다.
  - `/queue`와 `/queue/:noticePk`를 모바일에서 목록/상세 분리 화면으로 나눈다. 상세 상단에 "목록으로" 버튼과 현재 위치(`3 / 17`)를 둔다.
  - 리뷰 바는 하단 고정하되 핵심 필드만 노출하고, 나머지는 "등급·준비 상태 수정" 확장 영역으로 분리한다.
  - action strip은 제목 아래 3개 세로 행으로, 판정 배너는 등급 → 다음 행동 → 확인 항목 순 세로 배치로 바꾼다.
  - 모바일 사이드바를 10개 아이콘 레일 대신 햄버거 drawer로 바꾼다.
- **완료 기준**: 390 / 768 / 1024 / 1440px에서 한 글자 세로 줄바꿈이 없고, 페이지 전체에 가로 스크롤이 없다.

### P0-2. 미저장 리뷰 유실

- **증상**: 리뷰 입력 후 목록 클릭이나 J/K 이동 시 입력값이 안내 없이 사라진다.
- **원인**: `QueuePage.tsx:147`의 draft 재생성 effect가 dirty 여부를 보지 않는다.
- **수정 방향**: 단계적으로 적용한다.
  1. draft가 서버 값과 다른지 판정하는 dirty 상태를 도입하고, dirty일 때 이동 전 확인을 띄운다.
  2. 그 위에 공고별 초안 로컬 임시저장을 얹는다.
  3. 저장 성공 시 `저장됨 · 다음 공고로 이동했습니다 · 되돌리기` 토스트를 제공한다.
  4. 리뷰 바에 "저장되지 않은 변경사항" 상태를 표시한다.
- **적용 범위**: 목록 클릭, J/K 이동(`:188`), 저장 후 자동 이동(`:219`), 회차 변경, 브라우저 이탈(`beforeunload`).
- **완료 기준**: 위 다섯 경로 어디에서도 미저장 값이 안내 없이 사라지지 않는다.

### P1-1. 상단 바 재구성

- **증상**: 긴 `screening_basis` 전문이 badge를 통해 상단 대부분을 차지하고, 모바일에서는 의미 없는 지점에서 잘린다.
- **수정 방향** (`TopBar.tsx`):
  - 좌: 페이지 제목을 모바일에서도 유지한다.
  - 중: `2026.08.17–08.23 · 완료` 형태의 회차 선택.
  - 우: "판정 기준" 정보 버튼. 클릭 시 팝오버로 전체 기준선·데이터 출처·생성 시각을 보여준다.
  - 긴 문장을 badge label에 직접 넣지 않는다.

### P1-2. 페이지별 편집 범위 명시

전역 "읽기 전용"을 없애고 페이지별 문구로 교체한다.

| 페이지 | 문구 |
|---|---|
| 판정 상세 | 판정 원문 읽기 전용 |
| 회사 프로필 | 원본 문서에서 관리 |
| 검토 대기열 | 리뷰 저장 가능 |
| 수집 실행 | (문구 없음) |

### P1-3. 빈 메뉴 정리

`routes.tsx:31`의 `PlaceholderPage` 3개를 다음과 같이 처리한다.

| 메뉴 | 처리 |
|---|---|
| 마감 추적 | 대기열의 마감 임박순 필터로 연결 |
| 담당자 리뷰 기록 | 구현 전까지 숨기거나 "준비 중" 표시 |
| 산출물 감사 로그 | 수집 실행의 산출물 검증 영역으로 연결 |

메뉴를 유지한다면 빈 제목 대신 제공 예정 기능과 대체 경로를 안내한다.

### P1-4. semantic color token 분리

현재 브랜드·선택·성공·우선순위가 모두 그린이고, 경고와 오류가 같은 값이다(2.3). 색을 늘리는 것이 아니라 **역할을 분리**하는 것이 핵심이다.

| 역할 | 텍스트 | 배경 | 용도 |
|---|---|---|---|
| Brand | `#0F3E17` | `#E1F4DF` | 브랜드, 주요 CTA |
| Success | `#276238` | `#EAF6EB` | 완료, 통과 |
| Info | `#24576A` | `#EEF7FA` | 준비 상태, 출처, inferred |
| Warning | `#7A3E00` | `#FFF4E5` | 마감 임박, 확인 필요 |
| Danger | `#8F2F1D` | `#FFF1ED` | 마감 지남, 실행 실패, 차단 |
| Focus | `#1D4ED8` | — | 키보드 포커스 |
| Text secondary | `#6F6C64` | — | 보조 설명 |
| Decorative slate | `#B6CED5` | — | 장식선 전용 |

함께 처리할 대비 수정:

- `--color-muted-soft`를 4.5:1 이상으로 어둡게 조정한다.
- 사이드바 그룹 라벨 투명도를 45% → 65% 이상으로 올린다.
- 사이드바 보조 문구를 62% → 65% 이상으로 올린다.
- `--color-slate` 단독 사용을 장식선으로 한정한다.

### P1-5. 전역 포커스 표시

모든 링크·버튼·select에 `:focus-visible`을 정의한다. 현재는 4곳뿐이다(검증 11번).

### P2-1. 밀도와 터치 타깃

- 본문 13~14px, 메타데이터 최소 12px. 10px는 짧은 코드·eyebrow에만 사용한다.
- 리뷰 컨트롤 높이가 28~30px다. WCAG 2.2 [Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)의 하한은 24px이지만, 주요 모바일 컨트롤은 40~44px를 목표로 한다.

### P2-2. 로딩·오류·저장 피드백

- 로딩 문구에 `role="status"` / `aria-live`를 추가한다.
- 오류 화면에 재시도 버튼을 추가한다.
- `EmptyState`에 primary / secondary action을 지원한다(`EmptyState.tsx`).
- skeleton은 화면 구조를 유지하는 용도로만 쓴다.
- 저장·업로드·실행 결과는 `aria-live` 토스트로 전달한다.

## 4. 화면별 개선안

**대시보드**

- `collected-notices.json이 없어…` 같은 내부 파일명을 "수집 산출물 미적재"로 바꾼다.
- 값이 없는 KPI에 "수집 실행으로 이동"을 제공한다.
- 차단 항목은 개수뿐 아니라 영향이 큰 3개를 먼저 보여준다.

**검토 대기열**

- 데스크톱 구조는 유지한다.
- 태블릿 이하에서 목록/상세를 분리한다.
- 필터를 한 줄 가로 스크롤 대신 "필터 2개 적용" drawer로 바꾼다.
- 저장 여부와 초안 상태를 표시한다.
- 검토 완료율 외에 남은 우선 검토, 다음 마감을 표시한다.

**판정 이력** (`NoticeDetailPage.tsx`)

- 첫 진입 시 최근 또는 우선순위가 높은 공고를 자동 선택한다. 대기열(`QueuePage.tsx:136`)과 동작을 맞춘다.
- 대기열과 동일한 검색·등급·준비 상태 필터를 제공한다.
- 선택 항목에 scroll-into-view를 적용한다.
- "이전 판정 대비 변경됨" 항목을 목록에서 우선 강조한다.

**수집 실행**

- `theme.css:885` `.runs-scope-row`의 `grid-template-columns: 72px minmax(0, 1fr) auto`가 좁은 폭에서 "사전규격 수집되지 않음"을 세로로 가른다. 작은 폭에서는 label 위 / 값 아래 구조로 바꾼다.
- 새 수집 실행 후 단계·진행률·예상 산출물을 상단에 고정한다.

**첨부 확보**

- 기관별 그룹과 우측 등록 폼 구조는 유지한다.
- "마감 지남 / 미확보 / 기관 미등록" 필터를 추가한다.
- 기관 등록 성공 후 해당 공고의 검색 링크 생성을 직접 피드백한다.

| 단계 | 범위 | 검증 |
|---|---|---|
| 0 | breakpoint 집합 확정, `.master-detail-list` 등 죽은 규칙 정리 | 기존 화면이 모든 폭에서 회귀 없음 |
| 1 | P0-1 반응형 | 390 / 768 / 1024 / 1440에서 한 글자 세로 줄바꿈·가로 스크롤 없음 |
| 2 | P0-2 리뷰 초안 보호와 저장 피드백 | 목록·J/K·저장 후 이동·회차 변경·브라우저 이탈에서 미저장 값이 조용히 사라지지 않음 |
| 3 | P1-1, P1-2, 모바일 내비게이션 | 모든 폭에서 페이지 제목·회차·현재 상태 확인 가능 |
| 4 | P1-4, P1-5 | 작은 텍스트 4.5:1 이상, 모든 주요 컨트롤 키보드 포커스 확인 |
| 5 | P1-3, P2-2 | 활성 메뉴 중 제목만 표시되는 화면 없음 |
| 6 | Playwright 시각 회귀 테스트 | 390 / 768 / 1024 / 1440 스냅샷. 현재 `package.json`에 테스트 스크립트 없음 |

0단계는 원래 리뷰에 없던 단계다. 1~3단계가 모두 `theme.css`의 미디어 쿼리를 건드리므로, 전환점을 먼저 정리하지 않으면 같은 블록을 세 번 수정하게 된다.

효과 대비 비용이 가장 좋은 범위는 **1 + 2 + 3 + 4단계**다. 기존 디자인 기반을 유지하면서 체감 완성도를 가장 크게 올린다.

## 6. 유지할 것

리뷰가 지적한 강점은 개선 과정에서 훼손하지 않는다.

- 대시보드 "지금 처리할 일"이 통계를 실제 작업으로 연결하는 구조
- 검토 대기열의 목록 – 판정 근거 – 리뷰 입력 3단 구성 (데스크톱)
- 값 없음 / 계산 불가 / 0을 구분하는 데이터 신뢰성 표현
- 판정 결과에서 등급과 함께 근거·반론·확인 항목·다음 행동을 함께 제시
- 회차와 필터의 URL 유지 (`Sidebar.tsx`의 `runSearch` 전달 포함)
- J/K 이동, 나라장터 원문 연결, 저장 후 다음 공고 이동
- 브랜드 팔레트 `#0F3E17` / `#FFFEFC` / `#F5F4EF` / `#222222`
