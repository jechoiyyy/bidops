# 목록 상단바 통합과 기본 UI 배율 검증

검증일: 2026-09-09. 사용자 요청에 따라 Luna max 서브에이전트가 페이지별 점검,
공통 배율, 드래그 좌표 보정과 회귀 검증 수정을 나누어 진행했다.

## 변경과 배포 원인

- 현재 소스의 발주계획·사전규격·사업 추적·최종 Go/No-Go 목록은 이미 `TopBar`의
  제목 모드와 `PageHeaderActions`, `WorkspaceFrame`을 사용하고 있었다.
- 배포 전 서버의 페이지별 지연 로딩 JS에는 기존 본문 헤더가 남아 있었다.
  진입 HTML·JS만 대조해서는 이 차이를 확인할 수 없었다.
- 문서 루트에 `--bo-ui-scale: 0.9`와 `zoom`을 적용했다. viewport 기반 치수와
  최소 폭을 보정해 브라우저 100%에서 화면을 채우고 실제 최소 폭 1280px을 유지한다.
- 발주계획 목록 폭 조절은 마우스 이동 거리를 실제 렌더링 배율로 나누어 CSS 논리
  폭으로 변환한다. 키보드 조작과 저장 폭의 단위는 그대로다.
- 논리 글자 크기도 90%로 표시된다. 사용자 요청에 따른 이 계약은 디자인 PRD에 기록했다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| TypeScript 및 Vite production build | 통과 |
| `npm run test:contrast` | 9 통과 |
| `npm run test:screens -- --workers=4` | 502 통과, 5 건너뜀, 실패 0; 5.7분 |
| 컨테이너 내부 프론트엔드 파일 해시 | 검증 빌드의 75개 파일과 전부 일치 |
| 서버 HTTP 응답 및 로컬 `dist` 해시 | 같은 75개 파일과 전부 일치; 지연 로딩 JS·CSS 포함 |
| 실제 서버의 네 목록 × 두 viewport | 8개 조합 모두 통과 |
| 웹 API 및 컨테이너 health | 정상 |

화면 게이트는 별도로 빌드한 산출물을 preview 포트 4293에서 제공한 뒤
`PW_PORT=4293`과 해당 `PW_OUT_DIR`을 지정해 실행했다. 이 환경에서는 서버가 없는
포트에 대한 초기 연결 확인이 지연될 수 있어 preview를 먼저 직접 기동했다.

첫 진단 실행은 474 통과·28 실패·5 건너뜀이었다. 물리 좌표와 논리 치수를 섞던
비율 검사, 기존 100% 치수 기대값, 오래된 회차 화면 맥락 검사와 다중 화면 순회
시간 제한을 정리했다. 옛 경로 검사 실패는 배율 변경 전 빌드에서도 재현됐다.
최종 결정 확인은 변경 전후 빌드에서 반복 검증했으며 제품의 결정 동작은 수정하지 않았다.

실제 서버 검증은 1280×800과 1440×900, 브라우저 배율 100%에서 수행했다.
각 페이지의 기존 본문 헤더가 없고 제목·액션이 상단바에 있는지, 가로 넘침이 없는지,
액션 대화상자가 화면 안에 열리고 Escape로 닫히는지 확인했다. 상단바는 약 68.4px,
공통 workspace 높이는 각각 약 702.8px와 802.8px이었다.
픽셀 기준 이미지는 갱신하지 않았다. 이 기록은 UI 검증이며 모델 품질 측정 근거가 아니다.

  환경변수·mount·network·port 설정을 보존했고 배포 파일 75개의 HTTP 응답 hash가 빌드와 일치했다.
- 실행 로그와 이전 이미지 복귀 설정은
