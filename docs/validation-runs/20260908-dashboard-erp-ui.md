# 승인 ERP 대시보드 구현 검증

검증일·사용자 승인일: 2026-09-08. 사용자의 “해당 시안대로 너가 바로 적용해줘” 요청으로
위임 없이 직접 구현했다. 정본은 저장소 밖 `bidops-dashboard-erp-20260908`의
HTML·원본 TSX/CSS·상태별 캡처이며, 가상 데이터는 제품 코드에 포함하지 않는다.

## 구현과 데이터 경계

- 네 누적 업무 바로가기 → 본문 회차 선택 줄 → 마감 공고·담당자 확인 요청 → 회차 요약·검증
  상태 순서를 재사용했다. 본문 좌우는 67:33, 공고명·발주기관은 15px/600이며 기관은 제목 아래다.
- 회차와 마감 필터는 URL에 남는다. 회차를 자동 선택하지 않고 회차 변경 시 마감 필터만
  초기화한다. 회차 자료가 실패해도 누적 업무 바로가기는 유지한다.
- 발주계획 후보는 기존 relevant/uncertain 전체 건수 합, 나머지 누적 대기 수는 미확인이다.
  일부 페이지를 세거나 사업별 추가 API 호출로 전체 수를 근사하지 않는다.
- 마감은 `RunStatsResponse.generated_at`과 `timezone`을 기준으로 표시한다. 기준 시각이
  없으면 마감 0건으로 확정하지 않는다. 받은 회차의 7일 목록에서 기간·확인 항목을 좁힌다.
- 수집·후보 풀·판정 표본은 회차 통계, 담당자 리뷰는 `RunSummary.counts.reviews`다.
  `funnel.review_queue`를 리뷰 수로 대신하지 않는다. 조회하지 못한 리뷰 수는 미확인이다.
- 검증은 실제 반환 지표명·상태·근거를 표시하고 미달을 먼저 둔다. 시안의 가상 사람 정답 비교
  항목을 제품에 생성하지 않는다. 감사 누락의 분모를 추정하거나 계산 불가를 통과로 바꾸지 않는다.
- 공고 상세·등급별 이력·회사 프로필·검증 지표·실행 탭은 기존 경로로 이동하며 회차를 보존한다.
  대시보드는 API 읽기만 수행한다. 실행·승인·최종 결정 버튼을 새로 만들지 않았다.

최종 관련 검사 명령은 `dashboard-final-tests.log`에 원문을 보관한다. 시안 대조는
1280×800과 1440×900에서 수행했다. 업무 바로가기 y=92, 높이 83.5px, 하단 요약 높이
162px, 기본 세 공고 가시성을 확인했다. 시안의 40px 도구 모음을 제외한 높이는 위쪽 패널의
읽기 영역에 배정한다. 표·요청 영역의 좌표·폭, 숫자·캡션의 글자 두께도 원본과 대조했다.
기존 앱의 로고·사이드바 행·현재 경로 표시는 유지한다. 회차 종류·연도·식별자는 실제 입력으로
표시하며 같은 기간에 생성한 여러 회차를 구분하도록 검색과 회차 ID 설명을 제공한다.

## 남은 기존 실패

전체 화면 게이트가 모두 통과했다는 뜻은 아니다. 이전 기록의 11개 실패 중 대시보드 선택기와
route context 두 항목은 승인된 새 구조에 맞춰 수정해 통과했다. 남은 9개는 이전 실패와 같다.

- `common-interactions.spec.ts` 3개: UC-02 상태 문구, 사이드바 밖 회차 축, 흡수한 옛 경로.
- `route-context.spec.ts` 5개: queue list·queue detail·reviews 맥락, SPA 내부 link, queue detail 상단 경로.
- `screen-semantics.spec.ts` 1개: 흡수한 마감·감사 경로의 쿼리 보존.

합성 API 검사는 실제 운영 품질 측정·수집·모델 실행·정책 활성화의 증거가 아니다.
실제 화면에서는 마감 공고와 판정 표본이 있어도 판정 분포·검증 값이 없을 수 있으며 그 상태를
그대로 보존한다. 미측정·참조 실행을 품질 통과로 표시하지 않는다.
