# 사전규격 첨부 URL 수명 측정 (2026-08-31, D-9)

T-20의 조건부 다운로드는 "나중에 추적 대상이 되면 그때 받는다"가 전제다. 그 사이 첨부
URL이 죽으면 원문을 영영 못 받는다. [첨부 실측](20260830-prespec-attachment-probe.md)의
"측정하지 않은 것"에 수명이 `unknown`으로 남아 있었다.

## 방법

새로 수집하지 않았다. [사전규격 채움 곡선](20260831-prespec-fill-curve.md)이 나이
3·9·17·31·60·150일 코호트의 원문 페이지를 이미 보존해 두었으므로, 그 안의
`specDocFileUrl1~5`를 오늘 호출했다.

- 스크립트: `experiments/lifecycle-linkage-survey/scripts/prespec_attachment_survival.py`
- 나이 6구간 × `random.Random(20260831).sample` 30개 = **180 GET**, 간격 1.0초
- 인증 정보를 보내지 않고 redirect를 따르지 않는다. `www.g2b.go.kr` 외 host는 호출하지 않는다
- 본문 바이트는 저장하지 않고 sha256과 앞 16바이트 magic만 남긴다
- 증거: [`data/experiments/prespec-attachment-survival/20260831/survival.json`](../../data/experiments/prespec-attachment-survival/20260831/survival.json)

**횡단면 설계다.** [종단 관측](20260831-order-plan-longitudinal.md)에서 보였듯 횡단면과
종단은 어긋날 수 있다. 아래 "이 측정이 답하지 못하는 것"을 함께 읽어야 한다.

**180/180이 HTTP 200이다.** 4xx, 5xx, redirect, timeout이 0건이다.

### 200이 실제 파일이라는 것도 확인했다

[첨부 실측](20260830-prespec-attachment-probe.md)에서 "정책상 차단되는 건이 실재한다"고
기록했으므로 상태 코드만으로는 부족하다. 본문 앞머리를 검사했다.

| magic | 형식 | n |
|---|---|---|
| `d0cf11e0` | OLE CFB (hwp, xls) | 102 |
| `504b0304` | ZIP (hwpx, xlsx, zip) | 60 |
| `25504446` | `%PDF` | 18 |

HTML 오류 페이지, 빈 응답, 4KB 미만 응답이 **0건**이다. `Content-Length`와 실제 읽은
바이트가 180/180 일치하고 파일명 UTF-8 percent-decode 실패도 0건이다. 이번 표본에서는
정책 차단이 관측되지 않았다(08-30 표본에서는 30건 중 2건이었다). 표본이 달라서이며
서로 모순되지 않는다.

### 새 발견: 8.3%가 허용 확장자 밖이다

| 확장자 | n | 허용 여부 |
|---|---|---|
| hwp | 99 | 허용 |
| hwpx | 48 | 허용 |
| pdf | 18 | 허용 |
| **zip** | **9** | 거부 |
| **xlsx** | **5** | 거부 |
| **xls** | **1** | 거부 |

`app/services/attachments.py:17`의 `ALLOWED_EXTENSIONS = {"hwp", "hwpx", "pdf"}` 기준으로
**180건 중 15건(8.3%)이 확장자에서 거부된다.** 결함이 아니다 —
`prespec_attachments.py`가 `unsupported_extension`을 terminal code로 분류해 재시도하지
않고 fail-closed한다. 다만 조건부 다운로드를 켜면 **약 8%가 취득 실패로 떨어지는 것이
정상 동작**임을 운영자가 알고 있어야 한다.

`zip` 9건은 내부에 hwp가 들어 있을 가능성이 있으나 열어 보지 않았다. 압축 해제는 현재
취득 경계 밖이고 새 공격면이므로 이 측정에서 확장하지 않았다.

50MiB 초과는 0건이다(최대 15,305,728 B). 180건 총 다운로드는 134.8MB였다.

### 크기가 나이에 따라 커지는 것은 노화가 아니다

중앙 크기가 3일 126KB에서 150일 320KB로 커졌다. 파일이 자라는 것이 아니라 **서로 다른
코호트**다. 채움 곡선과 같은 횡단면 한계이며 이 값으로 추세를 주장하지 않는다.

## 함의

T-20의 조건부 다운로드 전제가 **지지된다.** 5개월 된 사전규격의 첨부가 오늘도 그대로
받아진다. 추적 상태가 나중에 정해지는 설계 때문에 원문을 못 받는 상황은, 적어도 150일
범위에서는 관측되지 않았다.

URL 형태 자체도 이 결론을 뒷받침한다.

```
https://www.g2b.go.kr/pn/pnz/pnza/UntyAtchFile/downloadFile.do
    ?bfSpecRegNo=R26BD00205236&fileType=BFDTL&fileSeq=1
```

서명 token도 만료 파라미터도 없다. presigned link가 아니라 **등록번호와 파일 순번으로
주소가 결정되는 방식**이므로 구조적으로 회전하기 어렵다.

## 이 측정이 답하지 못하는 것

- **URL 회전을 검출할 수 없다.** 표본의 URL은 모두 2026-08-31에 API가 광고한 값이다.
  "우리가 day 0에 저장해 둔 URL이 day N에도 유효한가"가 운영 질문인데, 이 설계는
  "오늘 광고되는 URL이 오늘 유효한가"를 잰다. 위의 URL 형태 관찰이 회전 가능성을 낮추지만
  증명하지는 않는다. **2026-09-13에 2026-08-30 표본 30건을 재호출하는 종단 점이
  이것을 직접 검증한다.**
- **생존자 편향이 있다.** API 응답에서 사라진 사전규격은 애초에 표본에 들어오지 않는다.
  레코드 자체가 삭제되는 비율은 측정하지 않았다.
- 150일을 넘는 수명. 나이 150일이 가장 오래된 코호트다.
- rate limit. 180회를 1초 간격으로 던져 제한을 만나지 않았다는 것 외에는 `unknown`이다.
- `zip` 안에 무엇이 들어 있는지.
