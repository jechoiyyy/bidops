# 사전규격 개요 — 충분한 설명과 PDF 페이지 근거 참조 실행

## 범위와 목표

사용자가 직접 검토한 것처럼 Qwen3.8:27B도 사업 이해에 필요한 내용을 충분히 출력하고, 근거를 청크 식별자가 아닌 PDF 페이지로 표시하도록 요청했다. 이전 개요 실패 6건(ID 137, 614, 171, 610, 159, 143)을 대상으로 한다. 글자수·줄수 제한은 제거하고 자원 한도와 모델 identity·host·revision 검증은 유지한다.

## 페이지 의미 확인과 원문 준비

현재 PDF 추출 경로의 page는 물리적 PDF 페이지다. HWP/HWPX 추출 경로는 HWPX section 순번을 page로 사용하므로 실제 PDF 페이지라고 표시할 수 없다. 이번 6건 모두 기존 텍스트의 page 값으로 PDF 근거를 만들지 않았다.

안전 검사 완료된 불변 원문 6개를 versioned MinIO에서 읽고 원본 버전·SHA-256을 대조했다. 저장소에 고정된 rhwp SVG 렌더와 Chromium 인쇄로 별도 참조 PDF를 만들고, 물리적 PDF 페이지별로 Poppler 텍스트를 추출했다. 변환본은 한컴 렌더링과 동일한 페이지 배치를 보증하지 않는다. 이번 결과의 페이지는 함께 제공하는 변환 PDF 자체의 페이지다.

| ID | PDF 전체 페이지 | 실제 검토한 PDF 페이지 |
| ---: | ---: | --- |
| 137 | 174 | 4–7 |
| 614 | 100 | 3–6 |
| 171 | 86 | 3–8 (3페이지의 목차 앞부분 제외) |
| 610 | 62 | 4–6 |
| 159 | 37 | 3–5 (다음 주절 본문 전까지) |
| 143 | 36 | 4–7 |

각 입력은 document_version_id, source_sha256, pdf_sha256, 선택한 물리적 pdf_page, 원문 페이지 텍스트 SHA-256과 시작 오프셋을 보존한다. 모델에는 선택 페이지 본문과 페이지 번호 등 허용 입력만 보낸다. 파일·객체 경로, 자격증명, 회사 자료는 입력에 포함하지 않는다.

국세청 사업은 이전 구조화 원문의 빈 기호 때문에 예산·기간이 미확인이었지만, 이번 PDF 4페이지와 렌더 이미지에서 사업금액·기간을 확인했다. 이전 참조 출력은 소급 수정하지 않았다.

## 출력 계약을 조정한 근거

- 첫 참조 계약(v1): 별도 evidence ID와 quote를 모델이 생성하도록 했으나, 2건에서 페이지 ID를 여러 인용의 ID로 중복 사용했다. 이후 1건의 진행 중 호출을 중단하고, 실패 원응답과 중단 감사를 보존했다.
- 두 번째 계약(v2): 각 사실에 페이지·quote를 직접 붙였다. 1건은 기계 검사 통과, 3건은 여러 페이지의 구절을 한 페이지 인용으로 합치거나 사실 숫자를 인용문에 충분히 넣지 않아 실패했다. 이후 1건의 진행 중 호출을 중단하고 결과를 보존했다. 국세청 출력에서는 사업금액을 계약금액이라고 바꿔 쓰는 의미상 오류도 확인했다.
- 최종 계약(v3): 각 사실 설명에 evidence_pages를 붙이고 근거 본문은 고정된 해당 PDF 페이지에서 조회한다. 모델은 인용문을 재생성하지 않는다. 사업 성격·과업·예산·기간·조건과 검토 의견·추가 확인 사항을 분리한다. 글자수·줄수 제한 없음. 숫자·고유명사·약어·금액의 역할을 보존하도록 명시했다.

이는 기존 실패 응답을 보정하거나 검증기를 우회해 성공으로 바꾼 것이 아니다. 각 계약·실행·원응답은 별도 보존하며, 최종 계약 역시 PDF 범위·숫자·영문 명칭·금액 역할 검사와 의미 대조가 필요하다. 페이지상 숫자 존재만으로 문장의 의미가 입증되는 것은 아니므로 운영 품질 승인을 주장하지 않는다.

## 실행 경계

`experiments/prespec-overview-pdf-reference/`에 정책·검증기·실행기·렌더러·테스트를 두었다. overview 용도의 기존 ModelClient만 사용하고 Qwen 모델명 및 digest를 대조한다. 호출 동시성 1, 자동 retry 0, 입력 24,000자·응답 16,384토큰·호출 300초의 자원 한도는 유지한다. 이는 요약 길이 제한이 아니라 과도한 요청과 잘린 응답을 차단하는 경계다.

원응답은 기존 암호화 model-response 객체 저장 경로와 ContentObject/Location에 저장하며, 건별 시작·결과를 AuditEvent에 남긴다. 기존 운영 개요 리뷰·스냅숏·결과와 사람 판정은 변경하지 않는다. 새 출력은 모두 `unmeasured_reference`다.

비공개 실행 입력·원응답·PDF·이전 정책은 `.dryforge/pipeline-20260903-20260907/overview-pdf-v1`, `overview-pdf-v2`, `overview-pdf-v3`에 보존한다. 모델 원문·PDF·HWP/HWPX·비밀은 커밋하지 않는다.

## 중지 시점 결과

사용자가 이번 건 이후 중지를 요청했다. 실행 상태를 확인했을 때 최종 6건의 응답이 모두 저장되어 프로세스가 이미 종료된 상태였다. 이후 추가 모델 호출·재시도는 하지 않았다.

최종 v3: 기계 검사 통과 4건(137, 614, 159, 143), 숫자 근거 검사 실패 2건(171, 610). 기계 검사 통과를 의미 품질 통과로 승격하지 않았다. RCMS 출력은 별도 PDF 이미지 대조에서 월별 예시 일정 배치를 추정한 문제가 확인되어 보고서에 담당자 확인 주의를 붙였다. 원문 페이지의 숫자 존재 검사만으로 표의 열 관계를 검증할 수 없다는 실제 한계다.

검증: 최종 정책과 validator 스키마 일치, 긴 설명 허용, 인쇄 쪽수 오인·숫자 근거 누락·근거 누락·약어 임의 풀이·사업금액의 계약금액 오표기·boolean 페이지 거절 및 복수 페이지 허용을 포함한 9개 테스트 통과. 기존 입력 원본과 변환 PDF 해시는 호출 전 대조했다. 국세청 PDF 4페이지와 RCMS PDF 3·6페이지의 렌더 이미지도 확인했다. 전체 6건의 의미 품질 대조는 완료하지 않았으며 중지 요청에 따라 후속 검토를 진행하지 않았다.

출력: `reports/prespec-overview-qwen-pdf-20260907/overview-6.md`, `overview-6.json`, `execution-results.json`. Markdown은 내부 청크 번호 대신 해당 PDF 페이지 링크를 표시한다. 기존 운영 개요 리뷰는 변경하지 않았으며 새 모델 원응답과 감사 메타데이터만 저장했다.
