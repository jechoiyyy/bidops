## 실행 범위와 방법

이전 실제 ClamAV·문서 worker 실행으로 얻은 `000/024/038-baseline-fresh.json` 전체 구조에 새 선택기를 실행했다. 이번 차수에서 파일 변환 자체를 다시 실행한 것은 아니다. 이전 원본 hash 및 동결 확인 항목 hash를 확인했다. Mock 변환기나 Mock 모델은 사용하지 않았다.

1. Unicode 정규화와 제목 내부 공백 처리를 적용한다.
2. 로마숫자 장과 아라비아숫자 하위 항목을 구분한다. 목차 점선·페이지 번호가 있는 줄을 제외한다.
3. 개요 제목과 같은 계층의 다음 장 사이를 선택한다. 짧은 제목 나열만 있는 구간은 목차 또는 본문 부족으로 남긴다.
4. 제목 계층이 불분명하거나 후보가 여러 개면 검토 대상으로 남긴다. 큰 장이 존재하는 문서에서 하위 `일반사항`을 대체 개요로 선택하지 않는다.
5. 빈 블록은 파생 컨텍스트에서만 제외한다. 선택한 각 문자열을 원본 block key·ordinal·문자 offset과 대조한다.
6. 기존 PDF 구조 경고는 유지하고, 목차·개요·다음 장 이미지 3페이지만 Luna로 대조한다.

본문 유무 검사는 정규화 길이 35자 이상인 비표 셀 줄들의 합이 100자 이상인지 보는 실험 휴리스틱이다. 짧은 정상 개요를 놓칠 수 있으며, 이것만으로 목차를 완전히 식별하거나 품질을 통과시킬 수는 없다. HWP/HWPX의 기존 `page` 값은 XML 구역 번호일 수 있어 `source_page`로 보존하고 물리 페이지로 표시하지 않았다.
