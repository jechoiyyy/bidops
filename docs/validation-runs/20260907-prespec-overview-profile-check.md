# 사전규격 개요 실행 범위와 회사 프로필 점검

이 문서는 모델 호출 전 점검 시점의 기록이다. 이후 실제 모델 실행·DB 저장·프로필 후보 보완은
[실제 개요 실행 기록](20260907-prespec-overview-live.md)에 있다.

## 사용자가 지정한 범위

2026-09-07 요청 기준, 입력은 `prespecs-20260831-20260902`의 SW사업대상 Y 공고
64건과 첨부 98개다. SW사업대상 N 609건은 이번 실행에서 제외한다.
C-1의 기본 대상은 Y이며 N은 사용자 요청 시 실행한다는 제품 기준을 전달받았다.
이번 단계는 실제 첨부 취득·파싱과 개요 검토까지이며 C-1·심층 검토·추적 결정은
실행하지 않는다. 이 기록 자체가 C-1 기본 선정 코드 변경을 의미하지는 않는다.

## 실제 실행 결과

64건의 첨부 98개에 대해 실제 다운로드와 검사·파싱을 시도했다.
최종 파싱 성공은 90개, 실패는 8개다. 실패 분류는 미지원 형식 5개,
변환 시간 초과 2개, MIME 불일치 1개다. 검사 응답 미확인 2개는 한 번씩
재검사하여 이후 변환 단계에서 시간 초과와 미지원 형식으로 각각 분류됐다.
초기 실행 스크립트의 Python import 경로 오류는 고친 뒤 해당 파일들을 재실행했다.
이 실행 오류를 문서 자체의 실패로 집계하지 않았다. 최초와 재실행 기록을 모두 보존했다.

파싱 성공 90개 중 결정적 개요 범위 추출은 22개가 ready, 68개가 unknown이다.

14건은 **사전 점검 후보**이며 DB snapshot 생성·binding·전송 검증을 마친
최종 실행 건수와 구별한다. 이번 실행의 Ollama 본문 호출은 0회다.
다운로드·구조·절단 결과는 비공개 로컬 실행 디렉터리에 보존했으며,
PostgreSQL/MinIO의 개요 리뷰 완료 상태로 적재하지 않았다.
전체 개요 검토를 완료했다고 보고하지 않는다.

정확한 서버 모델명과 digest를 사용한 개요 전용 설정을 준비했으나 적용하지 않았다.
현재 런타임의 기존 모델 정책을 Ollama 설정으로 전환하고 호환성을 확인해야 한다.

사용자에게 확인 질문을 남겼다. 확인 전 모델 본문 전송을 진행하지 않았다.
심층 자동 시작을 위한 active profile/policy 환경변수는 기존 런타임에서도 비어 있다.

비공개 실행 증거는 `.dryforge/prespec-reference-20260907/actual/parse-summary.json`,
`profile-audit.json`, 각 attachment의 원문·구조·cut·결과 파일이다.

`474b14b0946d4434e5407d19876578796dd1534ed1daa89f68ad9f7c5d54ce85`다.

## 실제 문서 처리 경로

1. 수집 원본은 보존하고 SW Y의 첨부 URL만 읽는다.
2. 실제 `ProviderConnector`로 허용한 나라장터 첨부 host에 접속한다.
   HTTPS·공인 IP·redirect·크기·timeout 검증을 사용한다.
3. 첨부 bytes와 SHA-256을 비공개 실행 디렉터리에 보존한다.
4. `ScratchDocumentProcessor`가 실제 ClamAV 검사를 하고 검사 결과를 원문 hash에 묶는다.
5. 자격증명·네트워크가 없는 실제 document-worker가 scratch 요청을 처리한다.
   HWP는 HWPX로 변환 후 XML 구조를, HWPX는 XML 구조를 추출한다.
   PDF는 텍스트 추출과 필요한 경우 렌더링·OCR 경로를 사용한다.
6. 구조 JSON의 block key, paragraph/table/cell, locator와 source hash를 보존하고
   실제 `deterministic_prefix_cut`으로 개요의 시작·끝을 찾는다.
7. 경계를 확정하지 못한 문서는 임의로 잘라 모델에 보내지 않는다.
   경계가 있는 첨부도 공고별 제안요청서 선택·입력 한도·binding 검증을 통과해야 한다.

HWPX의 page 값은 현재 section 순서에서 만들어지므로 인쇄본 페이지 번호와 같다고
주장할 수 없다. 초기 1개 HWP는 직접 processor 진단도 수행했고, 일괄 처리는
scratch 프로토콜과 실제 격리 worker를 사용한다. 다운로드 실패와 파싱 실패,
개요 범위 미확정은 각각 별도로 보존한다.

## 회사 프로필: 탐색에는 유용하나 심층 참여 판단에는 불충분

`docs/reference/company-profile.md`를 실제 `parse_profile`과
`input_versions._profile_payload_and_facts` 경로로 점검했다.
모델 입력용 fact는 43개이며 confirmed 24, inferred 4, unknown 15개다.
파서 오류 표식은 `profile_section_unstructured`다.

두 문제를 구분해야 한다.

- **원문 정보의 공백:** 실제 투입 가능한 PM/PL·기술 인력, 분야별 인원·등급·자격,
  동시 수행 가능 규모, 상주 한도, 수익·예산 기준, 공동수급 조건 등이 미확인이다.
  등록·인증은 유효기간과 적용 범위를 확인할 원본 증빙이 필요하다.
  실적은 수행 역할·지분·금액·기간·완료·발급 가능한 증명서를 연결해야 한다.
- **모델 입력의 공백:** 대표 실적·인증·제품/솔루션·주요 고객·반복 수행 기관 등
  원문에 있는 서술/표 일부가 status 기반 YAML fact로 추출되지 않는다.
  항목 없이 비구조화로 표시되는 절이 11개다. 원문 파일의 길이가 길어도
  심층 모델이 해당 내용을 모두 받는 것은 아니다.

기술·사업 분야 적합성을 탐색하는 참고자료로는 사용할 수 있다. 입찰 자격 충족,
실적 요건 충족, 인력 투입 가능성이나 최종 참여 가능 판정을 확정할 수준은 아니다.
미확인 정보를 추정해 채우거나 기존 프로필 snapshot을 덮어쓰지 않았다.

후속 순서는 원문에 이미 있는 근거를 구조화해 새 프로필 버전으로 가져오는 것,
누락 사실과 근거 위치를 대조하는 것, 실제 정보 공백을 담당자에게 확인하는 것이다.
프로필 내용은 개요 모델 입력에 포함되지 않으며 이번 단계에 회사자료를 전송하지 않는다.
