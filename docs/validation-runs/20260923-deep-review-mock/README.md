# 심층검토 세 묶음 MOCK 시안 — 2026-09-23

사용자 승인 범위: 가상 입력으로 요청 → 미리보기·모의 승인 → 진행 → 보고서·근거 확인.
실제 모델 호출·운영 정책·DB·배포 변경 없음. 실제 자료와 회사 정보를 사용하지 않았다.

## 시안 실행

```bash
cd web/frontend
npm run dev:mock -- --port 5194
```

주소: `http://localhost:5194/pre-specs/mock-review`.
기존 사전규격 목록의 `가상 사업 심층검토` 버튼에서도 진입한다.
가상 상세에서 완성 보고서 / 두 번째 단계 실패를 선택한다. 새로고침하면 초기화된다.
모의 승인은 실제 전송 승인이 아니며 외부 호출은 0회다.

## 입력과 설계

`web/frontend/src/mock-review/scenario.ts`에 가상 제안요청서 4절·회사 자료 3절,
8개 질문의 설명형 답변·원문 참조와 요청 묶음을 함께 정의했다.
화면 아래 `세 요청의 입력·응답 보기`에서 실제 사용하는 고정 입력/응답을 확인한다.

1. 사업 조건 이해: 과업·평가·계약 조건. 제안요청서 전체 입력.
2. 회사 대조: 적합성·수행 위험과 회사 원가 영향. 원문·회사 자료·1차 결과 입력.
3. 판단과 행동: 종합·다음 행동·판단 변경 조건. 두 결과와 근거 입력.

모의 진행은 React 상태로 재현하며 worker·큐·API 실행 연동은 하지 않는다.
세 묶음은 가상 표본의 목표이고 실제 문서 전체가 3회에 수용된다는 증거가 아니다.
실제 연결에서는 입력과 출력 예산을 확인하고 문서 절·표·조건과 예외 단위로 묶는다.
긴 문서의 무제한 단일 호출이나 조용한 입력 잘림은 채택하지 않는다.

금액 수동 대조: 월 인건비 1,400+300만원 × 12개월 = 20,400만원.
도구·출장 2,400 + 간접비 3,600 = 기본 원가 26,400만원.
상한 30,000 − 기본 원가 26,400 = 3,600만원이며 이익으로 표현하지 않는다.
중소기업확인서·야간 교대·보안교육은 미확인, 상근은 2명 요구 대비 1명 부족으로 표시한다.

## 이번 변경의 검증

- `npm run build`: TypeScript strict + production build 통과. 큰 bundle 경고 있음.
- production assets에서 `가람연구원`·`mock-review` 검색 결과 없음: 시안은 개발 MOCK 모드에서만 포함.
- `BIDOPS_MOCK_UI=1 PW_PORT=5194 npx playwright test tests/mock-review-prototype.spec.ts --project=app`:
  3개 통과(가상 근거/질문 커버리지, 1280×800 전체 흐름, 1440×900 전체 흐름).
  실패 시나리오 검사는 실제 MOCK 오류 문구와 기대값 불일치로 실패했다.
- 실제 응답과 기존 mock handler 확인 후 기대 문구만 수정하고 동일 명령에 `-g '두 번째'`를 붙여 재검사: 1개 통과.
  총 4개 관련 사례 충족, 이 실행에서 skip 없음. 기본 production 테스트에서는 개발 전용 검사를 명시적으로 skip한다.
- 앞선 검사에서 숨긴 details의 heading을 위치로 선택한 검사 오류도 확인했고, 열린 details로 범위를 고쳤다.
- 정상 실행의 API mutation 0건, 실패 시 최종 보고서 없음, 동일 프레임 중복 제출 방지,
  입력·응답 열람, 재시작, 미처리 API의 MOCK 404 응답을 확인했다.
- 두 viewport에서 승인 전 화면·대기 상태·완성 본문·근거 패널을 캡처했다.
  대기 캡처는 대기 상태의 증거이며 실제 모델 진행 속도의 증거가 아니다.
- `git diff --check` 통과. PostgreSQL·실제 모델·운영 스택은 이번 범위에서 검사하지 않았다.

MOCK 시안의 동작 검증이며 실제 모델 정확도·속도·3회 실행 성공의 증거로 사용하지 않는다.
