# 운영 적용·실제 Qwen 참조 검증 — 2026-09-22

**검증 완화·실행별 on/off 운영 적용 완료. 실제 off 실행은 문서 분석 완료 후 회사 대조에서 실패.** 사용자의 “적용과 품질 검증도 진행해봐”
요청에 따라 운영 스택에 적용하고 실제 Qwen을 호출했다. 처음 두 실행은 실패했으며,
세 번째 실행에서는 페이지 전체의 연속 인용이 단일 문단 제한에 걸렸다. 이후 이 제한을
완화하고 사용자가 확정한 원문 대조 on/off를 적용해 네 번째 실행까지 확인했다.
`unmeasured_reference` 표식을 유지하며, 사람 정답 지표나 정책 품질 통과로 승격하지 않는다.

- 정책 `8973ae72-9107-4418-9ab8-0bc5eb4822db`, 승인 프로필
  `d970500a-e30c-46cf-85e0-7e9a9e854f2b`를 **PoC 참조 실행 설정으로 선택**했다.
  정책 SHA-256은 `d97e5294ded62453c4bd75bb44a3ebbe182e24b04565e36444c8b0eecf69879a`다.
- 회사 핏 자동 실행은 false, 기존 개요 true·C-2 일일 실행 true·GPU 휴지 설정은 유지했다.
  migration은 하지 않았고 head `0031_prespec_preliminary_assessment`를 유지했다.
- 기존 프로필 source 버전이 `NoSuchVersion`으로 읽히지 않는 문제를 발견했다.
  같은 해시의 승인 원문을 명시적 `--repair-profile-source`로 재검증해 새 위치와 감사
  1건을 추가했다. 기존 프로필·회사 근거·과거 위치는 보존했다. 다른 과거 프로필은 미복구다.
- 실패 원인을 일반 코드로만 남기던 경로를 보완했다. 설명형 범위 오류는 정적 코드로,
  해당 실패 모델 응답은 암호화 model-response 저장소에 남긴다. 실패 결과를 보고서로
  발행하거나 모델 내용을 자동 보정하지 않는다.

## How · 과도한 검증을 어떻게 완화했나

- 공백·줄바꿈·따옴표 모양·전각 ASCII 차이는 고정 원문 위치에서 유일하게
  대응하는 원문 문자열로 연결한다. page 위치는 같은 페이지의 연속 문단도 허용한다.
  숫자/영문 토큰 합치기·문단 생략·순서 변경·다른 페이지 결합은 허용하지 않는다.
- 같은 원화 금액은 Decimal 단위 환산으로 인정한다. `84백만원`과 `84,000,000원`은
  허용하지만 `84만원`이나 `85,000,000원`은 차단한다.
- `’27`을 `2027년`으로 풀어 쓴 것은 본문 옆 확인 사항으로 남기고 생성은 허용한다.
  세기를 확정하지 않으며 다른 연도는 차단한다. 분석 한계·검증 경고에도 연결한다.
- 한 원문 조각의 선행 분석도 여러 묶음으로 나눠 회사 대조에 전달하고 모든 claim ID와
  coverage를 보존한다. 모델 로컬 UUID는 호출별 namespace에 결속한다.
- 원문 hash·위치·문서/회사자료 범위·다른 수치·부정 조건·전체 입력 누락·최종 종합
  입력 상한은 유지한다. 인용 일치가 문장 전체의 의미를 증명한다고 하지 않는다.
- 기존 정책 파일과 실패 이력은 보존했다. 이번 변경은 입력 처리·결정적 검증·UI이며
  프롬프트나 생성 설정을 바꾸지 않았다.

저장된 두 번째 실패 응답을 새 코드로 재검사한 결과 **통과**했다. 공백 차이 1건을
정확한 원문으로 연결하고 축약 연도 3건을 경고로 분리했다. 회사 대조 입력은 2묶음,
각 prompt 16,377자·10,125자로 24,000자 제한 안이다. 이는 **추가 모델 호출 없는
재검사**이며 전체 Qwen 실행 성공을 대신하지 않는다.

세 번째 attempt `20e3508d-a88b-4573-95e3-a2b676bd3a91`은
`2026-09-22T04:26:12.810111Z`에 시작해 `04:32:46.257736Z`에 인용 범위 오류로
실패했다. 실제 반환은 주장 11개·근거 1개였고 같은 페이지의 연속된 여러 문단을 인용했다.
page 위치에 맞게 연속 문단을 허용한 재검사에서는 인용 검사를 통과했다. 별도로 영문
`September 2026`과 원문의 축약 연도 대조 1건은 남는다. 영문 출력과 의미 품질은
검증 스위치 구현만으로 해결한 것으로 기록하지 않는다.

## 실행별 on/off 적용·검증

사용자가 권장안을 확정해 웹의 새 분석/재실행에서 **원문 인용·숫자 대조만** on/off한다.
기본 on이며 attempt 감사 기록으로 고정한다. off도 원문 hash·문서/페이지/회사자료 범위·
접근/안전·JSON/참조·계산식 재연산·누락 검사는 유지한다. 보고서에는 `원문 대조 미실시`,
근거 패널에는 모델 인용과 실제 원문을 구분해 표시한다. 이전 결과를 소급 변경하지 않는다.

- 관련 backend 148 passed 후 신규 명시 계약 필드 때문에 달라진 기대값 2건을 갱신해
  해당 2 passed. 재실행 HTTP 경로 별도 1 passed.
- PostgreSQL 17.11에서 정상·연도 경고·연속 문단·off 및 이력 보존 **4 passed**.
- UI 시작 요청·재실행·본문·기존 경로 **8 passed**. 설정으로 바로 가는 버튼을 보완한 뒤
  본문과 on/off 1280/1440 **4 passed**. 이미지의 production build를 그대로 사용했다.
- 합성 fixture 캡처: [설정 1280](synthetic-settings-1280.png),
  [설정 1440](synthetic-settings-1440.png), [미대조 인용과 원문](synthetic-unchecked-evidence-1440.png).
  실제 Qwen 보고서 캡처가 아니다.
- 운영 웹에서 체크박스를 끄고 재실행 단추를 눌러 **202 + false**를 확인했다.
  새 attempt `452f52b8-7965-44fc-96dc-3846b005beec`; 브라우저 오류 0.
  [실제 UI→REST 기록](live-toggle-check.json). 첫 문서 분석 단계는 완료됐다(주장 11개·근거 11개, 본문 11개 모두 한국어,
  한 호출 232,266ms·출력 7,751 tokens). 같은 응답을 on 기준으로 재검사하면
  숫자 근거 불일치 1건이 남는다. off 실행은 이를 대조 완료로 표시하지 않고 후속
  회사 대조로 진행했다.

### 실제 off 실행의 최종 결과와 남은 문제

네 번째 실행은 `05:01:16.534788Z`에 시작해 `05:06:52.117174Z`에 실패했다.
문서 분석은 완료됐고 회사 대조 첫 응답에서 `unexpected_synthesis_coverage`로 멈췄다.
저장된 응답과 실제 입력을 재검사해 다음 두 문제를 구분했다.

1. 입력에 포함된 선행 주장 7개를 `considered_claim_ids`에 적은 것은 유효한 부가 정보다.
   회사 대조에서는 무조건 빈 배열을 요구하던 검사를 **입력 범위 대조**로 완화했다.
   누락 검사가 필요한 종합 단계는 전체 포함을 계속 요구한다. 관련 검사 10 passed.
2. 모델이 회사자료 근거 ID 3개를 `premise_claim_ids`에 넣었다. 이들은 회사 근거로는
   존재하지만 주장 ID가 아니므로 연결할 수 없다. `dangling_premise`,
   `inference_evidence_required`, `unknown_shape`도 반환됐다. 이 검사는 유지한다.

최종 코드로 저장 응답을 그대로 재검사하면 첫 제약은 해소되지만
`claim_relation_out_of_slice`와 위 근거/형식 오류는 남는다. 실제 전체 생성 성공으로
기록하지 않는다. 추가 모델 호출 없이 재검사했으며 기존 실행·정책·응답은 수정하지 않았다.
원문 대조 off의 선택·전달·적용은 확인했으나 **완성 보고서 0건, 실제 내용 품질 미검증**이다.
후속 작업은 ID 종류와 근거 연결을 명확히 하는 새 불변 정책과 실제 생성 검증이며,
참조/근거 형식 오류를 대조 스위치로 우회하지 않는다.
