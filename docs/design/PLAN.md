# BidOps 화면 개선 구현 계획

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 — 착수 순서와 검증 게이트 |
| 문서 버전 | v0.1 |
| 기준일 | 2026-09-02 |
| 요구사항 | [PRD.md](PRD.md) |
| 채택 결정 | [ADR-0039 · ADR-0040 · ADR-0041](ADR.md) |

이 계획은 화면을 한 번에 갈아엎지 않는다. 각 단계는 **되돌리기 단위가 화면 하나**가 되도록
쪼개고, 앞 단계의 검증 증거를 다음 단계의 입력으로 쓴다. 코드가 있다는 사실과 화면 전환
완료를 구분한다.

## 1. 구현 원칙

- 레이아웃은 프로젝트가 소유한다. Astryx 페이지 템플릿으로 화면 골격을 대체하지 않는다.
- 한 화면 안에서 Tailwind와 Astryx를 섞지 않는다. 이행한 화면은 Astryx 토큰만 읽는다.
- 테마는 `astryx theme build` 산출물을 커밋해서 쓴다. 런타임 `defineTheme()`을 쓰지 않는다.
- 서체는 Pretendard 자체 호스팅을 유지한다. 외부 폰트 호스트를 런타임에 부르지 않는다.
- 판정 화면을 바꿀 때 등급·준비 상태·추적 승인·Go/No-Go의 분리를 유지한다.
- `unknown`·`null` 표기를 화면에서 지우지 않는다.
- 각 단계는 시각 기준선 갱신을 포함해야 완료로 본다.

## 2. 현재 기준선

| 항목 | 값 |
|---|---|
| 프론트엔드 | React 19 · Tailwind 4 · radix-ui · Vite 6 |
| 시각 회귀 | `web/frontend/tests/visual.spec.ts` 19개 · 기준선 PNG 124장 |
| 라우트 | `path` 항목 23개 (리다이렉트 2 포함) · 사이드바 16항목 |
| 화면 골격 CSS | `src/styles/` 15개 파일 (`theme.css` 108KB 포함) |

검증 명령은 다음 셋을 쓴다.

```bash
./run-tests.sh                    # 파이프라인 단위·교차
./web/run-web-tests.sh            # 백엔드·통합
cd web/frontend && npm run test:visual
```

## 3. 단계

### 0단계 — 의존성과 테마 기준선

Astryx를 설치하고 neutral 테마를 저장소에 고정한다. 화면은 아직 바꾸지 않는다.

**할 일**

1. `web/frontend`에 `@astryxdesign/core@0.5.2` dependency, `@astryxdesign/cli@0.5.2`
   devDependency 추가. 버전 고정.
2. `npx astryx theme add neutral`로 테마 소스를 받고, `--font-family-*` 토큰을 Pretendard가
   앞에 오는 스택으로 덮어쓴다.
3. `npx astryx theme build`로 정적 CSS·JS를 만들어 저장소에 커밋한다. 산출물 경로와 재생성
   명령을 파일 머리말에 남긴다.
4. `reset.css` → `astryx.css` → 테마 CSS의 layer 순서를 진입점에서 고정한다.
5. `CLAUDE.md`와 `AGENTS.md`의 외부 의존성 목록에 Astryx를 추가한다.

**완료 게이트**

- `npm run build` 통과
- 시각 기준선 124장 **무변경**. 이 단계에서 화면이 바뀌면 격리가 실패한 것이다
- `astryx theme build --check`가 커밋된 산출물과 소스의 일치를 확인한다

### 1단계 — 발주계획 C-2 목록과 판정 통합 (P1)

가장 큰 병목을 한 화면에서 없앤다. 이 단계가 이행 방식의 실증을 겸한다.

**할 일**

1. `PlanCard` 목록을 밀집 행으로 교체한다. 행에는 판정에 필요한 값만 둔다.
2. 오른쪽에 크기 조절 가능한 상세 영역을 붙이고 사람 피드백 폼을 그 안으로 옮긴다.
3. 신호 세부와 운영 텔레메트리를 상세 영역의 별도 탭으로 분리한다. 삭제하지 않는다.
4. 필터 버튼 4종을 조합 가능한 토큰 필터로 바꾸고 저장된 뷰를 만든다.
5. 저장 후 `다음` 이동을 넣는다.
6. 페이지 상단 설명 블록을 접을 수 있게 하고 실행 상태를 한 줄로 요약한다.

**완료 게이트**

- 한 건 판정에 페이지 이동 **0회**
- `filtered_out`·`not_relevant`·`unknown`·`null`이 서로 바뀌어 표시되지 않음을 테스트로 고정
- 기존 `order-plans.spec.ts` 통과. 시각 기준선 갱신 후 커밋
- 이 화면에 Tailwind 유틸리티 클래스가 남아 있지 않음

### 2단계 — 정보구조 재편과 Go/No-Go 승격 (P2 · P3)

화면을 새로 만들지 않고 배치만 바꾼다.

**할 일**

1. 사이드바 1차 분류를 회차 검토 / 누적 추적 / 기준과 운영으로 바꾼다.
2. `최종 Go/No-Go`를 최상위 항목으로 추가한다. 결정 대기 사업기회 목록을 진입 화면으로 만든다.
3. 기준 4화면을 `판정 기준` 한 화면의 탭으로 합친다.
4. 운영 3화면과 감사 로그를 `실행 상태` 한 화면으로 합친다.
5. `/deadlines`·`/audit` 리다이렉트를 각 화면의 저장된 뷰로 흡수한다. 기존 경로는 새 뷰로
   연결되게 남긴다.
6. 공고 판정 이력·담당자 리뷰 기록을 검토 대기열 탭으로 옮긴다.
7. 심층 검토 보고서 진입점을 사업기회 화면에 명시한다.

**완료 게이트**

- 사이드바 8항목, 모두 실제 화면
- 회차 선택기 표시 여부가 1차 분류와 일치
- 기존 경로가 404를 내지 않음
- `common-interactions.spec.ts`의 내비게이션 검사 갱신

### 3단계 — 사전규격 그룹화와 대시보드 확장 (P4 · P6)

**할 일**

1. 사전규격 목록을 개요 검토 상태별 접이식 그룹으로 바꾼다. 그룹별 건수를 표시한다.
2. 사람 검토 필요·실패를 기본 펼침, 완료를 기본 접힘으로 한다.
3. 심층 추적 승인을 목록 화면에서 내릴 수 있게 한다.
4. 대시보드 `지금 처리할 일`에 C-2 검토 대기, 사전규격 의견등록 마감, Go/No-Go 대기를 추가한다.

**완료 게이트**

- 개요 검토 상태 10값이 모두 그룹으로 표현됨
- 할 일 스트립에서 네 결정 화면 각각으로 이동 가능
- 시각 기준선 갱신

### 4단계 — 상세 화면 3종 골격 통일 (P5)

가장 큰 화면들이므로 마지막에 손댄다.

**할 일**

1. 사전규격 상세, 발주계획 상세, 입찰 변경 비교를 같은 골격으로 맞춘다.
   요약 헤더(상태 + 액션 고정) · 본문 반복 목록 · 우측 레일 이력.
2. 결정 액션을 헤더에 고정해 스크롤 위치와 무관하게 누를 수 있게 한다.

**완료 게이트**

- 세 화면에서 결정 액션이 첫 화면에 보임
- `bid-delta.spec.ts`, `deep-review.spec.ts`, `document-preparation.spec.ts` 통과
- 시각 기준선 갱신

## 4. 단계별 되돌리기

각 단계는 화면 단위 커밋으로 남긴다. 문제가 생기면 그 화면의 커밋만 되돌리고, Astryx 의존성과
테마(0단계)는 유지한다. 0단계를 되돌리는 경우에만 의존성을 제거한다.

## 5. 이 계획이 다루지 않는 것

- 다크 모드
- 미구현 흐름의 신규 화면
- Astryx 버전 갱신 정책
- 한글 서체 교체(Pretendard 유지가 전제다)
- 로그인·권한·알림

## 6. 열린 항목

| 항목 | 필요한 결정 | 시점 |
|---|---|---|

| 사이드바 브랜드색 | neutral 무채색을 받아들일지, accent만 RootLab 초록으로 덮을지 | 2단계 착수 전 |
| 저장된 뷰의 저장 위치 | 주소 파라미터 · 로컬 · 서버 중 어디에 둘지 | 1단계 착수 전 |
| 통합 색인 등록 | ADR-0039~0041을 `docs/ADR.md`와 `docs/tracking/decisions/`에 올리는 작업 | 0단계와 함께 |
