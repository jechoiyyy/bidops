# 사전규격 개요검토·예비 적합성 등급 통합 — 의도

- 상태: 제품 구현·격리 검증 완료. 모델 품질 측정·운영 적용 전.
- 작성일: 2026-09-21
- 문서: `intent.md`(목적·확정 선택) · [spec.md](spec.md)(기능·계약) · [plan.md](plan.md)(구현·검증 순서)
- 근거: 사용자 인터뷰와 최종 계획, `claude -p --model fable --effort high` 독립 리뷰의 계약 보완 사항.

## 1. Why — 왜 바꾸는가

사전규격 담당자가 **“무슨 사업이며, 우리 회사가 더 검토할 가치가 있는가”**를 개요검토 결과에서 함께 판단하도록 한다.

현재 개요검토는 문서 앞부분의 사업 목적·주요 과업·예산·기간을 요약한다. 화면의 적합성 등급은 별도의 선별 판정과 사람 정정값을 읽는다. 회사 핏도 별도 경로이며, 그 결과가 곧 화면의 4단계 등급은 아니다.

같은 문서 앞부분을 사용하는 개요와 예비 판단을 함께 생성하면 중복 입력과 기능별 호출을 줄일 수 있다. 정상 경로는 LLM 1회로 처리하고, 제외 후보와 위험 신호가 있는 결과만 추가 검증한다. 로컬 모델의 처리 시간·GPU 사용을 줄이고 향후 유료 API를 사용할 때의 효율성도 고려하되, 이번 작업에서 외부 API를 연결하지는 않는다.

이 단계의 질문은 **사업 관심도에 따른 검토 우선순위**다. 실제 수행 가능성·참가자격·참여 준비·추적 결정·최종 Go/No-Go는 별도 판단이다. 개요에 없는 사실은 심층검토에서 확인하며, 정보 부족을 제외로 바꾸지 않는다.

## 2. What — 사용자가 얻는 것

- 개요 요약과 함께 예비 적합성 등급, 핵심 이유, 공고와 회사 양쪽의 근거를 확인한다.
- 목록·상세·필터가 같은 대표 등급을 사용한다. 개요 기준이라는 한계와 출처·시점을 함께 본다.
- 판단이 어려운 건은 원문과 보류 사유를 확인한다. 미판정과 판단 보류는 구분한다.
- 향후 심층검토에서 사실·판단·근거·확인 항목을 다시 사용할 수 있다.

## 3. 확정한 선택

| 항목 | 결정 |
|---|---|
| 평가 목적 | 사업 관심도에 따른 후속 검토 우선순위 |
| 관심 분야 | AI/데이터·블록체인/DID·공공 SI/통합관리를 동등하게 적용 |
| 회사 역량·실적 | 확인된 정보만 보조 근거로 사용. 추정 정보를 확정 사실로 승격하지 않음 |
| 등급 | 우선 검토·검토 권장·관찰 대상·제외의 4단계 유지 |
| 정보 부족 | 등급 `null`과 별도 판단 보류 상태 |
| 화면 역할 | 새 예비 판단을 목록·상세의 대표 등급으로 사용. 사람 정정 우선 |
| 생성 호출 | 개요와 구조화된 관심도 판단을 통합해 정상 1회 |
| 의미검증 | 위험 조건에 해당할 때 최대 1회 추가. 제외 후보는 반드시 추가 검증 |
| 호출 상한 | 형식 오류 재시도 1회를 포함해 실행당 최대 3회 |
| 자동 실행 | 새 표시 등급으로 기존 자동 준비·심층검토 조건을 바꾸지 않음 |
| 심층검토 연계 | 재사용 가능한 결과·검증 기반까지. 실제 입력 연결과 회사 핏 대체는 후속 |
| 과거 건 | 자동 일괄 재평가 없음. 새 문서와 사람이 요청한 재실행에 적용 |

## 4. 범위와 경계

이번 작업은 개요검토, 예비 판단, 대표 등급 projection, 목록·상세·필터, 근거와 버전 저장, 검증 함수 재사용 기반을 포함한다.

심층검토의 입력 연결·회사 핏 대체·자동 실행 정책 개편, 새로운 화면 전용 등급 정정 API, 과거 건 일괄 평가 기능, 유료 외부 API 연결은 후속 범위다. 기존 사람 정정 저장 동작은 유지한다.

등급이 제외여도 목록 숨김·추적 종료·최종 No-Go를 실행하지 않는다. 원본 문서, 과거 모델 결과와 사람 리뷰는 덮어쓰지 않는다. 품질 미측정·참조 결과를 운영 품질 통과로 표현하지 않는다.

## 5. How — 접근과 성공 기준

모델은 요약과 축별 관계·근거 ID를 출력하고, 서버가 근거 검증과 등급 계산을 수행한다. 원문·회사 근거가 존재하는지 확인하는 규칙 검증과 문맥 해석의 의미검증을 구분한다. 위험 신호가 없다는 사실은 의미 정확성의 보증이 아니다.

사실 요약과 판단 객체를 독립 검증·게시해, 등급만 실패한 경우 사용 가능한 개요는 보존한다. 실행 완료, 개요 게시 가능, 등급 게시 가능, 의미검증 범위를 분리한다. 기존 자동화 소비자는 종전 검증 수준을 충족한 개요만 사용한다.

구현 성공은 [spec.md](spec.md)의 기능·계약과 [plan.md](plan.md)의 관련 검사가 갖춰진 변경이다. 비용과 품질의 개선 여부는 고정 원문 표본과 사람 판단으로 측정한다. 모델이 만든 정답을 사용하지 않는다.

실제 비교 실행 전에 표본과 품질 통과 기준을 고정한다. 구현 완료나 이 문서 작성만으로 정책을 활성화하지 않는다. 실제 모델 호출·migration·배포·정책 적용은 각 단계의 운영 확인을 거친다.
