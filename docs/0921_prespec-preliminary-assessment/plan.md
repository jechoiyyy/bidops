- 상태: 제품 구현·격리 검증 완료. 품질 비교·운영 적용은 미착수.
- 작성일: 2026-09-21
- 문서: [intent.md](intent.md)(목적·확정 선택) · [spec.md](spec.md)(기능·계약) · `plan.md`(이 문서)

## 1. 목표와 완료 범위

개요와 사업 관심도 판단을 통합 생성하고, 근거·규칙 검증과 선택적 의미검증으로 예비 등급을 제공한다. 화면 대표 등급과 기존 자동화 등급을 분리하고, 심층검토에서 재사용할 사실·판단·근거·버전을 보존한다.

구현 완료는 관련 코드·계약·migration·화면과 영향 범위 검사가 갖춰진 검토 가능한 변경이다. 실제 품질 비교와 운영 적용은 별도 확인 단계이며, 구현 완료만으로 정책을 활성화하지 않는다.

§3의 검사 명령·경로는 검증 범위를 정한 기준이며 실제 실행 결과는 아래 완료 기록에 적는다. 품질 비교와 운영 적용은 아직 실행하지 않았다.

### 개발 담당 모델

작업 담당은 **sol high**(`gpt-5.6-sol`, reasoning effort `high`)와 **luna max**(`gpt-5.6-luna`, reasoning effort `max`) 중에서 배정한다. 이 배정은 제품 안에서 호출하는 사설 Qwen 모델이나 overview 용도 설정을 변경하지 않는다.

공식 문서상 Sol은 복잡한 전문 작업을 위한 모델이며 Luna는 비용 효율을 중시하는 작업용 모델이다. 두 모델 모두 여기 지정한 effort를 지원한다. 아래 배정은 해당 설명과 이번 작업의 계약 위험·범위를 바탕으로 한 판단이며, 이 저장소에서 두 모델의 구현 품질을 비교 측정한 결과는 아니다. 근거: [GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol), [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna) (2026-09-21 확인).

| 작업 묶음 | 담당 | 선행 조건·배정 이유 |
|---|---|---|
| 계약·상태·ADR 정의 | sol high | 부분 성공·검증 범위·기존 소비자 경계를 함께 판단해야 함 |
| migration·입력 고정·프로필 해석 | sol high | 원본 불변성·무결성·구버전 호환에 직접 영향 |
| 통합 생성·파싱·정책 loader | sol high | 한 응답의 부분 실패와 호출 예산을 기존 runner에 통합 |
| 근거 검증·등급 계산·선택적 의미검증 | sol high | 핵심 과업·근거 의존성·잘못된 제외 처리의 중심 로직 |
| 자동화 소비자·재관측·재실행·재사용 | sol high | 표시 변경이 자동 실행으로 번지거나 과거 건을 다시 처리할 위험 |
| 대표 등급 API·batch projection·필터 | sol high | 화면·건수·페이지 분할·기존 API의 의미를 일치시켜야 함 |
| 프런트 타입·목록·상세·필터 배선과 화면 검사 작성 | luna max | API·상태·기대 결과 확정 뒤 기존 컴포넌트에 연결하는 범위 |
| 백엔드 회귀 검사 작성·통합 검증 실행 | sol high | 계약·PostgreSQL 변형·모듈 간 영향을 함께 확인 |
| 확정된 계약·운영 절차 문서 반영 | luna max | 구현 결과와 승인된 규칙을 입력으로 받아 문서에 반영 |
| 품질 비교 설계·결과 분석·운영 적용 준비 | sol high | 사람 정답·검증 한계·활성화·롤백 조건의 판단 필요 |

총괄과 관련 검사 실행자는 **sol high 한 컨텍스트**로 둔다. 작업자는 자기 변경에 필요한 검사 코드를 함께 작성하고, 총괄이 영향 범위 검사를 직접 실행해 인수한다. 동일 검사를 담당자마다 반복하거나 추가 리뷰 단계를 관성적으로 만들지 않는다. §2~§5의 체크 항목에는 담당 모델을 직접 표기한다.

Luna 작업에는 확정된 API 예시, 상태·문구, 담당 파일, 기대 결과를 전달한다. 계약 해석이나 판정 정책 변경이 필요한 차이는 총괄 Sol이 먼저 해결한다. 두 작업이 같은 파일을 수정해야 하면 순차 진행한다. 담당 배정은 실행 승인이나 실제 위임을 뜻하지 않는다.

## 2. 구현 순서

### 계약과 입력·저장 기반

- [x] **sol high** — 실행 상태·개요 게시·등급 상태·검증 범위를 분리한 새 계약을 추가한다. 구버전 reader와 새 버전의 의미를 구분한다.
- [x] **sol high** — 개요 run의 입력 바인딩·판단 객체·검사 범위·실행별 정책/프롬프트 정보를 저장하는 migration을 추가한다. Alembic head와 런타임 기대 revision을 동기화한다.
- [x] **sol high** — 프로필 전용 해석과 최소 구조화 투영을 사용한다. 미설정과 고정 입력 해시 불일치·손상을 구분한다.
- [x] **sol high** — 새 불변 정책·validator를 발행하고 loader가 구·신 버전을 명시적으로 처리하게 한다. 기존 정책 파일은 고치지 않는다.
- [x] **sol high** — 원문·프로필·정책·모델·생성 설정의 고정 입력과 결과 이력을 연결한다.

### 통합 생성과 판정·검증

- [x] **sol high** — 기존 overview client·합성 worker에서 통합 생성 응답을 처리한다. 별도 worker나 기능별 생성 호출을 추가하지 않는다.
- [x] **sol high** — 개요와 판단을 독립 파싱한다. 전체 JSON 손상과 객체 단위 오류를 구분한다.
- [x] **sol high** — 축별 관계·실제 수행 과업·근거 의존성으로 등급을 계산한다. 핵심 근거 탈락은 보류로 연결한다.
- [x] **sol high** — 인용·수치의 명백한 불일치와 문맥의 모호성을 구분한다. 새 validator의 강화된 규칙은 새 결과에만 적용한다.
- [x] **sol high** — 제외 후보·역할/문맥/수치 위험 조건에서만 의미검증을 1회 수행한다. 게시 후보 개요 전체와 판단의 검사 범위를 보존한다.
- [x] **sol high** — 정상 1회, 선택적 검증 포함 2회, 형식 재시도 포함 최대 3회를 강제한다. 사실 오류 재생성·의미검증 재시도·provider fallback은 금지한다.

### 기존 소비자·재실행 경계

- [x] **sol high** — 기존 회사 핏·자동 시작 경로가 새 `completed` 상태만으로 통과하지 않게 한다. 현재 입력의 전체 개요가 종전 검증 수준을 충족한 경우만 소비한다.
- [x] **sol high** — 기존 effective grade와 사람 정정 hook은 유지하고 표시 등급과 섞지 않는다.
- [x] **sol high** — 같은 문서의 기존 종결 결과는 정책·프로필 교체나 재관측만으로 자동 재실행하지 않게 한다.
- [x] **sol high** — 새 문서·명시적 재실행과 동일 입력 재사용을 구분한다. 명시적 재실행은 새 run에서 실제 평가한다.

## 3. 검증 목록

검사 실행 담당은 **sol high**다. 백엔드 검사 작성도 sol high가 맡고, 화면 검사 작성은 API 계약이 확정된 뒤 luna max가 맡는다. 리더가 관련 검사를 한 번 수행하고, 추가 검토가 있으면 같은 소스와 결과를 사용한다. 수정 후에는 영향받은 검사만 다시 실행한다.

| 검증 항목 | 입력·기대 결과 | 검사 위치·증거 |
|---|---|---|
| 등급 계산 | 직접/부분/간접/무관/미확인·복합 과업; 해당 등급 또는 보류 | `tests/deep_review/`의 순수 판정 검사와 pytest 결과 |
| 근거 의존성 | 핵심 과업 인용 탈락; 약한 근거로 하향 판정하지 않고 보류 | 개요 claim 검증·run 검사 |
| 사실 검증 | 감리/개발 혼동, 부정·조건, 예산 주체·단위, 없는 인용, 미확인 회사 역량 | validator 검사; 명백한 실패를 추가 호출로 구제하지 않음 |
| 부분 파싱·게시 | 정상 개요+잘못된 판단 객체; 개요 보존·등급 보류. 전체 JSON 손상은 전체 형식 실패 | parser·runner·API 통합 검사 |
| 호출 예산 | 정상 1회, 위험/제외 2회, 형식 재시도 포함 최대 3회 | fake model 요청 기록과 실제 runner의 `call_count` |
| 검증 범위 | 의미검증 ID 누락/중복·등급만 검증; 전체 개요 통과로 승격 금지 | semantic 계약·기존 소비자 통합 검사 |
| 자동화 격리 | 표시 우선 검토·기존 등급 부적격; 기존 자동 준비 자격 유지 | `tests/app/`의 사전규격 projection·자동 준비/시작 통합 검사 |
| 프로필 | 미설정은 회사 근거 없이 평가 가능; 해시 불일치는 판단 보류 | 입력 해석·runner 검사; 심층 정책 상태와의 분리 확인 |
| 재관측·재실행 | 구정책 완료 건 재관측 시 새 run 0건; 사람 재실행 시 1건 | enqueue·적재 hook 통합 검사 |
| 동일 입력 재사용 | 모든 바인딩 일치만 재사용; 명시 재실행은 실제 평가 | 캐시/입력 바인딩 검사 |
| 대표 등급 | 사람 정정 우선, 새 보류, 미판정, 기술 실패·취소, 문서 변경 | API strict 응답·필터·건수 검사 |
| 목록 효율 | 서로 다른 건수에서도 추가 조회가 건수에 비례하지 않음 | batch projection 쿼리 수 비교 |
| 이력·호환 | 구·신 정책 run 혼재; 각자 버전·품질·검증 수준 표시 | API·migration 검사 |
| 화면 연결 | 목록→상세의 등급·출처 일치, 필터/건수, 근거 이동, 부분 결과·품질 표식 | 사전규격 Playwright 검사, 필요한 상태의 실제 캡처 |
| 화면 구조 | 1280×800·1440×900에서 레이아웃·긴 한글·오류/보류 상태 | 영향 화면의 구조 검사 |

### 실행 범위와 명령

- 백엔드: 변경한 `tests/deep_review/`와 직접 영향받는 `tests/app/` 파일을 `web/backend/.venv/bin/python -m pytest <대상 파일>`로 선택 실행한다. 새 검사도 같은 소유 디렉터리에 둔다.
- PostgreSQL: 일회용 `postgres:17.11`과 `BIDOPS_TEST_POSTGRES_URL`을 사용해 관련 파일의 PostgreSQL 변형, 빈 DB migration, 구버전 행 유지·제약·중복 실행을 검사한다. 운영 DB는 쓰지 않는다.
- 환경: 백엔드 검사에 `BIDOPS_PRESPEC_OVERVIEW_ENABLED=false`를 명시해 운영 `.env` 유입을 막고, 필요한 활성 조건은 개별 fixture에서 설정한다.
- 프런트: `web/frontend`에서 `npm run build`와 영향받는 사전규격 Playwright 의미·구조 검사를 실행한다. 화면 연결은 API 단위 검사만으로 완료 처리하지 않는다.
- 전 모듈 스위트·전체 이미지 재빌드·전 화면 재검사는 구체적인 회귀 근거가 있을 때만 확대한다. 관련 검사가 통과하면 반복 검증을 종료한다.
- 실제 명령·결과는 구현 완료 기록에 짧게 남긴다. 모델 비교처럼 별도 실행 증거가 필요한 자료만 `docs/validation-runs/`에 기록하고 미리 통과 증거를 만들지 않는다.

### 구현 검증 기록 (2026-09-21)

## 4. 품질 비교와 운영 적용

### 비교 실행 전에 고정할 것

- [ ] **sol high** — 동일 원문 표본, 문서·범위·회사/관심도 입력 버전, 현행·수정 정책과 모델 설정을 고정한다.
- [ ] **sol high** — 사람 정답과 품질 통과 기준을 정한다. 수치 기준은 아직 결정되지 않았으며 실제 비교 전에 고정해야 한다.
- [ ] **sol high** — 위험 신호가 없는 추천 결과도 포함해 탐지 누락을 확인할 수 있게 한다.
- [ ] **sol high** — 실제 모델 비교 실행의 입력·대상·범위를 준비하고 실행 직전에 사람 확인을 받는다.

개요는 동일 원문에서 현행과 수정안을 비교한다. 현행 개요는 새 예비 등급의 정답이 아니므로, 새 등급은 별도 사람 판단으로 평가한다. 잘못된 제외, 핵심 과업 해석 오류, 근거 없는 사실·회사 판단, 판단 보류 비율, 호출 수·토큰·시간을 기록한다.

### 운영 전환

- [ ] **sol high** — 측정 결과와 사람 평가로 적용 여부를 결정한다. 참조 결과나 규칙 검사 통과만으로 활성화하지 않는다.
- [ ] **sol high** — 적용 전 전체 백업·롤백 태그·migration head·정책 마운트와 버전 확인 절차를 준비한다.
- [ ] **sol high** — migration·배포·정책 적용은 각각 직전 확인 후 수행한다. 앞 단계의 확인을 다음 단계의 승인으로 간주하지 않는다.
- [ ] **sol high** — 구정책·결과를 보존하고, 롤백이나 새 정책 교체가 과거 건 자동 재평가를 촉발하지 않는지 확인한다.
