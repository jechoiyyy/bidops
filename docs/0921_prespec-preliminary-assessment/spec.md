- 상태: 제품 구현 기준 명세. 격리 검증 완료, 모델 품질 측정·운영 적용 전.
- 작성일: 2026-09-21
- 문서: [intent.md](intent.md)(목적·확정 선택) · `spec.md`(이 문서) · [plan.md](plan.md)(구현·검증 순서)

## 1. 입력과 결과

개요 run은 선택된 원문의 범위, 관심도 정책, 최소 회사 프로필, 프롬프트·모델·생성 설정을 고정한다. 회사 정보는 승인된 구조화 항목만 사용한다. 모델 호출은 기존 `overview` 용도의 통일 client와 합성 analysis worker 경계를 사용한다.

한 생성 호출에서 다음을 만든다.

| 객체 | 내용 |
|---|---|
| 사실 요약 | 사업 목적·주요 과업·예산·기간과 원문 근거 |
| 예비 판단 | 실제 계약 수행 과업·사업 유형, 세 관심 축별 관계·이유·근거 주장 ID |
| 회사 보조 근거 | 역량·실적을 판단에 사용한 경우 승인 프로필의 근거 ID |
| 확인 항목 | 핵심 과업·역할·관계 판단에 부족한 정보 |

사실과 모델 해석, 서버가 계산한 등급을 구분한다. 모델은 최종 등급 라벨을 정하지 않는다. 단순 관심 축 부합은 승인된 관심도 정책을 참조하고, 회사 역량·실적을 주장할 때는 확인된 회사 근거를 요구한다.

프로필 조회는 심층검토 정책 활성 검증과 분리한다. 프로필 미설정이면 회사 보조 근거 없이 관심도 정책으로 평가할 수 있다. 설정된 프로필의 해시 불일치·손상은 단순 정보 부족과 구분하고 해당 판단을 보류한다. 실패 사유를 보존하며 손상된 회사 정보를 모델 입력으로 사용하지 않는다.

## 2. 등급 계산

세 관심 축은 **AI/데이터·블록체인/DID·공공 SI/통합관리**이며 동등하게 취급한다. 축별 관계는 직접·부분·간접·무관·미확인으로 구조화한다. 프로필의 추정 관심 분야와 미기재 정보를 확정된 선호·비관심으로 바꾸지 않는다.

계산 순서는 **핵심 과업 확인 → 근거 유효성 확인 → 가장 강한 유효 관계 선택 → 제외 추가 검증**이다.

| 표시 | 조건 |
|---|---|
| 우선 검토 | 실제 주요 과업이 하나 이상의 관심 축에 직접 부합 |
| 검토 권장 | 직접 부합은 아니지만 구체적인 연계 과업이 존재 |
| 관찰 대상 | 주요 과업이 확인됐고 간접적인 연관만 존재 |
| 제외 | 주요 과업이 확인됐고 세 축 모두 무관하며 추가 의미검증 통과 |
| 판단 보류 | 핵심 과업·수행 역할·필수 근거가 부족하거나 검증 미해결 |

검증에 실패한 주장을 참조하는 판단은 무효화한다. 핵심 과업 근거가 탈락하면 남은 약한 근거만으로 낮은 등급을 만들지 않고 보류한다. 미확인 관계를 무관으로 바꾸지 않는다.

`판단 보류`는 다섯 번째 등급이 아니다. 등급은 `null`이고 별도 상태로 기록한다. 자격·실적 미확인만으로 등급을 낮추거나 제외하지 않는다. 제외 등급만으로 목록 숨김·추적 종료·최종 No-Go를 실행하지 않는다.

## 3. 생성과 검증 흐름

### 3.1 호출 예산

| 경로 | 최대 호출 |
|---|---:|
| 정상 통합 생성 | 1회 |
| 통합 생성 + 선택적 의미검증 | 2회 |
| 형식 오류 재시도 + 선택적 의미검증 | 3회 |

형식 오류의 생성 재시도는 1회만 허용한다. 사실·근거 오류를 수정하는 자동 재생성, 의미검증 재시도, 다른 provider로의 자동 fallback은 하지 않는다. 호출 수·토큰·지연·사유를 실제 실행에서 기록하고 사용량 미수신을 0으로 채우지 않는다.

### 3.2 독립 파싱과 결정적 검사

JSON이 유효하면 사실 요약과 판단 객체를 독립 파싱·검증한다. 판단 객체의 오류만으로 정상 개요를 버리지 않는다. 전체 JSON 손상·중복 키처럼 안전하게 분리할 수 없는 경우는 전체 형식 실패로 처리한다.

원문 인용·위치, 회사 근거의 존재·상태, 수치·단위·주체, 필수 항목, 주장 참조 관계를 검사한다. 명백한 인용·수치 불일치는 새 validator에서 해당 사실의 차단 사유로 처리한다. 추가 LLM 검증으로 결정적 실패를 통과시키지 않는다.

실패한 사실과 그 사실에 의존한 판단을 제거한다. 나머지 개요는 기존 부분 게시 기준, 즉 통과 주장이 1개 이상이며 전체의 절반 이상인 조건을 적용한다. 등급은 별도로 핵심 과업 근거가 온전한지 검사한다. 새 validator의 차단 규칙을 과거 결과에 소급 적용하지 않는다.

### 3.3 선택적 의미검증

다음 중 하나라도 해당하면 추가 의미검증을 최대 1회 수행한다.

- 서버 계산 결과가 제외 후보다.
- 수치의 주체·단위·표 관계에 모호성 코드가 발생했다.
- 계약 수행 과업과 대상 사업의 역할 구분이 불명확하다.
- 인용 문맥과 생성 문장 사이의 부정·조건 표현 차이를 규칙이 감지했다.
- 모델이 역할·문맥의 불확실성을 명시했다.

역할·문맥 탐지는 버전이 고정된 규칙과 사유 코드를 사용한다. 모델 자기신고는 보조 신호이며, 신호 없음이 의미 정확성을 보장하지 않는다. 탐지 누락도 품질 비교 대상으로 삼는다.

추가 호출은 게시 후보 개요 전체와 예비 판단을 원문 주변 문맥에 대조한다. 반환 대상 주장·판단 ID 목록을 고정하고 누락·중복을 검사한다. 등급만 검사한 결과를 개요 전체의 검증 통과로 표시하지 않는다.

### 3.4 결과·검증 상태

실행 상태, 개요 게시 상태, 등급 상태, 의미검증 상태를 분리한다.

| 구분 | 계약 |
|---|---|
| 의미검증 상태 | `not_run`, `passed`, `failed` |
| 등급 상태 | `graded`, `held`, `none` |
| 검사 범위 | 대상 주장·판단 ID와 각각의 검사 결과 |
| 실행 상태 | 대기·실행·기술 실패·취소 등을 등급이나 검증 수준과 구분 |

의미검증 미실행을 통과로 표시하지 않는다. 개요만 사용 가능하면 개요를 제공하고 등급은 보류한다. 추가 검증의 기술 실패도 이미 유효한 개요를 숨기지 않되, 필수 검증을 마치지 못한 등급은 게시하지 않는다.

기존 회사 핏·자동 심층검토 소비자는 **현재 입력에 대한 개요 전체가 종전 검증 수준을 충족한 결과만** 사용한다. 새 run의 `completed`만으로 통과시키지 않는다. 과거 검증 수준은 저장된 정책·검사 기록으로 해석하며, 불명확한 기록을 승격하지 않는다. 이 변경은 기존 검증 경계를 보존하기 위한 소비자 수정이며 새 등급에 따른 자동 실행 정책 변경이 아니다.

## 4. 대표 등급과 화면

화면 라벨은 **예비 적합성 등급**, 설명은 **개요 기준**이다. 출처·판단 시점·품질 표식을 함께 제공하고, 상세에서 핵심 이유와 원문 근거로 이동할 수 있게 한다.

대표 결과는 사람 정정 → 새 정책 판정 결과/판단 보류 → 기존 선별 등급 → 판정 없음 순으로 해석한다.

| 조건 | 표시·소비 규칙 |
|---|---|
| 사람 정정이 있음 | 기존 정정값 우선. 모델 결과와 정정의 출처·시각 구분 |
| 새 정책 판정 결과가 있음 | 최신 새 판정 표시 |
| 새 정책 판단 보류 | 과거 모델 등급으로 대체하지 않고 보류 표시 |
| 새 정책의 판정 결과가 없음 | 기존 선별 등급이 있으면 그 출처와 함께 표시 |
| 판정·정정이 모두 없음 | 판정 없음 |
| 재실행 대기·실행·기술 실패·취소 | 기존 유효 결과를 덮지 않고 최신 실행 상태를 별도 표시 |
| 문서 변경으로 기존 결과가 유효하지 않음 | 현재 등급으로 사용하지 않고 이력에서 제공 |

목록·상세·필터·건수는 동일한 서버 계산을 사용한다. 페이지 분할 전에 필터를 적용하며 결과 건수에 비례하는 추가 조회를 만들지 않는다. 브라우저에서 등급을 계산하지 않는다.

기존 사람 정정 저장과 자동 준비 hook은 유지한다. 새 화면 전용 정정 API는 만들지 않는다. 새 대표 등급이 높아도 기존 심층검토 실행 자격을 충족하지 못할 수 있으며, 제한 안내는 실제 실행 기준을 설명한다.

## 5. 저장·API·호환성

### 5.1 실행 저장과 버전

기존 개요 run에 입력 바인딩과 별도 판단 객체를 저장할 필드를 migration으로 추가한다. 사실 요약과 관심도 판단은 별도 객체로 보존한다. 원문 위치, 판단과 근거의 의존성, 확인 항목을 저장해 심층검토 재사용 기반으로 삼는다.

새 생성·결과·검증 계약과 불변 정책·validator 버전을 발행한다. 구버전 결과는 기존 reader로 읽고 새 검증 의미를 구버전 계약으로 게시하지 않는다. 과거 결과·사람 리뷰·정책 파일은 수정하지 않는다.

정책·프롬프트·프로필·모델·생성 설정의 버전과 해시를 실행별로 보존한다. 이력은 현재 설정이 아닌 해당 실행의 버전을 표시한다. 원응답은 기존 암호화 저장 경계를 사용한다.

### 5.2 공개 API와 타입

- 사전규격 목록·상세 응답에 화면용 `display_assessment`를 추가한다. 등급·상태·출처·기준 run·판단 시각·품질 표식을 제공한다.
- 개요 응답은 새 버전에서 사실 요약·예비 판단·근거·확인 항목·검증 결과를 구분해 제공한다.
- 기존 `grade`·`grade_source`와 effective grade 함수는 기존 자동화 의미를 유지한다.
- 화면용 `display_grade` 필터를 추가한다. 4단계 등급과 판단 보류·판정 없음을 구분한다.
- 기존 `grade` 필터 계약은 유지하고 새 화면은 `display_grade`를 사용한다. 구버전 화면 URL의 등급 필터는 진입 시 새 표시 필터로 정규화한다.
- 부분 결과와 검증 상태를 프런트 타입에 반영하고, 모델 원문·내부 경로·객체 자격증명은 응답에 포함하지 않는다.

소유 모듈의 batch projection과 lifecycle 확장점을 사용한다. 다른 모듈의 내부 ORM을 직접 가져오거나 프런트에서 업무 규칙을 복제하지 않는다.

## 6. 자동 촉발·재실행·재사용

자동 촉발은 **같은 공고·같은 문서에 기존 종결 결과가 있으면 정책·프로필 교체만으로 새 run을 만들지 않는다.** 판정 결과 또는 판단 보류가 남은 종결 실행을 대상으로 하며, 단순 실패·취소와 구분한다. 정책 digest만 바뀌어 과거 재관측 건이 자동 재평가되는 동작을 막는다.

새 문서와 사람이 요청한 재실행은 새 이력으로 처리한다. 과거 완료 건 일괄 재평가 기능은 추가하지 않는다.

실행 여부와 결과 재사용은 별도 규칙이다. 실행이 허용된 뒤 문서·범위·프로필·정책·프롬프트·모델·생성 설정·validator가 모두 같은 유효 결과만 재사용한다. 재사용 시 최초 결과의 출처를 보존한다. 명시적 재실행은 새 run에서 실제 평가하며 이전 결과를 덮지 않는다.

## 7. 품질과 적용 경계

참조 실행·미측정·mock·표식 없음의 구분을 목록과 상세에 유지한다. 대표 등급이 존재하거나 규칙 검증을 통과했다는 이유로 품질 통과 상태로 승격하지 않는다.

구현 완료는 이 명세와 관련 검사를 갖춘 변경이다. 실제 비교 전에 표본·사람 정답·품질 통과 기준을 고정한다. 개요는 현행과 수정안을 비교하고 새 등급은 별도 사람 정답으로 평가한다. 모델의 판단을 최종 정답으로 쓰지 않는다.

정책 활성화와 운영 적용은 별도 단계다. 실제 모델 호출·migration·배포·정책 적용은 [operations.md](../operations.md)와 루트 [AGENTS.md](../../AGENTS.md)의 단계별 확인을 따른다. 상세 검증과 종료 기준은 [plan.md](plan.md)에 둔다.
