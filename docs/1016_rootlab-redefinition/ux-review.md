## 3. 자체 평가에만 있던 것

- 브리핑 1~2위와 5~6위의 시각적 차등(순위 강조). Astra는 반대로 "첫 층을 통일하라"고 했다. 둘 다 "첫 시선에서 할 일 고르기"가 목적이므로 첫 층 통일 + 순위 배지로 절충한다.
- 절 미리보기 serif 글꼴이 제품 본문과 어긋남. 소소한 문제라 유지하되 RL-04에서 결정.

## 4. 어긋난 판단

- Astra는 Slack 반응 버튼을 "줄이기보다 예측 가능하게"라고 했고 자체 평가는 "상위 3건만 버튼"이었다. 채택: 모든 건에 채택·무시 2개로 통일(Astra), 제목이 상세 링크, 중복 "화면에서 열기" 제거.

## 5. 결정 (RL spec에 반영할 것)

1. 상태 축 세 가지를 색과 이름으로 분리한다: 사실 상태(확인됨/제안값/미확인), 요구 대조(충족/부족/미확인), 사람 결정(추적/보류/종료). `unknown`은 절대 부족으로 승격하지 않는다(hp-contract §7).
2. 모든 숫자에 분모를 붙인다(카드 48 / 영역 6 / 체크리스트 5 / 확인 업무 n). 화면마다 참조한 회사 버전·실행 id를 표시한다.
3. 조회·채택·추적 결정·자동 분석을 분리한다. 조회는 상태를 바꾸지 않고, 채택은 담당 기록이며 취소 가능, 분석은 독립 실행.
4. 브리핑·Slack 항목은 같은 4줄(제목·기관·마감 종류 / 추천 이유 1줄 / 핵심 부족·미확인 1줄 / 보조 판정)과 같은 2버튼이다. 하루 1회 본문 + 예외 알림(정정·마감 D-3·D-1)만 별도이고 분석 완료는 스레드에 기록한다.
5. 원문 쪽·회사 근거·초안 문장은 왕복 링크이며 쪽 미확인은 링크가 아니다.
6. 제안서 지표는 "초안 연결 n / 검토 완료 n / 제안 수치 n / 빈 자리 n"이며 내보낸 PDF에도 미확인·조건부 표식을 남긴다.
7. 회사 근거 화면의 첫 행동은 "지금 확인하면 판정이 바뀌는 항목"이고 버전 동결은 그 뒤다. 필드별 보유/세부값/유효기간 상태를 둔다.
8. 상태 화면 추가: 브리핑 0건(정상/실패 구분), 분석 대기·진행·부분 실패·시간 초과, 정정 후 재검토, 초안 생성 중·실패.
9. 주 버튼 대비는 테마 토큰으로 해결하며 화면 CSS에서 색을 재정의하지 않는다(ADR-0048).
10. 보류: 권한·역할 구분(현재 전원 동일 권한 전제를 명시), Go/No-Go 화면 연결(후순위 범위 유지).
