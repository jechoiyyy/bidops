# BidOps 재정의 초안 — 루트랩 기준 AX 과제

- 상태: **초안·미승인** (2026-10-16). §6 인터뷰 답을 받은 뒤 `sdlc:replan`으로 `docs/work/constitution/{mission,roadmap}.md`·큐에 반영하고 이 문서는 결정 기록으로 축약한다.
- 회사 기준: 실회사 ㈜루트랩. 근거는 [`docs/reference/company-profile.md`](../reference/company-profile.md)(2026-08 회사소개서)와 [`docs/reference/company-homepage-profile.md`](../reference/company-homepage-profile.md)(2026-10-16 홈페이지).
- 이전 방향과의 관계: C-2 발주계획 선별(운영 PoC), DEMO 가상 SI 3사(종료), HP 가상 홈페이지 1사(HP-00·01 완료, 02~06 미착수)는 기록과 코드를 보존하되 **가상회사 전제는 폐기**한다.

## 1. 왜 필요한가

사용자 진술: 나라장터 공고를 살펴보는 데 인적·시간 비용이 많이 들고, 단순 서칭에 입력이 집중된다.

루트랩 실적으로 구체화하면:

| 사실 | 함의 |
|---|---|
| 홈페이지 실적 행 63건 중 운영·유지관리 32%, 고도화 25% — 연차 반복 사업이 주력 | "아는 사업의 다음 연차"를 놓치지 않는 것이 1차 가치. 이 신호는 발주계획·반복 발주처 조회로 거의 결정적으로 잡힌다 |
| 발주처 상위 5곳이 실적의 59% | 기관 축 추천이 키워드 축보다 강할 수 있다 |
| 사업명 키워드가 블록체인·플랫폼·홈페이지·복지·재난·연구장비로 넓다 | 단일 키워드 검색으로는 모집단을 못 좁힌다. 지금 실무자는 여러 검색어를 매일 반복한다 |
| 발주계획 3일 1,200건·사전규격 일반·기술용역 매일 전량 | 사람이 전부 읽을 수 없고, 현재 C-2는 precision 36.7%라 추천의 2/3가 헛걸음 |
| 회사 프로필 미확인 항목 20개(예산·지역·컨소시엄·인력·자격) | 적합성의 "자격·수행 가능" 축을 기계가 채울 수 없는 상태 |
| 현재 제품: 발주계획 → 사전규격 → 입찰공고의 세 화면, 사람 게이트 6곳 이상, 심층 검토 100쪽 4~8시간, 알림 미구현, 제안서 미구현 | 서칭 비용을 "화면 보는 비용"으로 옮겼을 뿐 입력 총량이 크게 줄지 않았다 |

## 2. 궁극 목표 (제안)

> 루트랩이 수주할 수 있는 공고를 놓치지 않고, 실무자가 나라장터를 직접 뒤지지 않게 하며, 참여 판단과 제안서 작성의 출발점을 에이전트가 만든다.

세 단계 목표와 성공 측정:

| 단계 | 목표 | 측정 |
|---|---|---|
| G1 발견·알림 | 매일 1회 에이전트가 "볼 만한 공고 N건 + 이유"를 실무자에게 보낸다 | 실무자가 직접 검색하는 시간(기준선 → 목표), 나중에 참여한 공고 중 브리핑에 없던 건 0 |
| G2 판정 근거 | 공고 원문(요구사항 카드·자격·예산·일정)과 회사 근거를 대조해 참여 가능 여부 보조 판정과 차단 조건을 준다 | 사람 gold와 판정 일치, 차단 조건 recall (HP §9 기준 재사용) |
| G3 제안서 초안 | 요구사항별 대응 방안·유사 실적·인력 구성 초안을 만든다 | 실무자가 초안에서 출발해 작성 시간이 줄었는지, 요구사항 누락 0 |

범위 밖(유지): 자동 입찰·제출, 발주처 연락, 최종 Go/No-Go, 제안서 제출본. PRD §5.4의 "자동 입찰서 작성 제외"는 **"제출본 자동 작성 제외"로 좁히고 초안은 범위에 넣는다**(결정 필요, §6 Q4).

## 3. AX 관점 재설계 — 사람 흐름에서 무엇을 생략·전환하나

| # | 현재 사람이 하는 일 | 제안 | 이유 |
|---|---|---|---|
| A | 매일 발주계획 후보(≤80건)·사전규격 목록을 화면에서 훑는다 | **전환: pull → push.** 하루 1회 브리핑(상위 N건, 각 건 이유 3줄·차단 조건·마감). 실무자는 목록을 열지 않고 브리핑에 `볼게요/무시`로 반응 | 서칭 입력을 없애는 것이 과제의 본질. 목록 화면은 감사·탐색용으로만 남긴다 |
| B | 발주계획 전 후보에 사람 relevance 라벨 | **생략.** 브리핑 반응(채택·무시·이유)만 피드백으로 저장 | 전건 라벨은 품질 게이트용 비용이었다. 운영에서는 추천된 것에 대한 반응만으로 충분 |
| C | 사전규격 등급 입력·추적 결정 입력 | **축소.** 에이전트가 등급·추적 제안과 근거를 미리 채우고 사람은 다를 때만 고친다 | 입력 횟수를 줄이되 결정 주체는 사람 |
| D | 개요(앞부분) 검토 → 확인 → 심층 건별 승인 → 4~8시간 대기 | **통합.** 요구사항 카드 기반 1회 분석(HP-03 두 층 설계)을 상위 후보에 **자동** 실행. 건별 승인은 외부 모델 전송 정책 때문이었으므로 모델 경계를 다시 정한다(§6 Q3) | 개요/심층 두 단계는 비용 절약용 분할이었는데 카드 단위 분석이 40분 목표면 분할 이유가 약해진다 |
| E | 발주계획·사전규격·입찰공고 세 화면을 따로 본다 | **전환.** 사업기회 1건 = 타임라인 1개. 상태가 바뀔 때(사전규격 등록, 공고 게시, 정정, 마감 D-3)만 알림 | 세 단계는 나라장터 구조이지 실무자의 관심 단위가 아니다 |
| F | 회사 프로필의 미확인 20항목을 아무도 채우지 않는다 | **신설.** 회사 근거 입력·확인 절차(인터뷰 → 구조화 → 버전 고정 → 분기 갱신). 인력·자격·선호·제외를 포함 | §4의 핵심 요인 |
| G | 유사 실적을 사람이 기억으로 찾는다 | **강화.** 루트랩 실적(PDF 130 + 홈페이지 57) + 나라장터 과거 낙찰·개찰 이력(같은 기관의 전년 공고, 낙찰자, 투찰률)을 매칭 신호로 | 연차 반복 사업과 경쟁 구도를 기계가 더 잘 본다 |
| H | 가상회사 3사·1사 전환 화면 | **보류.** 회사는 루트랩 하나. 회사 경계 코드(DEMO-01)는 유지하되 전환 UI는 숨긴다 | 실회사 1곳 과제에 불필요 |
| I | 제안서를 백지에서 쓴다 | **신설.** 카드 → 대응표(요구사항·수행 방안·근거 실적·담당) → 절 초안. 과거 제안서가 있으면 문체·구성 근거로 | G3 |
| J | 입찰공고 delta·Go/No-Go | **유지, 후순위.** worker 미구현 상태 그대로 두고 G1·G2 뒤에 | 지금 비용이 가장 큰 곳이 아니다 |

유지하는 원칙: 원문 불변·계보 보존, `unknown` 보존, 모델 주장의 원문 locator 검증, 사람 최종 결정. 이것은 AX가 아니라 신뢰의 조건이다.

## 4. 가장 중요한 성공 요인 1가지

**회사 자신에 대한 근거 데이터의 정확성과 최신성** — 확인된 실적·자격·인력·가용성·선호·제외 조건.

이유:

1. 공고 쪽 데이터는 모든 경쟁사에 같다. 추천이 루트랩에 맞는지는 전적으로 회사 쪽 데이터가 정한다. 자격·인력·예산 축이 `unknown`이면 판정은 "모름"에 머물고 실무자는 다시 자기 머리로 판단한다.
2. G1·G2·G3 모두 같은 데이터를 먹는다. 추천 이유, 차단 조건, 제안서의 실적·인력 절이 전부 여기서 나온다. 하나를 고치면 셋이 좋아진다.
3. 지금 가장 비어 있는 곳이다. 프로필 미확인 20항목, 홈페이지에는 자격·인력이 없음, DEMO·HP가 가상회사로 우회한 이유도 이것이다.

이 요인이 채워졌는지는 결과로 안다: **실무자가 직접 서칭을 그만둔다.** 그러려면 "놓친 공고 0"과 "브리핑 상위 N의 채택률"이 신뢰 임계값을 넘어야 하고, 그 둘은 회사 데이터 없이는 올라가지 않는다.
