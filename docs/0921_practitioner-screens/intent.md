## 1. 무엇을 하려는가

관리 화면의 사용자는 발주계획·사전규격·입찰공고를 보고 추적 여부와 Go/No-Go를 정하는 기획·사업개발 실무자다.
대시보드도 운영자가 아니라 **실무자가 하루를 시작하는 화면**이다. 이 작업은 두 원칙을 화면 전체에 적용한다.

1. **같은 기능은 같은 UI로 그린다.**
2. **실무 화면에는 공고를 판단·결정하는 데 필요한 정보만 남긴다.** 서비스 운영 정보는 `실행 상태`·`판정 기준` 화면이나 로그에서 본다.

그리고 점검에서 드러난 **실무자에게 필요한데 화면에 없는 정보**를 채운다.

## 2. 확인된 문제

### 2.1 같은 기능, 다른 UI

- 회차 선택기 구현이 6벌이다. 발주계획(`OrderPlansPage.tsx`, `ReviewFilterSelector`)과 사전규격(`PreSpecsPage.tsx`, Astryx `Selector` 직접)은 URL 파라미터(`source_run_id`)·라벨(`수집 회차`)이 같은데 검색 유무, 누적 옵션 문구(`누적 · 회차 선택 안 함` / `모든 수집 회차`), 옵션 포맷, 오류 처리(배너 / 없음), CSS가 모두 다르다. 2026-09-20 통일(ADR-0062)은 위치만 맞췄다.
- 페이지네이션 3종(`ListPager`는 자리만 갖고 단추는 화면별), 빈 상태 마크업 복제(사업 추적·Go/No-Go가 `common/EmptyState`를 우회), "예산 없음" 문구 5종, 날짜 포맷 함수 중복 7곳, 목록 범위 설명 단추 이름 4종(`실행 상태`/`표시 범위`/`데이터 현황`/`이 목록이 무엇을 세는가`), 목록 건수 캡션 4종.
- 사업 추적·최종 Go/No-Go는 `SplitWorkspace`를 쓰지 않는 자체 골격이다. `tests/explore-workspace-consistency.spec.ts`도 "아직 통일하지 않은 화면"으로 비워 두었다.

### 2.2 실무 화면의 운영 정보 (약 40곳)

- 발주계획: 행의 `판정 policy c2-…-v4`, `BM25 …`·`Qwen …` 배지, `예산 null (미제공)`, 영문 enum이 그대로인 상세 필터와 사람 판단 수정 폼, 다이얼로그의 execution_id·policy/binding sha·토큰·`duration_ms`·artifact sha256, 배너의 digest·컨테이너·환경 설정.
- 사전규격 상세: 회사 적합성 실행 정보(모델·프롬프트·sha·토큰·ms), 주장 ID, 제목 `현재 v4 개요 실행`, 같은 경계 문장 4회 반복.
- 심층 검토·Go/No-Go·입찰 변경 비교: `안전한 오류 코드`, uuid·SHA-256·block_key·bbox, 영문 enum 병기, `InputRefFacts` 13줄.
- 셸: `판정 기준` 팝오버의 run_id, 사이드바 `관리자 화면`, 폼 오류의 `· 오류 코드`.
- `lib/glossary.ts`는 이미 "목록·필터는 한글 라벨, 계약 토큰은 상세의 기술 정보에서만"이라고 선언했다. 위는 자기 규칙 위반이다.
- 발주계획 선별(C-2) 실행 기록은 옮겨 담을 운영 화면이 아직 없다. `/runs`는 공고 판정(C-1) 실행만 읽는다.

### 2.3 빠진 실무 정보

- 발주계획 상세 API(`api.getOrderPlan`, `screening-history`)는 선언만 있고 호출부가 없다 — 신규/계속, 회차별 판정 변화, 사업기회 링크가 화면에 없다.
- 수요기관(`notice.demand_agency`)은 DB·적재·색인까지 있는데 어떤 응답에도 없다. 조달청 대행 사전규격은 목록에 대행기관만 보인다.
- 발주계획의 계약방법·공고 게시 여부·연결 공고번호, Go/No-Go 대기열과 사업 추적 목록의 마감·예산이 응답에 없다.
- 사전규격 검토 제외의 사유·작성자·시각, 입찰공고의 개찰일시·유사 실적 매칭은 응답에 있는데 그리지 않는다.
- 대시보드는 누적 업무 바로가기 4개와 보류 패널 아래 패널 4개가 회차를 골라야 나오고, 그중 `검증 상태`·`회차 요약`은 운영 지표다. 누적 기준의 마감 임박·결정 대기·사람 확인 목록이 없다.
- **정확성 결함(리뷰 발견)**: `NoticeFacts.tsx`가 지역 제한 근거가 비면 `지역 제한 없음`을 출력한다. 수집기는 "빈 근거는 제한 없음의 증거가 아니다"라고 명시한다 — null을 자격 확인 완료로 바꾸는 표시다.

## 4. 범위 밖 (findings에 인계)

- **수집 확장**: 자격등록 마감·공동수급협정 마감·설명회·입찰 개시·낙찰하한율·사전규격 납품기한. 판정 입력 계약의 닫힌 검증기 전체(수집기 → `ingest/contracts.py` → `loader.py:669-725` → `orchestrator.py:1278,1341` → `build_screening_results.py:583` → `loader.py:2934-2946,3052-3082`)를 함께 열어야 하고, 미수집/원문 빈 값/해석 실패/정상 4상태 계약을 먼저 설계해야 한다. 과거 회차는 소급하지 않고 `미수집`으로 보인다.
- **단계 지연(재확인 알림)**: 발주 예정월+2개월 / 사전규격 등록 후 45일. 임계값의 경험적 근거가 없어 "지연"보다 "재확인 알림"이 맞고, 후속 단계 연결 시 해제·월 경계 정의가 필요하다. 효과는 ⓐ 배지 전용 ⓑ `action_reasons` 추가(분류식에 의해 `조치 필요` 구역으로 올라감, `hold_overdue`가 선례) 중 그 작업에서 정한다.
- `budget` 출처 구분 컬럼, 발주계획 규격 내용·수행 지역, 사내 담당자 배정·메모, 입찰 delta 계산 worker.

## 5. 독립 리뷰가 바꾼 것

| 지적(코드로 확인됨) | 반영 |
|---|---|
| `latestCompletedExecution`은 성공·부분 성공만 골라 "과거 성공 + 이후 실패"를 문제없음으로 본다. "문제 있을 때만" 칩을 띄우면 실패를 숨긴다 | 칩 조건을 "최근 실행의 건강 상태"로 먼저 고친다(spec §3.1) |
| `daily-trigger` 응답에 오늘 실행 여부가 없다 | 배너는 "자동 선별이 꺼져 있습니다"까지만 말한다 |
| `budget`은 `asignBdgtAmt→presmptPrce→bsisAmount` fallback | '배정예산'이라 부르지 않는다(spec §6.3) |
| `screening_history`는 운영·측정·참조 실행을 구분하지 않는다 | 이력 항목에 `purpose`·실행 시각 추가(spec §5) |
| 입찰공고는 `agency`가 이미 수요기관, `demand_agency`는 항상 null | 입찰공고 투영 삭제, 사전규격 검색에 수요기관 추가 |
| 회차 변경의 URL 의미가 두 화면에서 다르다 | 공용 컴포넌트는 표시만, URL 정책은 페이지 소유(spec §2.1) |
| 개정할 정본 누락 | `glossary.ts:14`, ADR-0064 결정 7 개정 추가 |
| `WorkloadProjection`은 건수만 준다 | 대시보드 패널의 목록 계약을 먼저 닫는다(spec §7) |
| 버전 올림은 프런트 타입·mock까지 한 단위 | 패키지 B1이 함께 소유(plan §1) |
