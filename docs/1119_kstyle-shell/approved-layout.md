2026-11-21 사용자가 테일넷 전체 시안을 승인하고 React 운영 웹 구현을 요청했다. 기준은 [전체 시안](https://42-ax.tail0ab8c5.ts.net:8191/?page=dashboard)과 [사전규격 분할 시안](https://42-ax.tail0ab8c5.ts.net:8191/?layout=split)이다. 시안의 값과 저장 동작은 예시다. 제품 화면의 수집·개요·추적·최종 결정은 기존 REST 응답과 담당자 기록을 사용한다.

> **2026-11-23 개정.** 분할 비율(목록 60% \| 미리보기 40%), 목록 행(열이 있는 표), 판정 기준·실행 상태의 탭(왼쪽 구역 메뉴), 읽기 화면의 오른쪽 정보 열은 [ADR-0077](../tracking/decisions/0077-table-workbench-layout.md)이 대체한다. 아래 표의 "분할 검토"·"목록 밀도" 행과 "판정 기준과 실행 상태는 기존 탭" 문장은 2026-11-21 시점의 기록이다. 셸·위치 줄·도구줄·읽기 폭은 그대로다.

- 대시보드는 업무량과 최근 수집·업무를 보여 주며 각 업무로 이동한다. 브리핑은 반응 보기와 추천 미리보기를 조합한다.
- 발주계획·사전규격·사업기회·최종 Go/No-Go는 목록과 오른쪽 검토 영역을 사용한다. 선택·일괄 처리·키보드 순회·보류·종료와 상태 구분을 유지한다.
- 회사 근거는 확인 필요·자격·실적·인력·선호를 제공한다. 판정 기준과 실행 상태는 기존 탭과 각 탭의 목록·상세를 공통 셸에 배치한다.
- 사전규격 상세는 목록으로 돌아가는 링크와 하단 추적 시작을 갖는다. 사업기회 상세는 관련 기록과 입찰공고로 이어지고, 입찰 변경 비교에서는 조건·문서 비교와 사람의 최종 결정을 확인한다.
- 발주계획과 사전규격의 단건 `미선택 → 계속 추적`은 담당자 이름이 있으면 한 번에 기록한다. 사유는 `null`로 저장한다. 서버는 잠금 후 현재 상태를 재확인하며, 이미 결정된 건의 기존 값은 보존한다. 일괄 시작·보류·종료·되돌리기와 최종 결정은 각자 사유와 확인 절차를 따른다. [생애주기 REST 계약](../contracts/lifecycle-rest.md)

## 공통 선택 도구

발주계획과 사전규격에서 목록 제목 아래, 열 이름 위에 공통 도구줄을 둔다. 선택 건수, 현재 페이지 전체 선택, 선택 전체 해제, 일괄 추적 시작을 같은 순서와 이름으로 제공한다. 발주계획의 일괄 추적 종료와 사전규격의 검토 제외·선택 순회도 각각 이 줄에서 실행한다. 행 활성 상태와 체크 집합은 별도다. 기존 필터 초기화, 페이지 간 선택 유지, 감사 사유와 확인 절차를 따른다.

## 인수 기준

1280×800, 1440×900, 1920×1080에서 같은 목록·선택 건으로 위치 줄, 탭과 검색, 분할선, 긴 제목, 본문 읽기 폭과 하단 결정 버튼을 확인한다. 행 선택과 키보드 이동, 상세 열기·복귀, 필터·회차 변경, 추적 시작 성공·실패·기존 결정 충돌을 확인한다. 제품 빌드와 격리 데이터로 확인한 결과를 운영 배포 기록과 구분한다. 예시 데이터로 [구현 화면 미리보기](https://42-ax.tail0ab8c5.ts.net:8192/)를 열 수 있다.

## 운영 반영

이 변경은 프론트엔드 번들과 추적 상태 API를 같은 이미지에 넣는다. 기존 DB의 추적 사유 열은 이미 nullable이므로 스키마 migration은 없다. [운영 호스트 절차](../operations/host.md)와 [백업 절차](../operations/backup-restore.md)에 따라 운영 변경 직전 확인을 받은 뒤 새 이미지와 이전 이미지 롤백 태그를 준비한다. 배포 직후에는 운영 웹 상태와 사전규격·발주계획 읽기 화면을 확인한다. 테스트 데이터로 추적 저장과 충돌을 검증한 결과는 실제 운영 사업기회를 변경한 증거와 구분한다.
