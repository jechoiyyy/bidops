## 남은 작업

이번 설계는 판정 에이전트 런타임, 정기 실행, 모델 품질 게이트의 문서 설계를 확정했다. 설계 확정은 구현 완료를 뜻하지 않으며, 아래 목록에서 이번 설계의 구현 대상과 기존 미완료 작업을 구분해 진행한다.

우선순위는 앞 항목의 출력이 뒤 항목의 입력이 되는 순서다.

1. 사용자 편집 가능한 선정·분석 정책 저장소와 관리 화면을 구현한다. 저장 시 불변 정책 버전을 만들고 이후 회차에만 적용하며 회차에 사용 버전을 기록한다.
2. 이름 입력 기반 작성자 식별과 감사 이벤트 모델을 구현한다. 조회는 이름 없이 허용하되 리뷰·정책 승인·외부 전송 승인은 이름을 요구한다.
3. 첨부 문서 집합과 작업 상태 모델을 추가한다. 원본 해시, 획득 출처, 변환기 버전, HWPX 정본, 실패/사람확인 상태를 보존한다.
4. 헤드리스 HWP→HWPX 자동 변환기를 연결하고 대표 문서를 한컴 변환 결과와 회귀 비교한다. 직접 HWP 파서를 운영 경로에 넣지 않는다.
5. HWPX 문단·표·요구사항 ID·원문 위치 구조화기와 결정적 문서 검증기를 구현한다. 소방예방정보시스템 사례의 유일 요구사항 55개를 회귀 기준으로 사용한다.
6. [이번 설계 구현 대상] `qwen3.8:27b`를 이용한 1차 다섯 관점 판정을 판정 에이전트 런타임과 애플리케이션 워크플로에 연결한다. 단계별 JSON, 타임아웃, 잘린 출력, 스키마 실패를 사람 검토로 라우팅한다.
7. 1차 판정 품질, 심층 리포트 품질, 실제 사업 결과, UX 피드백을 수집하고 모델 품질 게이트와 정책 변경 제안으로 연결한다. 등급 재현성 등 미측정 항목은 통과로 취급하지 않으며, 제안은 사람 승인 후 새 정책 버전으로만 활성화한다.
8. `우선 검토` 공고의 첨부 확보 후 심층 분석 오케스트레이터를 구현한다. 자격, 요구사항, 평가, 위험을 단계별로 실행하고 원문 인용·산술·ID를 검증한다.
9. 심층 리포트 검토·수정 UI와 구조화 결과 내보내기를 구현한다. 자동 권고와 담당자의 최종 결정을 분리해 표시한다.
10. OpenAI 보조 경로를 기본 비활성으로 구현한다. 공고/회차별 전송 미리보기·승인·최소 데이터·감사 기록이 갖춰지기 전에는 API 호출을 추가하지 않는다.
11. [이번 설계 구현 대상] 전체 리뷰 로그 화면과 운영 백업·복구 자동화를 완성하고, 정기 수집과 실패·부분 성공의 관리 화면 표시를 스케줄링 설계에 따라 구현한다. 메일·메신저 등 외부 알림은 만들지 않으며, 품질 게이트와 담당자의 명시적 활성화 전에는 정기 실행을 상시 운영 스위치로 켜지 않는다.

## 차단·외부 의존 사항

- 사전규격 API의 운영 이용 승인이 없으면 사전규격 실전 수집 범위가 제한된다.
- 운영용 HWP 변환기 패키지와 격리 방식은 후보 구현을 대표 문서로 비교한 뒤 확정해야 한다.
- OpenAI 보조 경로는 조직의 외부 데이터 전송 허용 범위와 키 관리 주체가 정해지기 전까지 운영 활성화할 수 없다.
- 백업 주기·보관 위치·복구 책임자는 사내 배포 환경이 정해져야 확정할 수 있다.
