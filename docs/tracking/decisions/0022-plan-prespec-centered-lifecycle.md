# 발주계획과 사전규격을 중심으로 기회 생애주기를 구성

- 상태: 채택
- 일자: 2026-08-27

## 맥락

입찰공고가 올라온 뒤에만 심층 검토하면 준비 시간이 짧다. 발주계획은 사업 제목과 예상 정보를 일찍 제공하지만 제안요청서가 없어 상세 적합성을 확정하기 어렵다. 사전규격에는 제안요청서가 공개되어 심층 검토를 시작할 수 있지만 모든 사전규격이 선택된 발주계획과 공식 연결되는 것은 아니다.

완전 자동으로 끝까지 실행하면 사람이 검토할 지점이 사라지고 불필요한 첨부 분석 비용이 발생한다. 반대로 각 단계를 별도 도구로만 만들면 relation, 재시도, 감사, 화면 상태가 중복된다.

## 결정

제품 흐름은 다음과 같이 구성한다.

1. 발주계획을 매일 독립 수집하고 월요일·목요일에 사람이 조기 관심도를 검토한다.
2. 사전규격을 발주계획 선택 여부와 무관하게 매일 독립 수집한다.
3. 사전규격 RFP에는 저비용 1차선별을 적용하고 사람이 심층 검토 실행 여부를 승인한다.
4. 심층 보고서 뒤 사람은 `계속 추적|보류|종료`를 선택한다. 이는 최종 입찰 판단이 아니라 추적 범위 승인이다.
5. `계속 추적` 기회에서 입찰공고와 정정을 감시한다. 사전규격 대비 material delta가 있으면 새 심층 검토를 만들고 사람이 최종 `Go/No-Go`를 결정한다.

발주계획, 사전규격, 입찰공고는 내부 opportunity ID로 묶는다. 공식 통합번호 관계만 자동 확정하고 제목·기관·예산·시기의 유사도 관계는 사람 확인 대기 후보로 남긴다.

각 단계는 자동으로 다음 단계에 연결할 수 있고 수동으로 단독 실행·재시도할 수도 있다. 두 방식은 별도 구현을 만들지 않고 같은 execution, attempt, immutable artifact, idempotency, 상태 전이를 공유한다.

## 대안

발주계획에서 선택된 건만 사전규격을 추적하면 공식 연결이 없거나 계획이 선행하지 않은 사전규격을 놓칠 수 있어 기각했다.

사전규격 1차선별 직후 심층 검토와 입찰 추적을 모두 자동 실행하면 첨부 분석 비용과 잘못된 추적이 누적되고 사람 결정 경계가 사라져 기각했다.

입찰공고 중심을 유지하면 제안요청서를 분석할 수는 있지만 사전규격 공개 기간의 준비 기회를 잃어 조기 탐지 목표에 맞지 않아 기각했다.

연결형 workflow와 단계별 실행을 서로 다른 기능으로 구현하면 상태와 artifact 계약이 갈라져 기각했다.

## 결과

새 DB와 API에는 전체 발주계획, 독립 사전규격, opportunity relation과 후보 relation, 사람의 선별·추적·최종 결정, bid delta를 구분해 저장해야 한다. 매일 수집과 월·목 사람 검토를 별도 일정으로 운영한다. 문서 준비와 실패 재시작 화면도 동일한 stage 경계 위에서 제공해야 한다. 시스템은 알림과 대시보드로 결정을 보조하지만 입찰 제출이나 발주처 연락을 실행하지 않는다.
