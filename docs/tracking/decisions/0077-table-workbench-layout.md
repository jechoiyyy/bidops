# 관리 화면의 목록·관리·상세를 표 작업대 배치와 공용 틀로 맞춘다

- 상태: 채택 — 2026-11-23 사용자 결정("전체 시안 1로 정할게", "시안 1을 기준으로 진행하자"). 구현은 2026-11-23~24 main 작업 트리에서 단계별로 진행했다([수정안과 진행 기록](../../specs/1123_astryx-templates/plan.md)). main `1d85c1b`에 커밋했고 2026-11-24 운영 web에 프런트엔드 번들만 배포했다(기록(`docs/validation-runs/20261124-table-workbench-frontend/README.md`, git 이력)). 화면 배치 결정이며 품질·운영 활성화 근거가 아니다.
- 일자: 2026-11-23
- 근거: [Astryx 적용 시안](../../specs/1123_astryx-templates/README.md)의 시안 1 기준(`web/frontend/design/astryx-templates/`, `variant "a"`·`mode "base"`), 운영 웹 29개 주소 검토 결과
- 관련: ADR-0040(레이아웃은 프로젝트 소유)·ADR-0047(데스크톱 1280~1920)·ADR-0048(테마 정본)·ADR-0076(바탕 위 흰 패널 셸 — 이 ADR이 결정 6·7·13의 일부를 대체)·[`approved-layout.md`](../../specs/1119_kstyle-shell/approved-layout.md)(2026-11-21 적용 기준 — 분할 비율·행 모양·관리 화면 탭을 이 ADR이 대체)

## 맥락

2026-11-23 운영 웹을 검토하니 화면은 다섯 유형(목록|미리보기, 관리 목록|상세, 읽기 상세, 최종 결정, 요약)으로 묶이는데 같은 유형 안에서 같은 기능이 다르게 그려지고 있었다. 목록 4화면은 행 구현이 둘(Astryx `List` 기반 2줄 행, `Table` + 첫 열 버튼)이고 결정 영역 배치가 넷이었다. 관리 2화면은 안쪽 여백 배치와 2~3단 탭을 따로 썼고, 입찰공고 상세는 옛 양식이었다. 상태 표식·마감 표기·사실 표시·단계 표시도 화면마다 달랐다.

시안 넷(배치 유지안, 표 작업대, 묶음 검토, 읽기 집중)과 표 작업대 위의 보기 방안 셋(크게 보기, 훑기 길잡이, 내 화면 맞춤)을 실제 Astryx 컴포넌트로 만들어 비교했고, 사용자가 표 작업대 기준안을 골랐다. 색·글꼴·셸은 바꾸지 않는다.

## 결정

1. **공용 층 하나.** 화면은 공용 틀에 내용만 넘긴다. 새 층을 나란히 만들지 않고 기존 `components/common`을 바꾼다: `RecordTable`(목록), `SplitWorkspace`(목록|미리보기 틀), `DecisionBar`(결정 띠), `Marks`(`StatusMark`·`ClassTag`·`DeadlineText`), 세로 사실 목록(`Facts`), `FlowSteps`(단계), `SectionNav`(구역 메뉴), `RecordFrame`(읽기 상세), 배치 규칙은 `styles/workbench.css`. 같은 기능의 모양을 화면 CSS에서 다시 정하지 않는다.
2. **목록은 열이 있는 표다.** 발주계획·사전규격·사업기회·최종 Go/No-Go·관리 화면의 목록은 Astryx `Table` 조합 방식의 `RecordTable` 하나로 그린다. 사업명 열이 남는 폭을 먼저 갖고(280px쯤까지), 그다음 발주기관 열이 120~200px로 늘어난다. 값 칸은 14px 본문 먹색이고 줄바꿈하지 않으며, 12px 보조 회색은 보조 줄에만 쓴다. 긴 사업명은 한 줄로 자르고 전체를 `title`로 준다.
3. **행이 키보드 계약을 진다.** 행 `<tr>`이 `useRowKeyboardNavigation`의 `rowProps`와 `aria-current`를 직접 받는다. 사업기회·최종 Go/No-Go의 "첫 열 버튼" 방식은 없앤다. active 행과 checked 집합의 분리, plain Space 토글, ↑↓와 페이지 경계 쪽 넘김, 화면별 `Ctrl/Cmd+Enter`는 그대로다.
4. **목록 60% | 미리보기 40%.** ADR-0076·`AGENTS.md`의 38%와 `approved-layout.md`의 56%를 대체한다. 관리 화면은 구역 메뉴(200px)를 뺀 폭에서 같은 비율이다.
5. **선택 행은 브랜드 옅은 채움 + 왼쪽 2px 브랜드 선이다.** ADR-0076 결정 7의 "선택 행은 fill"을 대체한다(실제 CSS는 2026-11-23부터 이미 이 모양이었다).
6. **결정 띠.** 미리보기·상세의 바닥은 `DecisionBar` 하나다: 왼쪽에 현재 상태(라벨 + 표식 + 보조 문구, 담당자 이름 안내), 오른쪽에 보조 행동들과 주 행동 1개. 화면의 주 버튼은 결정 행동 하나다(사전규격 목록의 `상세 페이지 열기`는 보조). 셸 하단 슬롯(`PageFooterBar`)은 여전히 추적 결정 전용이고, 미리보기 칸 안의 결정 띠는 별개 부품이다.
7. **관리 화면은 구역 메뉴다.** 판정 기준과 실행 상태의 2~3단 탭을 본문 왼쪽 `SectionNav`로 합친다. 열한 주소는 각 구역을 직접 연다. `approved-layout.md`의 "기존 탭" 문장을 대체한다. 회사 근거(`CompanyWikiPage`)는 자체 명세가 있어 이 결정에서 뺀다.
8. **읽기 상세는 본문 + 오른쪽 정보 열이다.** 사전규격 상세·사업기회 레코드·입찰공고 상세가 `RecordFrame`을 쓴다. 사업기회 레코드의 정보 열은 왼쪽에서 오른쪽으로 옮기고, 추적 상태 변경은 하단 결정 띠로 옮긴다. 읽기 폭 규칙(1040px, 1680px 이상 1200px)은 그대로다.
9. **상태·단계의 표기.** 상태는 채움 표식(`StatusMark`)이고 색은 표시 문구가 아니라 상태 값에서 정한다. `참조 실행 · 품질 미측정`·`표식 없음`·`판정 실행 없음`·`미확인`에는 성공·실패 색을 쓰지 않는다. 단계는 `FlowSteps`로 그리되, 현재 단계 앞에 미확인 단계가 있으면 완료 체크로 그리지 않는다(Astryx `Stepper`는 앞 단계를 모두 완료로 그리므로 단계마다 표시를 직접 넣는다).
10. **사전규격 목록의 밀도 선택을 없앤다.** 표는 한 가지 밀도다.

## 그대로 둔 것

색·글꼴·셸(사이드바, 흰 패널, 위치 줄), 백엔드와 REST 계약, 주소와 질의 이름, 페이지 크기, `sessionStorage` key, 추적 선택·최종 Go/No-Go의 사람 결정 경계, 값 없음·미확인·계산 불가·0의 구분, 모든 대화상자와 로딩·오류 상태, 입찰 참여 결정의 담당자 이름 입력.

## 결과와 한계

- 1280px에서 표의 사업명 열은 180~200px(한글 12~14자)이다. 긴 사업명은 잘리고 전체는 `title`과 미리보기에서 읽는다. 시안 검토에서 본 보완 방안(사업명 두 줄, 훑기 길잡이, 보기 설정)은 이번에 넣지 않았다.
- 화면 검사는 구조가 바뀐 단언을 새 구조에 맞췄고 동작 단언은 유지했다. 단계별 감독 실행 결과는 수정안 §9에 있다.
- 2026-11-23 구현 시작 시점의 전체 화면 검사는 80건이 실패하고 있었다(2026-11-21~23 화면 변경을 검사가 따라오지 못함). 단계 0에서 건마다 낡은 단언과 제품 결함을 갈라 정리했다.
