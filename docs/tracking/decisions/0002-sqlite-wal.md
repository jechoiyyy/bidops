# 운영 저장소로 SQLite WAL 사용

- 상태: 대체됨
- 일자: 2026-08-24

## 맥락

주간 수천 건 규모이며 초기 사용자는 소수다. 별도 DB 서버는 사내 단일 배포의 운영 부담을 키우지만 리뷰·이력·첨부 메타데이터에는 관계형 정본이 필요하다.

## 결정

당시에는 `web/data/bidops.db`의 SQLite를 WAL 모드로 사용하고 SQLAlchemy를 저장 계층으로 두기로 했다.

## 대안

PostgreSQL은 동시성과 중앙 운영에 유리하지만 현재 규모에서 별도 서버·계정·백업 운영 비용이 더 커 기각했다. 파일 산출물만 유지하면 리뷰 동시 수정과 이력 질의를 안정적으로 제공할 수 없어 기각했다.

## 결과

심층 검토의 다중 worker, 객체 버전, 중앙 감사 요구가 생기면서 이 결정의 전제가 사라졌다. 현재 운영 정본은 PostgreSQL 17과 versioned MinIO이며 SQLite는 격리 테스트와 일회성 이전 입력에만 사용한다.
