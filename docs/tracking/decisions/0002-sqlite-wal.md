# 운영 저장소로 SQLite WAL 사용

- 상태: 채택
- 일자: 2026-08-24

## 맥락

주간 수천 건 규모이며 초기 사용자는 소수다. 별도 DB 서버는 사내 단일 배포의 운영 부담을 키우지만 리뷰·이력·첨부 메타데이터에는 관계형 정본이 필요하다.

## 결정

`web/data/bidops.db`의 SQLite를 WAL 모드로 사용하고 SQLAlchemy를 저장 계층으로 둔다.

## 대안

PostgreSQL은 동시성과 중앙 운영에 유리하지만 현재 규모에서 별도 서버·계정·백업 운영 비용이 더 커 기각했다. 파일 산출물만 유지하면 리뷰 동시 수정과 이력 질의를 안정적으로 제공할 수 없어 기각했다.

## 결과

단일 호스트 중심 운영과 정기 파일 백업이 전제가 된다. 높은 동시 쓰기나 다중 인스턴스 운영은 현재 구조로 보장할 수 없으며, 그 요구가 생기면 DB 이전 결정을 다시 내려야 한다.
