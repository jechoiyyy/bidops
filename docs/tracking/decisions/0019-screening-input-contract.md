# 판정 대상은 새 입력 계약으로 정의하고 병합기 수용 버전만 넓힌다

- 상태: 채택
- 일자: 2026-08-25

## 맥락

정기 실행에서는 규칙 필터를 통과한 후보를 전량 판정해야 한다. 기존 `select_validation_sample.py`와 `bidops.validation-set.v2`는 품질 게이트용 감사 표본이라는 기준선이므로, 전량 판정 대상과 표본 선정 산출물을 같은 계약으로 취급할 수 없다. 기존 병합기는 새 판정 입력을 수용하되 판정 내용을 검사하는 규칙을 계속 적용해야 한다.

## 결정

판정 대상 목록은 새 계약 `bidops.screening-input.v1`로 정의하고 파일 산출물로 남긴다. 기존 `select_validation_sample.py`와 `bidops.validation-set.v2`는 품질 게이트용 감사 표본 전용으로 유지한다. `build_screening_results.py`는 새 입력을 수용하도록 스키마 버전의 허용 범위만 넓히며, 다섯 관점·근거·반론·확인 항목 등의 판정 검사 규칙은 변경하지 않는다.

## 대안

기존 표본 스크립트에 전량 모드를 추가하는 방법은 품질 게이트용 표본 선정과 정기 판정 대상 생성을 한 스크립트에 섞어 기존 기준선의 역할을 바꾸므로 기각했다.

판정 대상을 파일로 남기지 않고 응용프로그램 안에서만 구성하는 방법은 입력 스냅샷을 재현·감사하고 실패 후 같은 대상을 다시 처리할 수 있는 계약을 남기지 못하므로 기각했다.

병합기에 어댑터를 덧대는 방법은 별도의 변환 경계와 중복된 매핑·검증을 추가해 입력 계약의 추적 경로를 복잡하게 만들므로 기각했다.

병합기를 새로 쓰는 방법은 기존 병합 동작과 산출물 기준선을 불필요하게 교체하고 회귀 범위를 넓히므로 기각했다.

## 결과

이번 결정은 결정 0001의 기존 스크립트를 기준선으로 유지한다는 원칙에 대한 명시적 예외다. 예외는 `build_screening_results.py`가 `bidops.screening-input.v1`을 포함하도록 수용 스키마 버전의 범위를 넓히는 데만 한정한다. 다섯 관점·근거·반론·확인 항목과 같은 판정 내용을 검사하는 규칙은 바꾸지 않으며, 검증 실패 결과를 자동 보정하거나 기존 표본 계약의 의미를 소급 변경하지 않는다.
