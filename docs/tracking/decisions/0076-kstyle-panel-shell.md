# 관리 화면 셸을 바탕 위 흰 패널 한 장과 패널 헤더로 바꾸고 중립색을 따뜻한 회색으로 개정한다

- 상태: 채택 — 2026-11-19 사용자 승인("전부 승인, 권장안대로 진행"). 구현은 worktree에 미커밋으로 있고
  pixel 기준선(linux)은 갱신하지 않았다. 품질·운영 활성화 근거가 아니다.
- 일자: 2026-11-19
- 근거: 사용자 승인 최종 시안 4장 [`docs/1119_kstyle-shell/mockups/`](../../1119_kstyle-shell/mockups/)
  (`FinalBriefing`·`FinalOrderPlans`·`FinalOrderPlansDone`·`FinalOpportunity`, 인라인 style이 수치 정본)
- 관련: ADR-0040(레이아웃은 프로젝트 소유)·ADR-0047(데스크톱 1280~1920)·ADR-0048(테마 정본, 이 ADR이
  라이트 중립색을 개정)·ADR-0073(RL 시안 v26 테마 개정)·ADR-0062(목록 글자 ⓒ를 발주계획에서 바꿈)·
  [ui-spec §1~§4](../../1016_rootlab-redefinition/ui-spec.md)

## 맥락

2026-10-16 v26 셸은 회색 사이드바 240px + 흰 상단바 44px + 흰 본문이었고 본문 13~14px의 조밀한 표
중심이었다. 최종 시안은 같은 메뉴 묶음을 유지하면서 (1) 셸을 따뜻한 회색 바탕 위의 흰 패널 한 장으로,
(2) 화면 제목을 문장형 `<h1>`과 한 줄 설명으로, (3) 본문 16px·주 버튼 56px의 큰 조작부로 바꾼다.
테마 색은 `bidopsTheme.ts`가 정본이므로 중립색 변경은 테마 개정이다.

## 결정

1. **셸.** 바탕 `#EEEDEB`(`--bo-frame`) 위에 228px 사이드바가 면 없이 놓이고, 본문은 바깥 여백 8px(왼쪽 0)·
   1px `#E4E3E0` 테두리·radius 12의 흰 패널 하나다. 별도 상단바는 없다.
2. **사이드바.** 묶음·항목·순서·건수 출처는 2026-11-18 개정 그대로. 행 36px·글자 14px/500·아이콘 16px,
   비활성은 보조 글자색, 활성은 `#E0DFDC` 채움 + 700 + 먹색 알약 건수. 건수 0은 그리지 않고 건수를 불러오지
   못하면 `–`(0과 다른 모양)다. `리스트` 묶음은 색 점·아이콘 없이 36px 들여쓴다. 맨 아래 담당자 칸은 브라우저에
   기억된 담당자 이름(`bidops.actorName`, 감사 표식이며 인증이 아님)을 보이고 고친다 — 브리핑·발주계획의 담당자도
   이 한 값을 쓴다.
3. **패널 헤더(모든 화면, 셸 소유).** 화면 이름 14px/600 + 문장형 `<h1>` 26px/700 + 설명 15px / 오른쪽 액션
   (`#page-header-actions`) / 둥근 칸 탭 40px·radius 8·선택 `#E0DFDC` 채움(`#page-header-tabs`) / 아래 1px 경계.
   `<h1>`은 셸이 쥐고 화면은 문자열만 올린다(`usePageHeader`) — 올리기 전(로딩·오류)에는 route 이름이 `<h1>`이다.
   상세 화면은 `‹ 목록` 돌아갈 링크(`nav[aria-label="현재 위치"]`) + 제목 배치이며 옛 경로(breadcrumb) 배치는 없앤다.
   문장의 숫자는 화면이 이미 받은 값(목록 total·탭 건수)으로만 만든다.
4. **중립색 개정(테마).** 본문 `#1B1B1A`, 보조 `#5E5D5A`, 경계 `#E4E3E0`, muted(선택 행·강조 블록) `#F6F5F3`,
   inverted `#1B1B1A`, 아이콘 보조 `#5E5D5A`, 입력 테두리 `#C9C7C2`, skeleton `#EFEEEC`. purple 계열을 시안의
   정보색(`#F2EFFF`/`#5A3EE6`, 5.68:1)으로 바꿔 모델 판단 표식에 쓴다. `--shadow-low` 라이트 값은 그림자 대신
   옅은 선 한 줄(`#EFEEEC`)이다 — 흰 패널 안의 상자는 뜨지 않는다. 프로젝트 토큰 `--bo-frame`·`--bo-sidebar-active`·
   `--bo-line-soft`·`--bo-panel-radius`. 대비 게이트(`npm run test:contrast`) 통과.
5. **강조·의미색은 바꾸지 않는다.** 브랜드 `#1D7B4E`·success `#1D7B4E`·warning `#8A5200`·error `#8F2F1D`는 대비
   게이트가 고정한 값이다. 시안의 `#166B41`·`#C83323`은 채택하지 않았다(2026-11-19 사용자 결정).
6. **글자·조작 단.** `typography.css`의 `--bo-k-*` 단(26·22·20·18·17·16·15·14·13·12px, 굵기 700·800 추가)과 조작
   높이(주 버튼 56·입력 48·행 안 버튼 44·탭 40·사이드바 행 36). 재구성한 네 화면(브리핑·발주계획·사업기회 레코드)과
   셸·패널 헤더가 쓴다. 운영 화면의 조밀한 표는 기존 4단을 유지한다.
7. **색·표식 규칙.** 추적 중 = 브랜드 옅은 채움, 결정 필요·후보 확인 대기 = 주의색, 모델 판단 = 정보색(보라),
   보류·종료·미선택 = 회색. 마감(D-n)·단계·건수는 표식이 아니라 글자, 숫자는 먹색. 선택 행은 fill 채움(브랜드 옅은
   채움은 상태 표식 전용). 글자가 항상 상태 이름이며 색만으로 말하지 않는다. blue 금지 게이트는 그대로다.
8. **목록|상세 화면은 패널 끝까지.** 발주계획·사전규격·사업기회·최종 Go/No-Go 목록은 `canvas: "flush"`로 두 칸이
   패널 가장자리에 닿고 세로선 하나로 나뉘며 목록은 38%다(발주계획과 사전규격 같은 폭 — 사용자 요청 유지).
   입찰 변경 비교(읽기 | 결정 두 칸)도 같은 배치이며, 사업명이 `<h1>`·현재 결정이 헤더 태그·문서 식별자가 설명
   줄이고 `결정 목록으로`·`결정 입력으로 이동`은 헤더 오른쪽 액션이다 — 1280×800에서도 결정 이유·기록자 칸이 첫
   화면에 남는다. 패널 헤더 사실 줄은 옛 pill의 의미색(success·warning·error)을 그대로 쓴다.
9. **문구.** 해요체, 문장형 제목, 주 버튼은 `~하기`(`추적 시작하기`, 넘기기는 `넘기기`). 값 없음/미확인/계산 불가/0,
   참조 실행·mock 표식, 부분 산출물 경고, 사람 결정 경계의 뜻은 바꾸지 않는다.

## 결과

- 바뀐 기존 규칙: ADR-0062 ⓒ(사업명·발주기관 같은 크기)는 발주계획에서 16/14px. ui-spec §4.1 "D-n 강조는 7일
  이내"는 "마감 전이면 강조". C-7 결정 버튼 이름은 `추적 시작하기`.
- 기존 API로 채울 수 없는 시안 요소(발주계획·사업기회의 수집 기준일, 서버가 기록한 "오늘 정한" 결정 목록)는 넣지
  않았다. `이 탭에서 정한 발주계획`은 이 탭에서 서버가 저장을 확인한 영수증만 sessionStorage에 모은 것이다.
- pixel 기준선(`web/frontend/tests/pixel-screens.spec.ts-snapshots/`, linux)은 갱신하지 않았다.

## 대안

- 화면별 헤더를 페이지가 직접 그리기: lazy·오류 경계에서 `<h1>`이 사라지는 문제(`PageHeaderActions`가 이미 피한
  문제)가 되살아나 택하지 않았다.
- 본문 16px을 운영 화면 표까지 적용: 표 밀도가 깨져 택하지 않았다.
- 시안의 의미색 `#166B41`·`#C83323`: 대비 게이트의 의미색 고정을 다시 열어야 해 택하지 않았다.
