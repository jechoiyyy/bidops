# ADR-0071 — 홈페이지 전문 가상 1사 기준 심층 검토 재정의

- 일자: 2026-10-14
- 상태: 목표 설계 채택. 제품 구현·배포·실제 모델 실행 승인 아님.
- 근거: 사용자가 2026-10-14에 가상 SI 3사 데모를 홈페이지 구축·운영·유지보수 용역
  전문 가상 1사로 바꾸고, 심층 검토 단계를 입력부터 실무자 판정 화면까지 다시 정의하기로 했다.
  같은 날 확인한 사실: 과거 홈페이지 제안요청서 5건의 HWP/HWPX 원본은 기존 rhwp 네이티브
  변환으로 4~10초에 구조화되고, 표 셀에서 요구사항 카드 198장(27·57·31·35·48)이 전부 복원된다.
  PDF 변환본은 읽기 순서가 깨지고 1건은 벡터 경로 글자라 OCR이 필요했으나 원본 HWP에는 글자가 있다.

## 결정

1. **대상 회사는 하나다.** 홈페이지 구축·운영·유지보수 용역 전문 가상회사 1곳을 `fictional_scenario`로 만든다.
   회사 어휘는 과거 홈페이지 공고의 요구사항 어휘에서 끌어내며, 의도적 격차를 둔다. 초안은 사용자가 승인한 뒤 동결한다.
   DEMO-01~04가 만든 회사 경계·온톨로지/그래프 저장·회사 REST·화면 코드는 그대로 쓰고 fixture·도메인·분석 파이프라인을 바꾼다.
2. **입력 정본은 HWP/HWPX 원본이다.** 변환은 기존 격리 document worker의 rhwp 네이티브 경로를 쓴다.
   PDF는 PDF 전용 첨부와 쪽 locator에만 쓴다. OCR은 이번 범위에 넣지 않으며 PDF 전용 첨부가 실제 수집에서 나타나면 다시 판단한다.
3. **분석 입력의 단위는 요구사항 카드다.** 분류·고유번호·명칭·정의·세부내용·응락수준·산출정보·관련 요구사항의
   라벨·값 카드를 결정적으로 읽어 inventory에 넣고, 쪽은 대응표에 직접 매핑된 키가 없을 때 표 앞 문단 anchor(최대 3개) 중 첫 매핑된 문단에서 물려받아 `inherited`로 구분한다.
   기존 열 제목 표 inventory는 유지한다. taxonomy에 운영·유지관리 목적과 유지관리 접두사(MAR·MPR·MHR·ECR)를 더한다.
4. **모델은 codex-exec의 `gpt-6-luna`, reasoning `high` 하나다.** 모든 단계가 같은 모델을 쓴다.
   HP 범위에서 로컬 Qwen/LiteLLM `local-agent-main`과 Terra는 쓰지 않는다(2026-10-14 사용자 결정, Terra 취소).
   모델·reasoning·CLI 버전은 새 불변 정책 파일과 runner 상수로 함께 바꾸며 기존 정책 파일(v1~v4·demo-v1)은 흔적으로 남긴다.
5. **분석은 두 층이다.** 1층은 카드·구간별 타입화 추출(자격·실적·인력·기술·기능·성능/SLA·보안·운영·계약·평가)과
   프로필 대조(결정적 비교 + 기존 3단계 그래프 경로), 2층은 역할별 판단·종합이다.
   코드가 카드 ID로 결과를 합치고 모델 간 충돌은 해소하지 않고 전달한다. 실무자 판정 항목은
   자격·실적, 상주·인력, 금액·기간, 기술(CMS·프레임워크·접근성), 운영(SLA·보안 점검)이다.
6. **실무자 화면은 다섯 블록이다.** 판정 카드 / 조건 체크리스트 / 요구사항 매트릭스 / 주의 포인트 / 다음 행동.
   판정은 참여 가능 여부에 대한 보조 의견이며 추적 승인·최종 Go/No-Go를 대신하지 않는다.
7. **품질 기준은 사람 gold 10건이다.** 사용자가 모델 출력을 보기 전에 문서마다 참여 판정, 차단 조건,
   충족 5·부족 5, 주의 포인트, 카드 상태 표본 10을 적는다.
8. **그래프 DB는 실험으로만 다룬다.** 같은 온톨로지·회사·요구사항을 PostgreSQL(현행)과 Neo4j에 적재해
   경로 recall, 질의 표현력, 설명 가능성 세 기준으로 비교한다. Apache AGE는 비교 대상에 넣지 않는다(사용자 결정).
   채택 조건은 실행 전에 숫자로 적는다. 결과가 나오기 전에는 제품에 그래프 DB를 넣지 않는다.
9. **SDLC.** DEMO 그룹은 2026-10-14에 닫는다. DEMO-00~04 기록과 코드는 보존하고, DEMO-05는 중단한다.
   새 그룹 `HP`에 HP-00~06을 등록한다. 상태·큐는 `scripts/feature_status.py`로만 바꾼다.

## 기존 결정과 관계

ADR-0070의 회사 경계·불변 근거·실제 인수 원칙과 공통 계약 §1~4·8의 저장 계약은 유지한다.
ADR-0070의 3사 비교·6건/18건/9건 목표와 LiteLLM 개요·핏 경로는 HP 범위에서 폐기한다(기록은 남긴다).
ADR-0069 건별 승인 Luna 경로와 ADR-0050 모델 경계는 유지한다. ADR-0051의 결정적 구조화 부분집합을 카드 inventory로 확장한다.
mission.md의 "RDF/OWL·SPARQL·별도 그래프 DB 제외"는 제품 범위에 한해 유지하고 실험(결정 8)은 예외다.

## 위험과 대안

가장 큰 위험은 카드 양식이 다른 공고(열 제목 표, 서술형 과업)에서 inventory가 비는 것이다. 기존 열 제목 경로를 유지하고 `inventory_empty`를 그대로 보고한다.
두 번째 위험은 호출 수다. 카드 198장을 건별로 보내면 호출이 수십 회이므로 카드를 구간으로 묶는 상한을 정책 값으로 둔다.
전 단계를 한 모델로 돌리는 대안(현행 narrative-v2)은 100쪽 문서에서 4~8시간이 걸리고 카드 단위 근거가 약해 채택하지 않았다.
