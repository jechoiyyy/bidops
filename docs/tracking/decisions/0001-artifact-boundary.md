# 기존 스크립트를 기준선으로 유지하고 산출물로 연결

- 상태: 채택
- 일자: 2026-08-24

## 맥락

수집·표본·병합·보고 스크립트에는 검증된 동작과 과거 회차 기준선이 있다. 웹 서비스에 같은 로직을 다시 구현하면 결과 차이가 규칙 변경인지 이식 버그인지 분리하기 어렵다.

## 결정

기존 스크립트는 유지하고 웹과 새 심층 검토 기능은 버전이 있는 JSON/YAML 산출물 또는 별도 프로세스로 연결한다. 새 기능은 기존 파일을 덮어쓰지 않고 새 계약을 추가한다.

## 대안

스크립트 로직을 백엔드 서비스로 흡수하는 방법은 호출이 단순해지지만 기준선 비교와 표준 라이브러리 독립성을 잃어 기각했다. 기존 스크립트를 직접 수정해 심층 검토까지 넣는 방법은 단계 책임과 실패 격리가 무너져 기각했다.

## 결과

적재기와 어댑터가 파일 계약을 다시 검증해야 하고 프로세스 로그·상태 관리가 필요하다. 스크립트 내부 객체를 웹이 직접 공유하는 구조와 기존 산출물 의미의 소급 변경은 허용되지 않는다.
