# 실무 화면과 운영 화면의 정보 경계를 처분 규칙으로 정한다

- 상태: 채택 (2026-09-21 사용자 결정)
- 일자: 2026-09-21
- 관련 결정: [ADR-0062](0062-explore-workspace-structure-unification.md)(수집 회차 선택 위치·실행 상태 표시)와
  [ADR-0064](0064-prespec-actionable-deadline-scope.md) 결정 7(도구 줄 순서)을 이 결정이 개정한다.

  ADR-0055(사전규격 담당자 브리핑 우선 배치 — 실행 정보 후순위)와 충돌하지 않으며 그 방향을 화면 전체로 넓힌다.
- 근거 요청: 2026-09-21 사용자 — "'발주계획'과 '사전규격'은 같은 '회차 선택' 기능 버튼이 있고 '수집회차'라는 텍스트를

## 맥락

관리 화면의 사용자는 발주계획·사전규격·입찰공고를 보고 추적 여부와 Go/No-Go를 정하는 기획·사업개발
실무자다. 그런데 조사에서 실무 화면 약 40곳이 서비스 운영 정보를 그대로 싣고 있었다.

- 발주계획: 행의 `판정 policy c2-…-v4`, `BM25 …`·`Qwen …` 배지, `예산 null (미제공)`, 영문 enum이 그대로인
  상세 필터와 사람 판단 수정 폼, 다이얼로그의 execution_id·policy/binding sha·토큰·`duration_ms`·artifact sha256,
  배너의 digest·컨테이너·환경 설정.
- 사전규격 상세: 회사 적합성 실행 정보(모델·프롬프트·sha·토큰·ms), 주장 ID, 제목 `현재 v4 개요 실행`,
  같은 경계 문장 4회 반복.
- 심층 검토·Go/No-Go·입찰 변경 비교: `안전한 오류 코드`, uuid·SHA-256·block_key·bbox, 영문 enum 병기,
  `InputRefFacts` 13줄.
- 셸: `판정 기준` 팝오버의 run_id, 사이드바 `관리자 화면`, 폼 오류의 `· 오류 코드`.

`web/frontend/src/lib/glossary.ts`는 이미 "목록·필터는 한글 라벨로 표시한다. 계약 토큰은 상세의 기술
정보에서만 표시한다"를 자기 규칙으로 선언해 두었다. 위 40곳은 그 규칙의 자기 위반이며, 규칙이 있는데도
지켜지지 않은 이유는 문구를 하나씩 심사할 **처분 기준**이 없었기 때문이다. 2026-09-20의 두 변경
(`d79bc48` 목록 바닥 안내 줄을 경고가 필요할 때만, `4b3a961` 검색 안내 문구를 접근 설명으로만)이 사실상
같은 심사를 했지만 그때는 한 화면의 두 문구에만 적용됐다.

동시에 **옮길 곳이 없다는 문제**가 있다. 발주계획 선별(C-2) 실행 기록을 읽는 운영 화면이 아직 없다 —
`/runs`는 공고 판정(C-1) 실행만 읽고(`RunsPage.tsx:119,207`), C-2 실행 상세는 실무 화면인
`OrderPlansPage.tsx:1146`에서만 읽는다. 지금 실무 화면에서 실행 기록을 빼면 운영자가 그 값을 볼 경로가
저장소 어디에도 남지 않는다.

검토한 대안:

- **운영 정보를 실무 화면에서 전부 삭제한다.** 식별자·해시가 화면에서 사라지면 운영자가 실행·정책·산출물을
  눈으로 대조할 수단을 잃는다. `glossary.ts`가 "사람이 눈으로 대조하는 값"이라고 적어 둔 값들이다.
  채택하지 않았다.
- **처분을 `실무 유지` / `운영 이동` 2종으로만 나눈다.** 경고 상황에서만 필요한 표시(부분 산출물, 선별 실패,
  자동 실행 꺼짐)가 갈 곳이 없어 상시 표시나 삭제 중 하나로 밀린다. 2026-09-20에 이미 "경고가 필요할 때만
  그린다"는 세 번째 처분이 필요했다. 채택하지 않았다.
- **영문 토큰·코드를 화면에서 일괄 한글화한다.** 서버가 정한 안전 코드(사유 코드·오류 코드)까지 번역하면
  모르는 코드가 임의의 다른 사유로 바뀌거나 숨겨진다(`web/frontend/AGENTS.md:21`). 채택하지 않았다.
- **빈 값 문구를 `값 없음` 하나로 합친다.** 5종이나 되는 "예산 없음" 문구는 줄여야 하지만, 서버가 null을 준
  것과 확인되지 않은 것과 계산할 수 없는 것과 실제 0은 서로 다른 상태다(`standards.md` "데이터 불변성과 상태").
  채택하지 않았다.
- **실무 화면에서 먼저 빼고 운영 화면은 뒤에 만든다.** 그 사이 C-2 실행 기록·계획별 신호를 읽을 경로가
  없어진다. 채택하지 않았다.
- **대시보드는 운영자 화면으로 두고 실무자는 목록 화면에서 하루를 시작한다.** 현재 대시보드는 누적 업무
  바로가기 4개와 보류 패널 아래 패널 4개가 회차를 골라야 나오고 그중 `검증 상태`·`회차 요약`은 운영 지표다.
  회차를 고르는 화면은 하루를 시작하는 화면이 되지 못한다. 채택하지 않았다.

## 결정

1. **실무 화면의 문구·값은 하나씩 심사해 다섯 중 하나로 처분한다.**

   | 처분 | 뜻 |
   |---|---|
   | 삭제 | 구조나 다른 표식이 이미 같은 사실을 말한다 |
   | 조건부 | 경고 상황에서만 그린다 |
   | 이동 | 운영 화면, 같은 화면의 접힌 `기술 정보`, 접근 설명(`aria` description) 중 한 곳으로 옮긴다 |
   | 한글화 | 값의 뜻은 실무 정보인데 표기가 계약 토큰·모델명·필드명이다. 표시만 바꾸고 서버 값·URL 값·unknown/null의 의미는 보존한다 |
   | 유지 | 판단에 필요하거나 결정 5의 경고다 |

   화면별 처분 결과는 `docs/0921_practitioner-screens/spec.md` §3이 정본이다. "운영 정보처럼 보인다"는
   인상만으로 지우지 않고, 각 항목이 어느 처분인지와 그 이유를 표에 남긴다.

2. **식별자와 해시 값 자체는 줄이지 않는다. 옮길 수는 있다.** 문서 버전 ID, SHA-256, execution_id, request ID는
   사람이 눈으로 대조하는 값이므로 8자 축약·말줄임을 만들지 않는다. 바뀌는 것은 **어느 화면의 어느 블록에
   있는가**뿐이며, 운영 화면이나 같은 화면의 접힌 `기술 정보`가 목적지다. `web/frontend/src/lib/glossary.ts:14`의
   "줄이거나 옮기지 않는다"를 이 결정에 맞게 개정한다(코드 패키지 R2가 개정한다).

3. **모르는 코드는 그대로 통과시킨다.** 서버가 정한 안전 코드 중 화면에 대응 문장이 있는 것만 한글화하고,
   목록에 없는 코드는 바꾸거나 숨기지 않고 원문 그대로 보여 준다(`web/frontend/AGENTS.md:21`). 한글화는
   표시 계층에서만 일어나고 서버 값·URL 질의 값은 영문 그대로 유지한다.

4. **뜻이 다른 빈 값은 합치지 않는다.** 서버가 null을 줌 = `미제공`, 확인되지 않음 = `미확인`, 계산할 수 없음 =
   `계산 불가`, 실제 0 = `0`. 합치는 것은 **같은 뜻을 다르게 쓴 문구**뿐이고(예: "예산 없음" 5종), 표시에서
   빼는 것은 영문 `null` 토큰이다. `unknown`·`null`을 확인 완료나 0으로 승격시키지 않는다는 기존 게이트는
   그대로다.

5. **지우면 안 되는 경고가 있다.** 아래는 어떤 처분에서도 삭제 대상이 아니다.

   ① 참조 실행 표식(`참조 실행 · 품질 미측정`/`mock 참조`/`표식 없음`, `lib/qualityStatus.ts`)
   ② 회차 모드 `· 측정 전용 실행`(`scope.purpose === "gate_measurement"`)
   ③ 부분 산출물·검증 경고
   ④ 계산 불가≠0, 실패≠성공/변경 없음
   ⑤ 판정 없음≠비관련
   ⑥ `is_current=false` 안내
   ⑦ 담당자 이름≠인증

   그리고 발주계획 상세의 "계획 정보 기반 탐색 신호 · 회사 적합성과 참여 자격은 미확인", 심층 보고서 범위
   주석(`DeepReviewPage.tsx:770`), `AttachmentPanel.tsx:53,79`의 안내, 사전규격 ⑥ 접힌 진단
   Collapsible(`docs/0915_ui-redesign/spec.md:234`, 실패·사람 확인이면 기본 열림).

   경고 문장이 운영 코드와 한 블록에 있으면 요소를 나눠 문장만 남긴다 — 블록째 옮기면 경고가 함께 사라진다.

6. **운영 수신처를 먼저 만들고 나서 실무 화면에서 뺀다.** `/runs` 회차 상세에 `발주계획 선별` 탭
   (`components/runs/OrderPlanScreeningPanel.tsx`)이 생긴 뒤에 발주계획 화면의 이동 처분을 실행한다
   (spec §4 → §3.1 순서). 같은 규칙을 다른 이동 처분에도 적용한다 — 접힌 `기술 정보` 블록이 없는 화면에서는
   블록을 먼저 만든다. 어떤 값도 "옮기는 중"이라는 이유로 저장소의 어느 화면에서도 읽을 수 없는 상태를 거치지
   않는다.

7. **대시보드는 운영자 화면이 아니라 실무자가 하루를 시작하는 화면이다.** 회차를 고르지 않아도 화면이 채워져
   있어야 하며, 회차 선택기와 `회차 실행 보기 →`는 삭제하고 `회차 요약`·`검증 상태`는 `/runs` 회차 상세로
   이식한다. 운영 화면 진입은 사이드바가 맡는다. 패널의 목록 계약(출처·모집단·정렬·기준 시각·제공자 부재
   처리)은 구현 전에 spec §7의 개정으로 닫고 별도 ADR(0066)로 기록한다.

## 결과

- migration 없음. 새 상태·필드·외부 전송·모델 binding이 없다. 서버 값·URL 질의 값·unknown/null의 의미는
  모두 보존되며 바뀌는 것은 표시 계층과 값이 놓이는 화면이다. Alembic head는 `0030_prespec_review_exclusion`
  그대로다.
- 이 결정으로 개정되는 정본(`docs/0921_practitioner-screens/spec.md` §8):

  | 문서 | 개정 |
  |---|---|
  | [ADR-0062](0062-explore-workspace-structure-unification.md) | 회차 선택 행(도구 줄 → 상세 필터 안, 공용 컴포넌트, run_id 제외, `/runs` 링크), 실행 상태 표시 행(최근 실행에 문제가 있을 때만) |
  | [ADR-0064](0064-prespec-actionable-deadline-scope.md) 결정 7 | 도구 줄 순서에서 수집 회차 칸 제거 |
  | `docs/0918_daily-operation/spec.md` §7 '행 표시'(결정 16) | 행에는 첫 수집일만, policy는 운영 화면, `판정 없음` 유지 |
  | `web/frontend/src/lib/glossary.ts:14` | "줄이지 않는다. 운영 화면·접힌 기술 정보로 옮길 수 있다"(코드 패키지 R2가 개정) |
  | `docs/0915_ui-redesign/decisions.md`, `docs/ADR.md` | 항목 추가 |
  | `docs/tracking/findings.md` | 분리한 후속 작업 인계(수집 확장, 단계 지연, 담당자 연락처, `budget` 출처) |
  | `docs/contracts.md`, `docs/bid-delta-contract-spec.md` | spec §5·§7의 투영 |
  | ADR-0066(신규, spec §7 착수 때) | 대시보드 누적 workload 키 |
  | `docs/tracking/status.md` | 패키지·배포 기록 |

- 화면 변경은 시안 승인 뒤에만 구현한다(2026-09-20 사용자 지시, ADR-0062가 첫 적용). 이 결정의 처분표도
  화면이 바뀌는 절은 시안 M1~M6에서 확정되며, 시안이 명세와 다르게 승인되면 명세를 개정 문장으로 고친다.
- 처분 심사에서 드러난 정확성 결함 하나는 시안과 무관하게 먼저 고친다 — `NoticeFacts.tsx:25-27`이 지역 제한
  근거가 비었을 때 `지역 제한 없음`을 출력한다. 수집기는 빈 근거가 제한 없음의 증거가 아니라고 적는다
  (`collect_notices.py:623`). `지역 제한 미확인`으로 고친다(결정 4의 `미확인`).
- 범위 밖으로 분리한 것은 `docs/tracking/findings.md`에 인계한다 — 수집 확장(자격등록 마감·공동수급협정
  마감·설명회·입찰 개시·낙찰하한율·사전규격 납품기한), 단계 지연 재확인 알림, 발주처 담당자 연락처 표시,
  `budget` 출처 구분.

### 독립 리뷰가 바꾼 것 (codex `gpt-6-astra` high, 2026-09-21)

설계 확정 전에 독립 리뷰를 받았다. 판정은 "수정 후 진행"이었고 차단 7·주의 7·누락 4건을 코드에서 다시
확인해 모두 반영했다. 이 결정의 문안을 바꾼 것은 다음 여덟 가지다.

| 지적(코드로 확인됨) | 반영 |
|---|---|
