# 판정 단계만 애플리케이션 안 오케스트레이터로 전환

- 상태: 채택
- 일자: 2026-08-25

## 맥락

세 스킬 가운데 언어모델이 필요한 단계는 판정이며, 수집과 보고는 이미 결정적 스크립트로 동작한다. 기존 파이프라인의 기준선을 유지하면서 정해진 시각에 판정을 수행하는 애플리케이션 구성이 필요하다.

## 결정

판정 단계만 애플리케이션 안 오케스트레이터로 전환한다. 오케스트레이터는 판정 입력을 만들고 모델 호출·결정적 검증·저장을 연결하며, 수집과 보고는 기존 결정적 스크립트로 유지한다. 수집·판정·보고의 자동 실행을 연결하더라도 최종 참여 결정은 담당자가 수행한다.

## 대안

세 스킬 모두를 모델 기반으로 재구성하는 방법은 모델이 필요하지 않은 수집·보고까지 비결정적 경로로 바꾸어 기존 기준선과 산출물 재현성을 훼손하므로 기각했다.

심층 검토까지 한 번에 포함하는 방법은 1차 판정과 심층 검토의 단계 범위와 입력·실패 경계를 한 번에 묶어 이번 전환 범위를 넓히므로 기각했다.

## 결과

판정에만 오케스트레이터와 모델 호출 경계를 둔다. 수집·보고 스크립트의 동작과 산출물 계약은 기준선으로 남고, 판정 결과는 검증을 통과한 뒤 저장 계층으로 전달해야 한다. 판정 결과가 참여 여부를 자동으로 확정하지 않는 경계도 유지한다.
