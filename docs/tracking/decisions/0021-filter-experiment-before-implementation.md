# 발주계획 선별은 비교 실험 후 구현

- 상태: 채택
- 일자: 2026-08-27

## 맥락

발주계획은 3일에 약 1,200건, 1주에 약 2,000건으로 예상된다. 제목과 제한된 메타데이터만으로 조기 가능성을 찾아야 하므로 규칙의 설명력, 검색 모델의 recall, LLM의 회사 맥락 이해, 검토 비용 사이에 tradeoff가 있다. 한 방식을 먼저 제품에 넣으면 그 방식이 만든 후보만 사람이 보게 되어 누락을 평가할 기준을 잃는다.

외부 GPT 모델은 비교 품질을 높일 수 있지만 회사자료의 외부 전송과 비용이 생긴다. Sol xhigh를 정답으로 사용하면 같은 계열 편향이 평가 기준에 들어간다.

## 결정

제품 선별기를 구현하기 전에 동일한 동결 3일 전체 모집단에서 다음 네 방식을 비교한다.

1. 키워드 규칙
2. ColBERT 유사도
3. Qwen3.8:27B 추론
4. GPT Luna xhigh 추론

모든 방식은 같은 공개 발주계획 메타데이터를 받고, 점수·순위·사유·버전·비용·지연을 저장한다. 사람은 모집단의 relevance와 우선순위를 최종 정답으로 판정한다. Sol xhigh 결과는 silver reference와 불일치 탐색에만 사용한다.

외부 모델에는 공개 발주계획 메타데이터와 별도 승인된 최소 회사 역량 요약만 보낸다. 회사 프로필 전문, RFP·첨부, 내부 리뷰·성과는 보내지 않는다. 담당자가 실행 payload를 보고 건별 승인하며 운영 장애 시 자동 fallback으로 사용하지 않는다.

초기 개발계정 일 1,000회 한도는 endpoint·page·retry별 실제 요청 수를 계측하면서 사용한다. cache를 재사용하고 700회 경고, 900회 신규 요청 중지를 적용한다. 운영 증액은 실측 보고서를 근거로 활용사례 등록 뒤 신청한다.

## 대안

키워드 규칙만 즉시 구현하면 빠르고 설명 가능하지만 의미가 다른 표현의 recall을 알 수 없어 기각했다.

Qwen 또는 GPT를 처음부터 운영 정본으로 정하면 모델 비용과 비결정성뿐 아니라 어떤 공고를 놓쳤는지 비교할 모집단·사람 정답이 없어 기각했다.

Sol xhigh 결과를 gold로 사용하면 사람 검토량은 줄지만 모델 편향과 확인되지 않은 회사 맥락을 정답으로 고정하므로 기각했다.

모든 방식을 영구 ensemble로 운영하면 누락 위험은 낮출 수 있지만 비용, latency, 정책 설명이 복잡해지므로 실험 결과 없이 먼저 선택하지 않는다.

## 결과

선택된 건만이 아니라 전체 정규화 발주계획과 네 방식의 결과를 보존해야 한다. 비교 보고서에는 recall, precision, 중요 누락, 사람이 볼 후보 수, 순위 품질, 비용, latency, 재현성을 포함한다. 선택 방식 또는 조합과 threshold가 승인되기 전에는 제품 scheduler와 always-on을 활성화하지 않는다.

## 개정 (2026-08-31): 비교 arm 교체

D-5 승인과 함께 비교 arm을 다음 셋으로 바꾼다. 실험을 먼저 하고 제품을 만든다는
원래 결정과 모집단·정답 판정·보존 요구는 그대로다.

1. BM25
2. 한국어 dense bi-encoder
3. 두 결과의 RRF 하이브리드

### 근거

고정 3일 모집단 997건(`data/experiments/order-plan-screening/20260824-20260826-interim-v3`)을
실측한 결과 한 건이 가진 텍스트는 `title` 중앙값 30자(p90 43자, 최대 78자, 최소 8자)와
`agency_name`, 두 값뿐인 `business_division`이 전부다. 사업개요도 본문도 없다.

- BM25의 term frequency 포화와 문서 길이 정규화는 이 길이에서 작동하지 않는다. 사실상
  IDF 가중 단어 겹침으로 퇴화하며 지배적 실패는 어휘 불일치다.
- 짧은 텍스트 의미 매칭은 dense bi-encoder가 가장 강한 영역이다. BM25가 0점을 주는
  어휘 불일치 건을 복구할 것으로 기대한다.
- ColBERT의 late-interaction 이점은 긴 문서의 토큰 단위 매칭에서 나온다. 30자 제목에서는
  이점이 사라지고 비용만 남으므로 dense bi-encoder로 교체한다.
- LLM arm은 비용 대비 가치 판단으로 보류한다. 사람 정답은 arm과 무관하게 보존하므로
  나중에 같은 모집단·같은 정답으로 추가 비교할 수 있다.

### 측정 기준

하이브리드의 채택 근거는 평균 순위 품질이 아니라 **단독 arm이 놓친 건의 복구**다.
BM25 단독과 dense 단독을 함께 돌려 서로 다른 실패를 대조할 수 있어야 하므로 세 arm이
최소 구성이다.

### 구현 제약

- 결합은 RRF로 시작한다. 가중 점수 합산은 BM25 점수와 코사인 유사도라는 눈금이 다른 두
  값을 정규화해야 하고 그 가중치가 튜닝 노브가 되므로 실험 결과 없이 도입하지 않는다.
- 회사 역량은 `company-capabilities.json`의 capability 6개를 하나로 합치지 않고 각각
  조회한 뒤 max를 취한다. 합치면 신호가 희석되고, 어느 역량 때문에 걸렸는지가 사람에게
  보여야 근거가 된다.
- 한국어 토크나이저 선택(형태소 분석 대 문자 n-gram)은 BM25 arm의 구현 결정이며 실행
  전에 고정하고 보고서에 남긴다.
