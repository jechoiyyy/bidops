# 정기 실행은 웹 프로세스 내부 스케줄러로 구동

- 상태: 채택
- 일자: 2026-08-25

## 맥락

정기 실행은 매일 회차를 고정해 수집·판정·보고를 수행해야 한다. 예약을 깨우는 책임과 실제 판정 오케스트레이션의 책임을 분리하되, 여러 웹 프로세스가 실행되어도 같은 회차가 중복 시작되지 않아야 한다.

## 결정

정기 실행은 웹 프로세스 내부의 스케줄러가 구동한다. 스케줄러는 예약된 작업을 깨우고 회차와 기간을 고정한 뒤 판정 오케스트레이터를 기동한다. 회차 중복 방지는 데이터베이스의 유일 제약으로 처리하며, 스케줄러가 판정 내용이나 모델 호출을 직접 수행하지 않도록 한다.

## 대안

별도 워커 컨테이너를 두는 방법은 배포·운영 구성요소와 실행 경계를 늘리고 웹 프로세스 안에서 회차를 기동한다는 목표와 맞지 않으므로 기각했다.

호스트 cron이 CLI를 호출하는 방법은 예약과 호스트 환경 의존성을 애플리케이션 밖에 두어 운영 상태와 회차 기동을 한 경계에서 관리하기 어렵게 하므로 기각했다.

## 결과

웹 프로세스 내부 스케줄러는 예약·중복 방지 경계에 머물고, 판정 오케스트레이터가 입력 구성과 모델·검증 흐름을 담당한다. 수동 트리거와 정기 트리거가 같은 회차 키로 충돌할 때는 데이터베이스 유일 제약에 따라 하나만 실행되어야 한다.
