# ADR-0073 — 루트랩 실회사 기준 AX 과제 재정의

- 일자: 2026-10-16
- 상태: 목표 설계 채택. 제품 구현·배포·실제 모델 실행 승인 아님. 기능 명세는 `RL` 그룹에서 `/sdlc:feature`로 만든다.
- 근거: 사용자가 2026-10-16에 BidOps를 실회사 ㈜루트랩 기준으로 다시 정의했다. 진술한 이유는 "나라장터 공고를 살펴보는 데 인적·시간 비용이 많이 들고 단순 서칭에 입력이 집중된다"이며, 목표는 "에이전트가 공고를 분석해 루트랩이 입찰·수주할 만한 공고를 찾아 실무자에게 알리고, 공고와 회사 데이터로 제안서 초안까지 쓴다"이다.
  같은 날 인터뷰 답(Q1~Q9)은 [재정의 초안 §6](../../1016_rootlab-redefinition/draft.md)에 있다. 회사 근거는 [회사소개서 프로필](../../reference/company-profile.md)·[홈페이지 프로필](../../reference/company-homepage-profile.md)·[선호·제약 제안값](../../reference/company-preferences.md)·[인터뷰 양식](../../1016_rootlab-redefinition/company-interview.md)이다.

## 결정

1. **회사는 실회사 루트랩 하나다.** DEMO(가상 SI 3사)와 HP(가상 온웹서비스 1사)의 가상회사 전제는 폐기한다. 회사 경계·그래프 저장·회사 REST·화면 코드(DEMO-01~04)와 요구사항 카드 inventory(HP-01), Luna identity(HP-00)는 재사용한다. 회사 행은 `is_fictional=false`로 등록하고 사실 노드의 origin은 확인 출처(회사소개서·홈페이지·사용자 인터뷰)로 적는다.
2. **목표는 세 단계다.** G1 발견·알림(평일 1회 브리핑, Slack bot + 화면), G2 판정 근거(요구사항 카드·자격·예산·일정 대 회사 근거 대조, 실무자 판정 보조), G3 제안서 초안(요구사항 대응표 + 사업 이해·수행 방안·유사 실적 절, DOCX). 자동 입찰·제출, 발주처 연락, 최종 Go/No-Go, 제안서 제출본은 범위 밖이다. PRD §5.4의 "자동 입찰서 작성 제외"는 "제출본 자동 작성 제외"로 좁힌다.
3. **공고 범위.** 사전규격·입찰공고가 브리핑 1순위, 발주계획은 반복 발주처의 연차 사업 예고 전용이다. C-2 선별은 브리핑 후보 생성기로 역할을 축소하고 반복 발주처·연차 사업 규칙을 앞에 둔다.
4. **AX 전환.** 목록 훑기(pull)를 브리핑(push)으로, 발주계획 전건 사람 라벨은 브리핑 반응(채택·무시·이유)으로, 개요 검토 + 건별 심층 승인은 카드 기반 1회 분석의 자동 실행으로, 세 단계 화면은 사업기회 타임라인 하나와 상태 변화 알림으로 바꾼다. 원문 불변·계보·`unknown` 보존·locator 검증·사람 최종 결정은 유지한다.
5. **모델 경계.** 모든 LLM 작업은 codex-exec `gpt-6-luna`(HP-00 identity)로 간다. 공고 원문·첨부와 회사 근거의 Luna 전송은 **정책 단위 사전 승인**으로 자동화하고 건별 클릭 승인을 없앤다. 건별 감사 기록·payload 동결·allowlist·hosted fallback 금지(ADR-0050)는 유지한다. ADR-0069의 건별 승인은 이 범위에서 정책 승인으로 대체한다. 기능 구현 완료 뒤 토큰 최적화용 로컬 LLM 단계를 별도 기능으로 검토한다.
6. **가장 중요한 성공 요인은 회사 자기 근거 데이터의 정확성·최신성이다.** 실적·자격·인력·가용성·선호·제외를 사용자 인터뷰로 채우고 버전을 고정한다. 확인 전 값은 `proposed`로 두고 차단 조건에 쓰지 않는다. 성공은 "실무자가 직접 서칭을 그만둔다"로 판정한다.
7. **기준선.** 실무자 5명이 2~3일에 한 번 서칭한다. 회당 60분(추정, 검색어 10개 안팎 반복·목록 훑기·상세 열기)이면 연 약 500시간, 약 3인월이다. 여기에 후보 공고별 제안요청서 정독 2~4시간이 더해진다. 실제 값은 인터뷰 F절로 교체한다.
8. **SDLC.** HP run `hp0206-20261015`를 abandon하고 HP-02~06을 `blocked`로 두고 큐에서 뺀다. HP-00·01 기록은 유지한다. main은 demo/local-20261009를 fast-forward한 상태(`before-rootlab-ff-20261016` 태그)이며 새 그룹 `RL`을 main에서 진행한다. 실행·검증은 `bidops-local` 격리 자원에서 하고 운영 전환은 별도 작업이다. Neo4j 실험은 보류한다.

## 개정

- 2026-10-16 (인터뷰 반영): 결정 2의 제안서 초안 출력 형식 DOCX를 **PDF(1차)·HWP(후속 결정)** 로 바꾼다. 사용자 답(E2)이 PDF·HWP이고 과거 제안서·표준 문구가 없어(E1·E3) 초안은 제안요청서 목차와 회사 근거만으로 만든다. 브리핑 시각은 평일 08:00(F4). 상주 가능 지역은 대구만(C4). 사업 유형은 유지관리·고도화·구축 동급(D8). 근거: [인터뷰](../../1016_rootlab-redefinition/company-interview.md), [프로필 §8](../../reference/company-profile.md).
- 2026-10-16 (독립 UI/UX 리뷰): 목업 리뷰 결정 10개는 [ux-review.md §5](../../1016_rootlab-redefinition/ux-review.md)에 있으며 RL-01~04 spec의 입력이다. 특히 `unknown`을 부족으로 승격하지 않는 규칙(HP 계약 §7)과 조회·채택·추적 결정·자동 분석의 분리를 화면 계약에 넣는다.
- 2026-10-16 (화면 시안 확정): 사용자 확정 시안 v26을 [RL 화면 구현 명세](../../1016_rootlab-redefinition/ui-spec.md)로 고정했다. CRM 앱 구조(사이드바 오브젝트·리스트, 리스트 뷰 + 피크 패널, 레코드 페이지 탭)이며 실무 화면에서 운영 정보를 제거한다. 밝은 사이드바와 신설 토큰은 테마 ADR(ADR-0048 개정)로 따로 확정한다.
- 2026-10-16 (테마·셸 적용): 사용자 "테마 토큰 교체하고 셸부터 시안 그대로 적용" 결정. `bidopsTheme.ts` 라이트 값을 시안 v26 hex로 교체(ADR-0048 개정: 흰 바탕, 사이드바 `#F8F8F9`, 경계 `#E6E7EB`, 본문 `#1F2328`, 강조·성공 `#1D7B4E`, 경고 `#8A5200`, 실패 `#8F2F1D`, 단계 teal, 라운드 6/8px), `brand.css`에 `--bo-sidebar-*`·`--bo-avatar-bg`·`--bo-warning-subtle` 추가, 사이드바·상단바를 ui-spec §1로 재작성, `/briefing` 자리 화면 추가. 대비 게이트의 의미색 기대값은 시안 값으로 갱신했다.

## 기존 결정과 관계

ADR-0070·0071의 회사 경계·불변 근거·카드 inventory·Luna identity는 유지하고 가상회사·3사 비교·gold 조건의 가상 전제는 폐기한다(기록은 남긴다). ADR-0049·0054의 사전규격 자동 준비는 유지하고 개요 run 자동 enqueue는 카드 분석 자동 실행으로 대체 검토한다. ADR-0060~0061의 C-2 운영은 유지한다. ADR-0050의 모델 경계는 전송 승인 단위만 건별→정책으로 완화한다.

## 위험과 대안

- 회사 데이터가 비어 있으면 판정이 `unknown`에 머물고 브리핑 신뢰가 서지 않는다. 대안(가상 데이터로 채우기)은 폐기했다. 인터뷰를 첫 기능(RL-00)으로 둔다.
- 브리핑 상위 N의 정밀도가 낮으면 실무자가 다시 직접 서칭한다. 반복 발주처·연차 규칙을 먼저 넣고 반응 피드백을 수집한다.
- 제안서 초안은 요구사항 카드 양식이 아닌 공고(열 제목 표·서술형)에서 대응표가 빈다. 기존 열 제목 경로와 `inventory_empty` 보고를 유지한다.
- Luna 자동 전송은 외부 서비스 의존과 비용을 늘린다. 정책 승인·건별 감사·일일 호출 상한을 둔다.
