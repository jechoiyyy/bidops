# 발주계획·사전규격 탐색 화면의 구조를 하나로 맞춘다

- 상태: 채택 (2026-09-20 사용자 결정, 시안 승인)
- 일자: 2026-09-20
- 관련 결정: `docs/0915_ui-redesign/spec.md` §2.4("발주계획의 구성·문구·상태 규칙은 현재 화면 그대로")를 넘는 결정, ADR-0040(레이아웃은 프로젝트 소유)·ADR-0047(데스크톱 전용)·ADR-0048(`bidops` 테마가 색 정본), [ADR-0063](0063-order-plan-bulk-tracking-end.md)(같은 작업의 일괄 종료)
- 근거 요청: 사용자 요청 2026-09-20 — "`/order-plans`와 `/pre-specs`의 UI 구조가 다를 필요가 없음, `/pre-specs` 기준으로", "발주기관을 따로 감싼 것은 가시성이 좋음, `/pre-specs`에도 적용", "회차 선택도 pre-specs와 동일하게"
- 승인 시안: `docs/0915_ui-redesign/mockups/0920_explore-unify/` (Artifact https://claude.ai/artifact/46DZkNcXT2nFmjZiWRkFCH Version 2)

## 맥락

두 화면은 같은 일을 한다 — 왼쪽 목록에서 고르고 오른쪽에서 읽고 추적을 정한다. 같은 primitive(`WorkspaceFrame`·
`WorkspaceFilterBar`·`WorkspaceViewTabs`·`SplitWorkspace`·`DenseList`)를 쓰면서도 그 안쪽 구성이 8곳에서 달랐고, CSS도
`c2l-*`와 `pre-specs-*`로 같은 규칙을 복제하고 있었다. 재설계 C(2026-09-15)는 사전규격 우측 pane만 새로 설계하고 발주계획은
"구성은 현재 그대로"로 두었으므로, 두 화면을 같게 만드는 것은 그 시안을 넘는 새 결정이다. 기존 근거는
`tests/explore-workspace-consistency.spec.ts`의 실측 비교(목록 비율·머리 여백)뿐이었다.

## 결정

사전규격을 기준으로 맞추되, 발주계획 쪽이 더 나은 세 곳은 그것을 공용으로 올려 사전규격에 적용한다. 데이터 계층은 건드리지
않는다 — 발주계획의 클라이언트 필터(`fetchAllOrderPlans`)와 `GET /api/order-plans` 계약은 그대로다(findings
"발주계획 화면이 누적 목록을 500행씩 전부 받아 브라우저에서 거른다"는 별도 작업).

| 항목 | 결정 |
|---|---|
| 필터 줄 추가물 | 화면별 유지. 발주계획의 저장된 뷰는 상세 필터 안에 남긴다 |
| 수집 회차 선택 | 발주계획도 필터 아래 줄(`WorkspaceFilterContext`)에 `수집 회차` 라벨로 둔다. 실행 상태 표시는 상단 바에 남긴다 |
| 목록 폭 | 38% 고정. 발주계획의 드래그 리사이저를 **제거**한다(기능 손실을 사용자가 확인하고 승인) |
| 목록 머리 | 한 줄(제목+건수, 기본 보기 설명). 발주계획의 범위·policy 설명은 목록 바닥 안내 줄로 내린다. **2026-09-21 개정(사용자 결정)**: 바닥 줄은 실무자에게 경고가 필요할 때만 그린다 — 판정 없음, 활성 policy 판정 없음, 측정 전용일 수 있는 회차 모드. 평상시 누적의 `판정 policy …`, 정렬 설명, 기본 보기 숨김 안내(`BM25 선정 제외…`)는 지운다. 숨긴 건이 있다는 사실은 `전체` 탭과 그 건수가 보여 준다 |
| 열 머리 | 공용. 발주계획은 `사업명 / 발주기관` · `발주 예정` |
| 행 배치 | 체크박스 왼쪽, 날짜 값은 오른쪽 열, 상태 칩은 아래 줄 |
| 목록 글자 | 발주계획도 사전규격과 같은 크기(+2px) |
| 선택 툴바 | 공용 컴포넌트. 발주계획에는 `전체 선택`을 넣지 않는다(업무 규칙). 단추는 `선택 항목 추적 시작`·`선택 항목 추적 종료`·`선택 전체 해제` |
| 페이저 | **발주계획 방식** — 목록 pane 안쪽 바닥 |
| 로딩·오류 | **발주계획 방식** — 조회 중에도 좌우 분할 골격을 유지하고 상태는 목록 pane 안에 그린다 |
| 빈·오류 표현 | `EmptyState`로 통일, 문구 보존 |
| 상세 머리 | **발주계획 방식** — sticky(`StickyDecisionHeader`) |
| 발주기관 | 공용 강조 블록(`--color-accent-muted` 배경, 기존 값 그대로 — 새 색 없음). 사전규격 상세 머리는 기관 블록(전체 폭) → 사업명 → 칩 → 식별 줄 순서(시안 A안) |
| 전체 상세(`/pre-specs/:id`) | 머리 최상단에 같은 블록을 추가하고 식별 줄의 기관명은 그대로 둔다(중복 표시를 사용자가 확인하고 승인) |

## 결과

- 중복 CSS 쌍(`.c2l-workspace`↔`.pre-specs-split-workspace` 등)의 공통 규칙은 `review-primitives.css`로 올리고, 화면 클래스는
  테스트 selector로 남긴다.
- `explore-workspace-consistency.spec.ts`의 selector 표를 함께 갱신한다. 픽셀 기준선 두 장(`order-plans-list`·`pre-specs-list`)을
  갈아 끼운다(사유: 이 결정, 승인자: jechoi).
- 시안 승인 게이트: UI 변경은 시안을 먼저 확인·승인한 뒤에만 구현한다(2026-09-20 사용자 지시). 이 결정이 그 첫 적용이다.
- 구현 때 실측할 접근성 항목(화면 축소 0.9 뒤 클릭 대상 24px, sticky 머리의 포커스 가림, 새 단추의 포커스 링 대비)은 오픈소스
  UX 가이드라인(ui-ux-pro-max v2.15.0, MIT)을 저장소 밖에서 조회해 대조한 것이다. 그 도구는 저장소에 설치하지 않는다 — 색·
  글꼴·반응형 추천이 ADR-0047·0048과 충돌하고, 플러그인·CLI 설치 경로가 프로젝트 설정 파일 쓰기와 외부 API 호출을 포함한다.
