# ADR-0070 — 가상 SI 3사·지식그래프 기반 사내 데모

- 일자: 2026-10-06
- 상태: 목표 설계 채택. 제품 구현·배포·실제 모델 실행 승인 아님.
- 근거: 사용자가 회사 전환+비교, 실제 공고+실제 분석, 심층 뒤 추적 결정,
  전문 분야 중심, 사전규격부터, 사내 격리, 기존 Luna, 6건/18건/9건,
  업무 온톨로지, 분석+탐색 그래프, 파일 기반 초기 관리와 5개 기능 문서화를 선택했다.

## 결정
회사 identity·회사별 추적은 lifecycle, 프로필·그래프·분석은 deep_review가 소유한다.
원문/문서 구조/v7 개요는 공통이며 회사 상태는 명시적 company_id로 분리한다.
PostgreSQL에 버전 그래프를 저장하고 불변 source/evidence 계보를 재사용한다.
가상 설정과 사실 확실성을 별도 축으로 유지한다. 모델의 근거 경로는 판단 보조이며 자격 충족 증명이 아니다.
원본과 프로필 projection은 같은 등록에서 생성한다. 회사별 경로는 전역 최신 프로필을 읽지 않는다.
기존 단일회사 API는 NULL 회사 계보로 유지하고 새 회사 결과는 namespace 경계에서 분리한다.

## 기존 결정과 관계
ADR-0045 모듈 경계, ADR-0047 데스크톱, ADR-0050 모델 경계, ADR-0069 승인 기반 Luna를 확장한다.
기존 검증 off 참조 정책은 보존하되 이 데모의 완성 보고서 인수 정책으로 사용하지 않는다.
프로필·실적 추정 금지는 유지한다. 새로 창작하는 자료는 fictional_scenario로 명시된 데모 입력이다.
그래프 DB, RDF/OWL, 편집/자동 추출 UI, C-2와 최종 Go/No-Go는 이번 범위 밖이다.

## 계약·결과
[DEMO 공통 계약](../../work/demo-contract.md)과 [로드맵](../../work/constitution/roadmap.md)이 새 구현 목표다.
원본·기존 결과는 덮지 않는다. 새 스키마는 새 migration과 runtime head/권한을 함께 검증한다.
외부 호출은 purpose/company/input hash가 고정된 건별 승인 뒤 공용 슬롯에서 수행한다.
운영 배포 없이 격리 인수하며 실제 18건/9건 성공을 별도로 증명한다.

## 위험과 대안
가장 큰 위험은 공고별 전역 최신 조회가 회사별 결과를 섞는 것이다. API와 worker의 읽기 범위 모두 검사한다.
독립 회사별 스택은 비교와 공동 원문 재사용에 불리하여 채택하지 않았다.
시연용 조작 결과는 실제 분석 요구를 만족하지 않으므로 채택하지 않았다.

## 개정 — 2026-10-11 DEMO-03 실제 인수 범위 재계획
