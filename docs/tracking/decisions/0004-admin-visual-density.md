# 관리자 화면의 여유형 RootLab 시각 체계

- 상태: 채택
- 일자: 2026-08-26

## 맥락

BidOps 관리자는 수십 건의 공고와 다섯 관점의 근거를 비교하면서도 긴 한글 제목, 미확인 값, 오류·차단 상태를 피로 없이 읽어야 한다. 기존 화면은 비교량을 우선한 고밀도 조작부와 외부 폰트 의존성을 사용해 화면 간 리듬과 입력 상태가 일관되지 않았다.

## 결정

RootLab의 짙은 초록 사이드바, 흰색 본문, 옅은 녹색·회색 바탕, 초록 주요 동작과 의미별 상태색을 유지한다. 공통 표면과 경계는 토큰으로 관리하고 8px 간격 단위, 카드 20~24px 안쪽 여백, 일반 조작부 40~44px 높이를 기본으로 하는 여유형 계층을 사용한다. Pretendard 로컬 파일을 기본 글꼴로 사용하고 숫자는 tabular 숫자, 식별자는 시스템 고정폭 글꼴로 정렬한다. 그림자는 팝오버와 알림에만 절제해 사용하며 그라데이션·유리 효과·네온·마케팅식 큰 빈 공간은 금지한다. 경고·오류·미확인·계산 불가·실제 0·등급·준비 상태는 서로 다른 문자와 표면으로 표시한다.

## 대안

참조 디자인의 마케팅식 여백을 그대로 적용하면 한 화면의 비교량이 크게 줄어 기각했다. 기존 고밀도 값을 그대로 두면 읽기와 조작 일관성이 떨어져 기각했다. 완전히 별도 팔레트를 만들거나 외부 폰트를 추가하면 기존 시각 정체성과 오프라인·시각 테스트 결정성을 잃어 기각했다.

## 결과

공통 컴포넌트 호출 의미와 업무 정보·검토 흐름 안전장치는 유지한다. 색만으로 등급·경고·마감·차단을 전달할 수 없으며 문자 라벨과 구조적 표시를 함께 둔다. 여유형 토큰은 정보 밀도를 없애는 규칙이 아니라 읽기·포커스·비활성·오류 상태의 최소 기준이다. 화면 변경은 `npm run build`와 로컬 폰트·외부 폰트 부재를 확인하고, 필요할 때 시각 검증에서 긴 제목·좁은 화면·null/0·계산 불가를 함께 확인한다.
