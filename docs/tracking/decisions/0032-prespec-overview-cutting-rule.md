# 사전규격 개요 검토 앞부분은 문서 구조에 따라 자르고 모호하면 사람 검토로 보낸다

- 상태: 채택
- 일자: 2026-08-31

## 맥락

[ADR-0031](0031-prespec-overview-review-stage.md)은 사전규격 개요 검토를 제안요청서
앞부분만 읽는 저비용 단계로 정했다. 그런데 [T-21 측정](../../validation-runs/20260831-prespec-rfp-structure.md)의
65건에서 목차 보유는 32%, 첫 소제목이 `사업개요`인 경우는 58%, `과업내용` 절 보유는
66%로 신호가 갈렸다. 첫 소제목 위치도 p50 32, p90 49, 최대 211 block으로 흩어져
고정된 block 수를 앞부분으로 볼 근거가 없다.

## 결정

**1. 본문과 대응하는 구조를 우선해 앞부분을 정한다.**

- 목차 항목이 본문 소제목과 대응하면 목차를 사용한다.
- 목차가 본문과 대응하지 않으면 의미 있는 주제 소제목을 사용한다.
- 번호 형식만으로 시작·종료 경계를 정하거나 절단하지 않는다.

자동 추출에 성공한 입력은 어떤 전략을 사용했는지(`strategy`), 시작·종료 위치
(`start_locator`, `end_locator`), 원문 식별 hash(`source_sha256`)를 보존한다.

**2. 경계가 모호하면 추측하지 않는다.**

시작 또는 종료 위치를 확정할 수 없으면 앞부분을 만들어 자동 판정하지 않고
`unknown`으로 남겨 사람 검토로 보낸다. 고정 block 수를 fallback으로 사용하지 않으며,
경계를 찾지 못했다는 이유로 전체 문서를 개요 검토에 자동 투입하지 않는다.

**3. 전체 문서 분석의 경계를 유지한다.**

전체 원문은 [ADR-0031](0031-prespec-overview-review-stage.md)이 정한 사람 승인 후
심층 검토 범위에서만 사용한다. 개요 검토는 구조로 확정한 앞부분만 입력으로 삼고,
절단 실패를 전체 문서 자동 분석으로 우회하지 않는다.

## 대안

**고정 block 수로 앞부분을 자르기 — 소거했다.**

문서마다 첫 소제목 위치가 크게 달라 짧은 문서에서는 범위를 넘고 긴 문서에서는
개요를 놓칠 수 있다. 측정된 위치 분포로는 하나의 block 수를 정할 수 없다.

**번호 형식만으로 경계를 정하기 — 소거했다.**

아라비아 번호 체계가 62%로 가장 많지만 모든 문서에 있지 않고, 번호가 있어도
본문의 의미 있는 개요 범위와 일치한다는 보장이 없다.

**경계 실패 시 전체 문서를 자동 투입 — 소거했다.**

잘못 자르는 위험은 피하지만 개요 검토의 저비용 목적을 깨고 입력 길이·비용·잘림
위험을 키운다. 불확실성을 `unknown`과 사람 검토로 드러내는 편이 안전하다.

## 결과

- 목차와 본문이 실제로 대응하는 문서는 목차를, 그렇지 않은 문서는 의미 있는 주제 소제목을 사용한다.
- 시작·종료가 불명확한 문서는 근거 없는 자동 판정을 만들지 않고 사람 검토로 보낸다.
- 자동 입력의 전략, 양 끝 locator, 원문 hash를 보존해 결과를 원문 버전에 되짚을 수 있다.
- T-23 구현은 이 절단 규칙을 따르며, REST·DB·파일 wire shape는 구현 계약 확정 시 별도로 정한다.
