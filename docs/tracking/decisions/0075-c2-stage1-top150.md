# C-2 1단계 절단을 BM25 상위 300건에서 150건으로 줄인다(정책 v6)

- 상태: 채택 — 구현·발행. 운영 DB 적재·게이트 측정·활성화 전이다. active는 v5다.
- 일자: 2026-11-18
- 근거 문서: [발주계획 선별(C-2) 수정안](../../1118_launch-hardening/발주계획-선별-수정안.md) §2·§3·§6
- 관련: [ADR-0037](0037-order-plan-c2-bm25-top300-qwen.md)(방식 선택, 대체하지 않음)·[ADR-0060](0060-c2-policy-db-row-authority.md)(행이 활성화 정본)·[ADR-0072](0072-c2-mac-litellm-ollama.md)(v5 묶음)

## 맥락

ADR-0037은 `BM25 Top 300 + Qwen`을 고정했고 300은 순위·병합 스크립트, worker, JSON schema에
상수로 들어가 있었다. 운영 14일(평일 평균 500건, 모델 판정 4,200건)에서 151~300위 판정은 모델
시간의 절반인데 모델 `관련`의 2.3%만 찾았다(201~300위는 1,400건 중 3건). 하루 평균 `관련` 49건,
`불확실` 46건이고 `불확실`의 gold 적중률은 9%다.

사람 정답 표본(gold adjudicated v3, 8월 4일치 625건, 관련 54건·높음 25건)을 v5 게이트 2차 pass
결과 행으로 다시 계산하면 다음과 같다(새 정책으로 모델을 돌린 값이 아니다).

| 방식 | recall | precision | 하루 최대 후보 | 높음 누락 |
|---|---:|---:|---:|---:|
| v5 (상위 300 + 모델) | 100% | 39.7% | 73 | 0 |
| **상위 150 + 모델** | 96.3% | 45.6% | 59 | 0 |
| 상위 100 + 모델 | 92.6% | 49.5% | 50 | 0 |

상위 150 밖으로 나가는 gold 관련 건은 2건(230위·259위)이고 둘 다 우선순위 `낮음`이다. 현재 게이트
임계(recall ≥ 90·precision ≥ 35·중요 누락 ≤ 3·하루 검토량 ≤ 80)를 계산상 모두 넘는다.

## 결정

1. **절단 값은 실행이 동결한 policy 파일의 `stage1.top_k`가 정한다.** binding
   `stage1_binding.top_k`와 같아야 하고 허용 값은 `{150, 300}`뿐이다. 순위 스크립트
   (`ALLOWED_TOP_K`)·병합 스크립트·worker·실행 생성·적재 CLI가 각자 검사하고, 어긋나면 모델 호출
   전에 기존 코드(`policy_binding_mismatch`·`binding_invalid`·`binding_mismatch`, 적재 CLI는
   `policy_top_k_invalid`·`binding_top_k_mismatch`)로 멈춘다. 모집단이 `top_k` 이하이면 전부 판정한다.
   점수 하한 같은 새 1단계 키는 두지 않는다(수정안 §5).
2. **정책 v6를 새 immutable 파일로 발행한다.** `order-plan-screening-policy.v6.json`
   (`c2-order-plan-screening-v6`, sha256 `57366b04f952afa6b7678f722e0eaa41a133eeaf1f5623d24024bbd59608de28`)은
   v5와 `policy_version`·`created_at`·`stage1.top_k`만 다르다. `order-plan-screening-phase0-binding.v6.json`
   (sha256 `ad583ce21ba8f834d5ae74e1d5014ec7cd9fbbdac74fa18c7cdbdabb43ded4dc`)은 v5와 `binding_version`·
   `created_at`·`policy` 참조·`stage1_binding.top_k`·`external_transport.decision_note`만 다르다.
   BM25 설정(`bm25.json`은 `top_k`를 담지 않는다)·프롬프트·모델 digest·generation config v6·회사 역량·
   배치 25·재시도 2·감사 표본 값·review-inputs manifest는 그대로다. 전송 승인은 v5 binding의 승인
   (2026-10-14 jechoi, ADR-0072)을 옮긴 것이고 payload·모델·endpoint가 같다는 점을 note에 적었다 —
   v6 적재 직전에 사람 확인을 받는다. v1~v5 파일과 v5 실행 기록은 바꾸지 않는다.
3. **파일은 DB 행마다 digest로 찾는다.** `mounted_files`는 `BIDOPS_C2_POLICY_PATH`·`BIDOPS_C2_BINDING_PATH`
   (기본값을 v6 파일로 올렸다)를 먼저 보고, bytes digest가 행과 다르면 같은 디렉터리의
   `order-plan-screening-policy.v*.json`·`order-plan-screening-phase0-binding.v*.json`에서 같은 digest의 일반
   파일을 찾는다. compose는 web·analysis-worker에 v5와 v6를 함께 마운트한다. 그래서 v5가 active인 채로
   v6를 적재·후보 지정·게이트 측정·활성화하고 일일 스위치를 옮기는 동안 경로 변경·재시작이 필요 없다
   (순서는 [운영 절차](../../operations/daily.md#v5-active에서-v6로-교체-adr-0075)).
4. **누적 목록은 `실패` 운영 실행의 결과 행도 읽는다.** 모델이 한 건도 답하지 못한 날도 merge는 전
   모집단 행(BM25 순위·점수, 2단계 `failed`)을 게시하고 실행은 `실패`로 끝난다. 같은 발주계획에
   `성공|부분 성공` 결과가 있으면 시각과 무관하게 그쪽이 이긴다. 판정 유무(`policy_versions`)·워크로드
   `null` 사유는 완료 실행만 센다. 응답 schema(`order-plan-list-response.v5`)와 field 뜻은 그대로다.
5. ADR-0037의 방식(BM25 → Qwen, 탈락은 `filtered_out`, hosted fallback 없음)은 유지하고 값만 바꾼다.
   migration은 없다.

## 하지 않은 것

- Phase 0 JSON schema(`skills/bidops-screen/contracts/bidops.order-plan-screening-policy.v1.json`·
  `…-phase0-binding.v1.json`의 `top_k: {const: 300}`)는 고치지 않았다. contract index와
  `validate_order_plan_phase0.py`가 schema 파일 sha256을 고정하고, v2 파일만 검증하며, 이미 v5의 Ollama
  provider도 받지 않는 Phase 0 동결 문서다. 런타임 검증은 순위 스크립트·worker가 한다.
- BM25 방식·토큰화·회사 역량 문장, 게이트 임계값·감사 표본 값, 프롬프트·모델, gold 확장.
- 실행 생성 시점의 1단계 계산(수정안 §5의 2단계).

## 한계

- 표의 recall 96.3%는 8월 평일 2일·관련 54건 표본의 재계산값이다. 품질 근거는 같은 gold v3로 v6를
  두 pass 측정해 게이트를 통과한 뒤에만 생긴다. 그 전에는 v6를 품질 근거나 활성 정책으로 적지 않는다.
- 운영 규모의 근거는 모델 판정 기준이다. 151위 밖의 사람 기준 누락은 감사 표본(실행당 10건, 창
  151~175위)으로만 계속 본다.
- 디렉터리 해석은 digest가 같으면 어느 파일이든 같은 승인 bytes라는 전제에 선다. 다른 디렉터리·
  symlink·이름 규칙 밖 파일은 보지 않는다.
