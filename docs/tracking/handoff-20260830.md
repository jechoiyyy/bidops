## T-20을 시작할 때 알아야 할 것

**다운로드는 수집기가 한다.** 웹 계층에 egress를 여는 대안은 별도 보안 결정이다.
`docker-compose.t7.yml:145`에서 `document-worker`가 `network_mode: none`이고
모든 network가 `internal: true`다. 반면 수집기는 `docker-compose.t7.screening.yml`로
이미 나라장터 egress와 API 키를 갖는다.

**스캔 통과 전에는 변환·파싱·제공하지 않는다** (`docs/security.md:56`).
회차 디렉터리에 내려받은 바이트는 quarantine → ClamAV → content object를 거쳐야 한다.
scanner 오류·timeout·미확인은 clean이 아니다.

T-4가 `attachments`에 URL까지 담아 놓았다(`specDocFileUrl1~5`, 650건 중 586건이 최소 하나).
실제 파일을 받는 것이 T-20이다.

## 아직 정하지 못한 것

**앞부분을 어디까지 자를지** — 소제목이 문서마다 다르고(`추진배경`·`사업개요`·`용역개요`·
`추진목표`·`과업내용`) 목차가 있는 문서와 없는 문서가 섞여 있다. T-21에서 표본으로 세고
T-22에서 정한다. 지금 정해진 것은 하나다: **규칙에 맞지 않는 문서는 추측해서 자르지 않고
`unknown`으로 사람에게 보낸다.** 잘못 자른 앞부분으로 "우리와 안 맞는 사업"이라는 판정이
나오는 것이 가장 나쁜 결과다.

**판정의 모델 계보** — ADR-0030이 mock 판정을 화면에 표시하기로 했으나 `Judgment`에
모델 계보가 없다. `ScreeningAttempt.model_digest`는 런타임 쪽에 있고 FK로 이어져 있지 않다.
어느 쪽을 정본으로 볼지가 T-19의 결정 사항이다.
