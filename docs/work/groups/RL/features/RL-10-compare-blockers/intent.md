# 결정적 대조의 차단 조건 (상주 장소·제외 분야)

2026-11-19, launch-hardening [설계고도화안](../../../../../specs/1118_launch-hardening/설계고도화안.md) §4 D-1. RL-05 인수(정책 v11, 회사 근거 v4)에서 차단 조건 7개를 모두 놓쳤다(대구 밖 상주 5, 회사 제외 분야 HW 2). D-2 분해(`docs/validation-runs/20261119-rl05-unknown-breakdown/README.md`, git 이력)는 대조 단계가 `gap`을 하나도 내지 못한 것이 직접 원인이고, 원문 그대로의 이상적 제약을 넣어도 지금 대조기는 `gap`을 낼 경로가 없다고 보였다.

| 유즈케이스 | 기대 | 확인 |
|---|---|---|
| 상주 장소가 회사의 상주 가능 지역 밖 | 사람이 확인한 구조화 값(상주 가능 시·도 전체 목록)과 겹치지 않을 때만 `gap` | 단위 테스트, D-2 탐침 재생 |
| 상주 장소를 결정적으로 알 수 없음 | `unknown`(`place_unresolved`), 추정하지 않음 | 단위 테스트 |
| 요구사항이 확인된 제외 분야에 온전히 속함 | 사람이 적은 요구사항 수준 용어로만 연결, 모든 절이 속할 때만 `gap` | 단위 테스트, 탐침, 과잉 차단 스캔 |
| 일부만 제외 분야 | `unknown`(`exclusion_partial`), `met`도 막음 | 단위 테스트 |
| v11 이하 결과 재현 | 대조 규칙 v1을 그대로 유지 | 기존 테스트, resume 재계산 |

선행: RL-03(대조기·정책 계보), RL-00(회사 근거 계약). 모델 호출·회사 사실 추정은 범위 밖이다. 회사 근거 v4에는 이 규칙이 읽을 구조화 값이 없으므로 코드만으로는 운영 결과가 바뀌지 않는다 — 값은 사람이 확인해 새 회사 근거 버전으로 등록해야 한다. 종단 판정 품질은 같은 gold 재측정(Luna 전송, 사용자 승인 대상)으로만 증명된다.
