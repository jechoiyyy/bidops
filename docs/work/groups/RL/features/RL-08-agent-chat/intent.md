# 공고별 Agent chat — intent

- 기능 ID: `RL-08-agent-chat`
- 상위 항목: RL — 루트랩 실회사 기준 AX 과제. 별도 기능 추가를 사용자와 확정(2026-10-21); 로드맵 반영은 인터뷰 완료 뒤 진행.
- 크기: L — 대화 저장·근거 조회·모델 입력/출력·REST·화면에 새 계약이 필요하다.
- 작성일: 2026-10-21
- 상태: 인터뷰 중인 초안. spec·plan·큐 등록·독립 검사는 아직 수행하지 않았다.

## 문제

사용자가 특정 공고의 기본정보·판정·심층 검토 결과를 확인하면서 궁금한 점을 자연어로 질문할 경로가 없다. 저장된 자료와 분석 결과가 있어도 화면과 원문을 직접 찾아 대조해야 한다.

## 기대 결과

발주계획·사전규격·입찰공고에 대해 기존 자료를 조회·해석하고 근거와 함께 답변한다. 사용자는 별도 기능 RL-08, 세 유형 지원, 읽기 중심 답변을 선택했다. 화면 위치·대화 이력·원문 조회 범위는 아직 선택 대기다.

## 유즈케이스

아래 질문은 범위를 설명하기 위한 예시이며 실제 인수 질문은 인터뷰에서 보완한다. 화면 진입점은 선택 후 고정한다.

|---|---|---|

| 공고 조건 확인 | 대상 공고의 채팅에서 자격·예산·일정 질문 | 실제 존재하는 자료를 인용하며 자료가 없으면 확인 불가를 표시한다 |

| 상태 변경 요청 | 채팅에서 추적·재판정·Go/No-Go 변경을 요청 | 이번 기능은 해당 업무 조작을 실행하지 않고 기존 자료 기반 답변 범위를 안내한다 |

## 선행·후속 기능

- 선행 후보(인터뷰·설계 완료 시 확정): `RL-00-company-ground-truth`, `RL-02-opportunity-timeline`, `RL-03-fit-verdict`. 2026-10-21 queue 조회에서 모두 존재함을 확인했다. 제안서 결과를 직접 참조하기로 정하면 `RL-04-proposal-draft`도 의존 범위와 대조한다.
- 후속: 없음. 다른 공고 비교·외부 검색·업무 실행의 포함 여부를 임의로 확정하지 않는다.
- 새 기능은 아직 큐에 등록하지 않았다. 기존 큐 순서·의존은 바꾸지 않았다.

## 영향 범위

- 모듈·컴포넌트: lifecycle의 공고 identity·확정 연결, screening의 읽기 projection, deep_review의 문서·분석·회사 근거와 모델 실행, frontend 공고 상세/사업기회 레코드.
- 큰 틀 문서의 절: roadmap RL 표, ARCHITECTURE §4.2·§6~9, contracts 공통 REST·식별자, business-rules “근거와 검증”, ui-spec §4.3·4.4. 구체 수정안은 선택 결과를 반영한다.
- 데이터·저장소: PostgreSQL·versioned MinIO 기존 기반. 대화 저장 단위와 보존 정책은 미확정이다.
- 외부 서비스·호출: RL 기준 codex-exec gpt-6-luna/high, 기존 공용 분석 슬롯 1개, 목적에 맞는 별도 승인 정책·건별 감사가 필요하다. 이번 문서 작업에서는 외부 호출하지 않는다.

## 제약

- 원문·프로필·정책·모델 입력과 결과·사람 리뷰는 불변/append-only로 보존한다.
- unknown/null·적합성·참여 준비·추적·Go/No-Go를 서로 대신하지 않는다.
- 외부 모델 전송은 정책 단위 사전 승인으로 자동화하되 건별 감사·payload 동결·allowlist·hosted fallback 금지를 유지한다(ADR-0073). 기존 "건별 전송" 문구는 이 규칙으로 읽는다.
- 외부 모델은 승인 payload만 건별 전송하며 전역 fallback과 자동 추적 결정을 금지한다.
- PostgreSQL 17·versioned MinIO·합성 analysis worker의 슬롯 1개와 모듈 의존 방향을 유지한다.
- 문서 변경은 diff/문서 검사만, 제품 변경은 직접 영향 검사만 실행하고 성공 후 반복하지 않는다.
- 운영 변경·실제 모델 호출은 직전 확인 대상이며 문서화 승인을 실행 승인으로 사용하지 않는다.
- HWP/HWPX 원본이 입력 정본이며 PDF는 PDF 전용 첨부와 쪽 locator에만 쓴다. OCR은 범위 밖이다(ADR-0071·0073).
- 새 DB 테이블·열 권한은 scripts/runtime-privileges.sql에 등록하고 migration에 GRANT를 쓰지 않는다.
- 사용자 요청 없이 commit·merge·push·브랜치 삭제하지 않는다.
- RL 기능은 main에서 분기한 브랜치와 bidops-local 격리 자원에서 구현·검증하며 운영 전환은 별도 작업이다(ADR-0073).
- RL의 모델 호출은 codex-exec gpt-6-luna/high 하나다. LiteLLM local-agent-main·Qwen·Terra를 쓰지 않고 기존 정책 파일·실행 row는 바꾸지 않는다(ADR-0071·0073).
- 회사는 실회사 루트랩 1곳이다. 확인된 사실(confirmed)·제안값(proposed)·미확인(unknown)을 분리하고 proposed와 unknown을 차단 조건으로 쓰지 않는다(ADR-0073).
- 기존 분석의 품질 인수는 RL-05 reject이며, 채팅 제공으로 품질 합격이 되지 않는다.
- 특정 공고에 데이터가 존재한다는 전제와 모든 공고에 같은 데이터가 존재한다는 가정을 구분한다. 입찰공고의 첨부 취득 경로는 현재 사전규격과 같지 않다.
- 기존 회사·공고 원문·판정·심층 결과·사람 결정은 읽기 대상으로 보존한다.
- 로그인 없는 현재 사내망 경계를 개인 비공개 대화 권한으로 표현하지 않는다.
