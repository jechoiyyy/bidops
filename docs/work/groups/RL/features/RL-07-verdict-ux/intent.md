# 판정 탭 실무자 화면 개선(프런트엔드 1차) — intent

- 기능 ID: `RL-07-verdict-ux`
- 상위 항목: roadmap §RL 표(RL-07 행, 2026-10-20 추가), [HP 공통 계약 §8](../../../../hp-contract.md#8-실무자-판정-화면-확정-구성-세부는-hp-04)(판정 화면 5블록), [RL 화면 명세 §4.4](../../../../../1016_rootlab-redefinition/ui-spec.md)
- 크기: M — 프런트엔드 판정 탭·대조표·원문 패널·좌측 요약·브리핑 링크 6~8개 파일, 새 REST·DB·서버 계약 없음, 외부 호출 없음
- 작성일: 2026-10-20

## 문제

RL-05 실제 10건(정책 v11) 화면을 독립 UX 검토(2026-10-20, fable)한 결과, 판정 탭은 ui-spec대로 그려지지만 실무자가 5초 안에 "무엇부터 확인할지"를 뽑아내기 어렵다. HP 계약 §8이 확정한 5블록 중 **주의 포인트**(서버 `result.cautions`·`conflicts`)가 화면에 없고, 코드가 붙인 "사람 확인" 다음 행동이 같은 문장으로 6~19번 반복되며, 검증 실패 목록과 대조표가 서로를 가리키지 못한다. 회사 사실이 연결되지 않은 행의 "회사 근거" 열은 내부 시스템 문장(대부분 영어)으로 차 있고, 쪽 위치가 없으면 "원문" 열 전체가 "쪽 미확인"이며, 1280px에서 원문 패널을 열면 표가 잘린다.

## 기대 결과

사업기회 레코드 판정 탭(`/opportunities/:id/verdict`)에서 실무자가 판정 아래 한 줄 요약(차단·주의·사람 확인 수)과 주의 포인트를 먼저 보고, 주의·검증 실패 항목에서 해당 요구사항 행으로 바로 이동한다. 반복·내부 문장은 접히거나 고정 문구로 바뀌고(원문 패널에서는 서버 문장을 그대로 볼 수 있음), 1280·1440 두 폭에서 표가 잘리지 않는다. 서버 응답·판정 값·계약은 바뀌지 않는다.

## 유즈케이스

| 유즈케이스 | 실행 방법(명령·화면·API) | 확인 기준 |
|---|---|---|
| 주의 포인트 확인 | 판정 탭(완료 판정) 중앙 표 위 "주의 n" 블록 | 서버 `cautions` 문장과 `conflicts`(역할 의견 불일치)가 항목마다 요구사항 문장과 함께 보이고 "요구사항 보기"를 누르면 그 표 행이 선택·스크롤된다. 0건이면 블록이 없다 |
| 한 줄 요약으로 우선순위 파악 | 좌측 판정 이름 아래 | "차단 a · 주의 b · 사람 확인 c"(서버 값 집계)가 보이고 주의·사람 확인 숫자를 누르면 해당 블록으로 이동한다(차단은 글자) |
| 반복 "사람 확인" 정리 | 좌측 다음 행동 | 모델 다음 행동은 그대로, 코드 행(`origin="code"`)은 "사람 확인 n건" 한 줄로 묶이고 펼치면 코드 행 문장과 "검증 실패 목록으로"·"누락 영역으로" 버튼(해당하는 것만)이 보인다 |
| 검증 실패 항목 추적 | 중앙 "검증 실패 — 사람 확인 필요" 목록 항목의 "요구사항 보기" | 필터 밖이면 필터를 풀고 해당 표 행이 선택되며, 표의 격리 행에는 목록과 같은 번호(카드 번호 또는 "격리 항목 k")가 보인다. 4건 이상이면 3건만 보이고 "n건 더 보기" |
| 회사 사실 미연결 행 읽기 | 대조표 "회사 근거" 열, 행 선택 → 원문 패널 | 확인 필요이면서 연결된 회사 사실이 없는 행은 "연결된 회사 사실 없음"으로 보이고, 원문 패널에 역할 의견 문장 전문이 서버 값 그대로 보인다 |
| 쪽 위치가 없는 판정 | 모든 행의 쪽이 미확인인 판정 | "원문" 열이 숨고 표 위 안내 한 줄이 보인다. 한 행이라도 쪽이 있으면 열은 그대로다 |
| 전부 확인 필요 안내 | 완료 판정에서 모든 행이 확인 필요이고 회사 사실과 연결된 행이 없음 | 판정 아래에 근본 원인 안내(회사 근거와 연결되지 않음 → 회사 근거 화면 링크)가 보인다 |
| 노트북 폭에서 원문 패널 | 1280×800에서 행 선택 | 표가 잘리거나 페이지 가로 스크롤이 생기지 않는다(1440×900도 동일) |
| 브리핑에서 판정으로 | `/briefing`에서 판정이 있는 항목(판정 이름 4값·"사전규격 판정 참조") 열기 | 판정 탭으로 바로 간다 |
| 작은 정리 | 체크리스트·상태 필터·필수 표기 | 체크리스트가 모두 같은 상태면 한 줄로 접히고, 표 행 상태가 한 종류면 상태 필터가 사라지며(전체 표시), 필수 여부를 모르는 행은 "필수 여부 미표기"로 보인다(독립 UX 검토 개선 권고) |

## 제약

- (공통) `feature.json` constraints 13개 그대로. 특히 문서 변경은 diff 검사만, 제품 변경은 직접 영향 검사만, commit·merge는 사용자 요청 시.
- (기능별) 화면은 판정·체크리스트·대조 상태·차단 조건을 **다시 계산하지 않는다**(ui-spec §4.4 RL-03 구현 기준). 허용되는 것은 서버 값의 개수 세기·묶어 보이기·접기·정렬 유지뿐이다.
- (기능별) 모델·서버 문장을 고치거나 다른 문장으로 바꿔 쓰지 않는다. 표에서 고정 문구로 대신 보여도 원문 패널에서 서버 문장을 그대로 볼 수 있어야 한다.
- (기능별) unit id(원문 hash 포함)·정책 id·모델명·해시·`unmeasured_reference`는 실무 화면 DOM에 쓰지 않는다(기존 금지 검사 유지).
- (기능별) 테마 토큰만, 데스크톱 전용 1280~1920px, 화면 검증 1280×800·1440×900(ADR-0047·0048). `unknown`에 error 색을 쓰지 않는다.

## 범위 밖

- 서버·데이터: 역할 의견 문장의 영어·내부 코드(`unmapped` 등) 유입(프롬프트·검증), 쪽 위치(`page_range`·`mapping_status`) 매핑 실패, 결정적 대조 범위(findings 2026-10-20), 브리핑 서버 `record_path` 변경 → 이 기능 완료 뒤 재검토.
- "원문 탭에서 찾기" 같은 새 원문 열람 화면(원문 탭은 현재 사전규격 링크 빈 화면).
- 판정 상태(pending·failed 등) 화면·다시 판정·오류 제보 대화상자의 동작 변경.
