# 실제 사전규격 엔진 분석과 상세 검토

- 기능 ID `RL-11-live-prespec-engine`
- 상위 목표 [루트랩 G2](../../../../constitution/mission.md)와 [실사용 전 설계 고도화](../../../../../specs/1118_launch-hardening/설계고도화안.md)
- 2026-11-20 사용자 요청. 외부 모델·새 실행 계약·상세 화면을 포함하는 L 작업

## 문제와 기대 결과

RL-09는 `bid-deep-agent` 코어와 저장·조회·mock 화면을 연결했다. 실제 분석은 요청할 수 없고, 현행 상세의 참여 판정은 RL 카드 요약을 읽는다. 담당자가 실제 사전규격의 참여 조건, 요구사항 대응, 회사 확인이 필요한 항목, 원문 근거를 한 화면에서 검토할 수 있게 한다. 엔진의 회사 입력은 원본 `bid-deep-agent`가 준비한 루트랩 회사 자료 묶음(프로필·실적·출처 등급·회사 위키) 전체이며, 공고마다 엔진이 위키에서 관련 페이지를 골라 쓴다(2026-11-22 개정, [회사 입력 기준](company-wiki-mapping.md)).

| 유즈케이스 | 실행 방법 | 확인 기준 |
|---|---|---|
| 회사 자료·위키 확인 | 회사 자료 묶음의 검사(lint)와 공고별 위키 선택 미리보기 확인 | 묶음이 원본 로더 검증을 통과하고, 공고마다 고른 유형·페이지가 결과에 남는다. 값이 `unknown`인 항목은 회사 사실로 채택되지 않는다. |
| 실제 사전규격 분석 | 대시보드 승인 대기 → 자동 생성한 전송 미리보기 확인 → 건별 승인 | 승인한 버전과 전송 내용이 일치한다. 성공·부분·실패와 건별 감사를 남긴다. |
| 참여 조건 확인 | 상세에서 차단·미확인 항목을 먼저 읽고 근거 열기 | 회사 근거와 공고 조항·표·쪽을 대조해 사람이 추적을 결정할 수 있다. |
| 결과 비교 | 같은 고정 사전규격과 회사 근거로 RL 카드와 엔진을 비교 | 근거 검증과 차단 조건을 동일 기준으로 본 뒤 상세의 기본 표시를 사람이 승인한다. |

## 선행과 후속

- 선행 `RL-09-engine-integration`, `RL-10-compare-blockers`. 기존 RL-05 gold 및 채점 계약은 비교의 증거이며, 기존 reject를 보존한다. [현재 로드맵](../../../../constitution/roadmap.md)
- 후속은 실사용 상세 적용 승인과 소수 담당자 인수다. 기존 대량 브리핑 트리거, 제안서 소비 계약, 입찰공고 delta, SSO는 별도 범위다.
- 발주계획과 독립적으로 발견한 사전규격까지 자동 준비한다. 개요 실패 우회·원문 동결·승인·검토의 조건은 [최종 명세](spec.md)에 따른다. 사전규격 개요 시운전은 별도 운영 작업이다. 개요는 사람이 먼저 읽는 요약에서 유지하며 엔진의 원문 입력을 대체하지 않는다.

## 유지할 경계

BidOps가 공고, 회사 근거, PostgreSQL, MinIO, 공용 분석 작업 슬롯, 추적과 최종 결정을 소유한다. [공통 제약과 출처](../../../../feature.json) 및 [기준선 기록](../../../../source-baseline.json)을 따른다. 엔진의 실제 호출은 기존 RL의 Luna/high만 사용하고 새 경로에는 사용자가 요청한 건별 승인을 요구한다. 기존 RL 카드 전송 경로에 주어진 승인과 결과는 보존한다.

| 확인할 결정 | 필요한 시점 |
|---|---|
| 하드웨어 제외 업무 표현과 SW 부수·혼합 과업의 예외 | 2026-11-20 확인. 새 회사 버전은 근거 및 규칙 검증 뒤 별도 등록. [매핑안](company-wiki-mapping.md) |
| 호출당 토큰 예산·보존 기준(시운전 호출 수는 하루 1개 공고·하루 및 공고당 최대 8회로 확정). 실적 대응표·문장별 발췌 목록은 2026-11-22 개정으로 만들지 않는다 | 실제 전송 승인 전 |
| 비교 결과의 상세 기본 표시와 중단 기준 | 사람 채점·인수 결과 확정 후, 실제 사용자에게 표시하기 전 |
