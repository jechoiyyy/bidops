# 사전규격 상세 화면 설계안

실무자가 첫 화면에서 **의견 마감이 언제인지, 참여를 막는 조건이 있는지, 어떤 근거를 누구에게 확인할지** 파악하는 것을 목표로 한다. 전제는 실제 엔진 분석과 사람 인수가 끝난 상태다. 현재 상세의 개요·첨부·추적 기능과 [운영 셸](../../../../../tracking/decisions/0076-kstyle-panel-shell.md)을 이어 쓴다.

## 분석 완료 화면 시안

[세 시안 비교](mockups/after-analysis/index.html)는 같은 예시 원문·회사 근거를 사용한다. 구현 권장안은 **A 판단 브리핑**에서 차단·미확인과 다음 행동을 먼저 읽고, 항목을 선택하면 **B 근거 대조**처럼 조항·회사 자료를 나란히 여는 방식이다. **C 후속 업무**는 계속 추적 중인 공고를 다시 열 때 지금 확인할 일과 본공고 대기를 구분하는 참고안이다. 최종 배치는 담당자 인수에서 결정한다. 시안은 예시 데이터로 화면 행동을 확인한 자료다. ## 대시보드와 상세 진입

업무함을 ‘분석 승인 대기’, ‘조치 필요’, ‘결과 확인’ 세 목록으로 제공한다. 기본 행은 공고 제목·의견 마감·지금 할 이유·추적 상태다. 건수를 누르면 같은 조건의 전체 목록, 행을 누르면 같은 사전규격 상세의 해당 위치로 간다. 예외는 원본 보완·영향 있는 연결 확인 등 담당자가 취할 행동이 있을 때만 올린다. 시스템 복구 대기·일일 한도 대기는 운영 상태로 표시한다. 결과 확인은 미확인 결과 버전만 센다. 미추적·마감 전으로만 제한하는 현행 개요 업무량과 조회 조건을 혼용하지 않는다.

미확인 질문마다 ‘지금 확인’ 또는 ‘자료 대기’를 표시한다. ‘지금 확인’은 업무함에서 해당 질문으로 바로 열고, ‘자료 대기’에는 기다리는 자료(예: 본공고의 상주 조항)를 적는다. 새 근거가 도착했을 때는 업무함에 다시 올라온 이유와 바뀐 조항을 함께 보여준다.

## 상세 첫 화면과 근거 열기

아래는 배치 예시다. 실제 데이터에서 분석 전과 검토 결과 해당 없음은 구별한다.

```text
1440 × 900   목록으로   사전규격 제목                         현재 추적 상태
             발주처 · 공고번호 · 의견 마감 일시(KST) · 예산
             지금 할 일   [결과 확인]           개요 ▸   원문·첨부 ▸
             차단 조건                         미확인 사항
             필수 상주 장소 / 회사 제한         지정 장소 확인 / 확인할 자료
             ──────────────────────────────────────────────────────
             요구사항 대응표                     │ 선택한 행의 원문
             요구 ID · 필수 · 대응 · 근거 열기    │ 파일 버전 · 5쪽 / 절·문단
             …                                  │ 표 머리 · 선택 셀 · 인용
                                                │ 확인한 회사 사실 · 유효기간
```

```text
1280 × 800   목록으로   사전규격 제목                         현재 추적 상태
             발주처 · 의견 마감 일시(KST)       지금 할 일 [승인 자료 확인]
             차단 조건                         미확인 사항
             가장 중요한 조건과 근거            질문과 확인할 자료
             ──────────────────────────────────────────────────────
             요구사항 대응표 · 전체 폭
             요구 ID/제목        필수 여부       회사 대응         원문 열기
             → 열면 오른쪽 서랍에 문단/표와 회사 근거, 닫으면 같은 행
```

- 헤더에 의견 마감을 한 번 표시한다. ‘지금 할 일’에는 단계에 맞는 조치 하나를 둔다. 승인 대기에서는 전송 자료 확인, 결과 확인 중에는 읽음 기록과 추적 결정을 순서대로 제공한다. 추적 결정 없이 읽음만 저장할 수 있고, 마감 경과 미추적 공고는 기존 수동 추적 동작으로 다시 열 수 있다.
- 차단과 미확인은 영향이 큰 항목을 각각 최대 3개까지 먼저 표시한다. 나머지는 같은 영역을 펼친다. 요구사항 대응표는 요약 바로 아래 본문이며 별도 탭 전환 없이 첫 행에 접근한다. 개요는 접어서 한 곳에 두고, 개요 우회 때는 승인 영역에 사유와 보낼 원문 범위를 표시한다. 입력 정정 시 이전 결과는 날짜·버전이 붙은 이력에서만 연다.
- **참여 조건**은 차단 → 확인 필요 → 충족 순을 기본으로 한다. 행은 공고 조건, 회사의 확인된 사실 또는 미확인 사유, 근거 열기 순으로 읽는다. 법적 자격과 루트랩의 사업 제한을 표시명으로 구분하고, 공동수급·유효기간·지역 예외를 원문과 함께 확인한다.
- **요구사항 대응**은 요구사항 ID·제목, 필수 여부, 대응 상태, 루트랩 근거를 보여 준다. 부족·미확인을 빠르게 좁힐 수 있고, 과거 실적을 쓰는 행은 확인된 역할·범위와 시행 시점을 펼칠 수 있다. 선택한 행의 인용은 오른쪽 원문과 연결한다.
- **계속 추적 후에도 남는 질문.** 예를 들어 ‘근무 장소 미확인’에는 ‘상시 상주가 필수인가? 장소는 어디인가?’와 ‘대구 외 상주가 필수이면 회사 수행 제한과 충돌’을 함께 표시한다. 담당자가 계속 추적을 저장하고 다시 열어도 같은 항목에서 원문 조항과 회사 기준을 확인할 수 있다.
- **확인 필요**에는 확인할 질문, 이 판단이 영향을 주는 조건, 공고 근거, 확인할 자료 또는 행동을 표시한다. 행별로 회사 자료 확인과 발주 문구 확인을 구분한다. 사람이 남긴 확인 기록은 분석 결과와 함께 읽을 수 있게 하고, 기존 원문과 엔진 판정은 보존한다.
- 확인 질문의 기본 저장 동작은 **이 공고에서 확인 완료**다. 발주처 답변은 해당 조항에, 인력 가용성은 해당 공고의 투입 기간에 연결해 보여준다. 재사용 가능한 회사 증빙에는 별도 **회사 근거로 등록** 동작을 제공하고 등록할 사실·범위·유효기간을 보여준다.
- **원문·첨부**는 분석에 쓰인 파일과 쪽 범위, 준비 상태·빠진 파일, 원본 열기를 제공한다. 원문 HWP/HWPX에서 쪽을 확정하지 못하면 절·표·셀을 보여 준다. 근거가 여러 위치에 있으면 후보를 함께 보여 준다.

## 두 화면 폭과 문서 대조

1440×900에서는 근거를 열면 본문 오른쪽에 한 패널로 나란히 보여 준다. 본문을 읽다가 인용→원문→회사 근거를 확인해도 행·탭·스크롤 상태를 유지한다. 1280×800에서는 기본 폭을 업무 레코드에 주고, 근거를 열 때 오른쪽 패널을 펼친다. 키보드에서 근거 버튼으로 열고 Esc·닫기로 나올 수 있으며 원래 행으로 초점을 되돌린다. 닫힌 상태에서도 원문 열기 단추와 상태 텍스트를 쓸 수 있다. 색은 승인 토큰을 사용하고 상태는 문구로도 전한다.

## 상태별 표시

| 상황 | 담당자가 보는 것 |
|---|---|
| 미시작·대기·실행 중 | 준비 중인 문서 또는 분석 상태와 다음 행동. 완료된 과거 결과가 있다면 “이전 입력 기준”을 붙인다. |
| 최신 실행 완료 | 사람이 승인한 표시 경로의 현재 결과와 확인할 항목. 범위·공고 문서·회사 근거 확인일을 같이 본다. |
| 부분·실패 | 어떤 절·첨부가 빠졌는지, 확인된 근거는 무엇인지, 어디부터 다시 확인할지. 오류는 간단한 업무 문장으로 안내한다. |
| 문서·회사 근거 변경 | 이전 판정을 이력으로 내리고 새 문서나 회사 근거를 다시 확인하도록 안내한다. |
| 두 경로 비교 중 | 승인된 검증자 뷰에서 RL 카드와 엔진 결과를 같은 조건·요구 ID로 나란히 본다. 실무 상세의 기본 탭에는 사람 인수된 한 경로의 현재 결과를 둔다. |

## 실무 화면 정보 감사

main의 PreSpecDetailPage.tsx에서 추적 컨트롤, 개요 본문·주장별 근거, 문서 준비 진행 단계와 취득 집계, 상시 OrderPlanCandidatesSection, 실행 정보, 맨 아래 RL 참여 판정·회사 적합성 순서를 대조했다. 현재 아래로 밀린 참여 조건은 상단으로 올리고, 상시 후보 영역은 영향이 있는 연결 예외에서만 연다. 실행 ID·해시·토큰·모델 설정은 운영 진단 경로에서 다룬다. 현재 담당자 이름은 감사 표식이며 진단 탭 숨김은 접근 제어를 제공하지 않는다.


| 현행 또는 엔진 출력 | 제안 | 이유 |
|---|---|---|
| 첨부 취득·변환·개요의 단계별 카드와 배지 | 상단에는 현재 처리 상태 한 줄. 첨부별 준비 상태와 실패 조치는 원문·첨부에 모은다. | 같은 진행 상황을 여러 곳에서 읽을 필요가 없다. |
| 참여 판정/RL/엔진 mock/RL 비교 결과 | 기본 화면에는 채택된 결과 하나를 사용한다. 비교·mock은 검증 뷰 또는 운영 실행 이력에 둔다. | 업무 화면의 기본 결과가 어떤 경로에서 나왔는지 명확해진다. |
| 미확인 사유 코드, 위치 enum, 긴 실행 UUID·hash, 정책 파일·프로필 ID, 모델 파라미터·토큰·비용, 원응답 | 권한과 보존 정책에 맞는 운영 진단에서 다룬다. | 실무 화면에 필요한 정보는 영향, 문서 버전, 사람이 할 행동이다. |
| 종합 점수 범위·역할별 토론·회사 위키 전문 | 확인 가능한 조건·사실·원문과 그 공고에 고른 위키 페이지(엔진 선택 결과)를 보여 준다. | 점수와 위키의 설명은 참여 조건의 증빙을 대체할 수 없다. |
| 의견 마감·예산·보고 근거·차단·미확인·회사 사실의 유효기간 | 업무 표면에 두고, 실패 시 해당 조건과 조치에 연결한다. | 담당자가 추적 결정과 발주 문서 검토에 직접 쓴다. |
| 추적·최종 Go/No-Go·분석 실행의 버튼 | 건별 전송 승인과 결과 확인·추적은 현재 단계의 행동 영역, 최종 Go/No-Go는 입찰공고 이후 기존 화면에 둔다. | 같은 공고에서 사람이 내리는 결정의 의미와 시점이 다르다. |

### 담당자 인수 시나리오

실제 공고 하나에서 첫 화면으로 차단 및 미확인 항목을 구별하고, 조건에서 원문과 회사 근거를 찾고, 목록으로 복귀할 때 선택과 필터를 복원할 수 있어야 한다. 두 번째 사례에서는 장문·부분 결과의 빠진 문서가 보이고, 다시 확인할 행동을 찾을 수 있어야 한다. 문서가 정정된 사례에서는 이전 결과를 이력에서 확인한다. 1280×800과 1440×900에서 각각 키보드 탐색과 말줄임·긴 한글 제목을 확인한다.
