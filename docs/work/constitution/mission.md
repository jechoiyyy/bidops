# BidOps mission

## 목적과 사용자
기획·사업개발 담당자가 실제 조달 요구와 회사 근거를 대조하고 추적 여부를 결정하도록 돕는다.
정본은 [PRD](../../PRD.md) §1~4 및 [업무 규칙](../../business-rules.md)이다.
자동 입찰·발주처 연락·최종 Go/No-Go는 사람의 책임이다.

## 이번 목표 — DEMO
2026-10-06 사용자 선택: 사내 격리 환경, 실제 사전규격, 전문 분야가 다른 가상 SI 3사,
회사 전환과 비교, 온톨로지·지식그래프의 분석 입력 및 탐색 화면 활용, 파일 기반 버전 관리,
기존 Luna 심층 경로, 공고 6건·적합성 18건·대표 3건×3사 심층보고서 9건.
심층검토 뒤 계속 추적·보류·종료를 사람이 저장하면 첫 데모의 업무 범위가 끝난다.
2026-10-09 재계획: `bidops-local` 격리 스택과 2026-10-06~08 실제 3일 수집 자료를 기준으로 구현을 계속한다.
DEMO-00은 로컬 데이터·문서 준비와 LiteLLM `local-agent-main` 개요 참조 실행을 선행 준비로 판정한다.
DEMO-00은 현재 run을 수동으로 main에 통합하되 운영 배포는 별도 전환 작업으로 남긴다. DEMO-01~05는 그 main에서 분기한 데모 브랜치와 `bidops-local`에서만 구현·검증한다. 보고서 인수 담당자는 사용자 본인이다.

## 성공 기준
동일 공고에서 각 회사의 긍정 근거·격차·미확인·후속 행동을 원문까지 설명할 수 있다.
회사별 결과와 결정이 섞이지 않고 실제 완료 보고서 9건을 열 수 있어야 한다(목표).
최소 시연 기준은 핏 18건과 대표 1건×3사 보고서 3건의 완료·인수이며, 나머지는 실패 기록과 함께 보여 주고 9건 완료로 적지 않는다.
분석 결과가 다를 이유를 확인하며, 다른 결과를 만들기 위해 모델 출력을 조작하지 않는다.
가상회사 설정과 실제 공고 사실, 모델 의견, 미확인을 분리한다. 참조 실행을 운영 품질로 승격하지 않는다.

## 범위 밖
발주계획 C-2 변경, 입찰 delta·최종 Go/No-Go, 외부 공개·SSO, 그래프 편집 UI,
문서 자동 추출 후 승인 UI, RDF/OWL·SPARQL·별도 그래프 DB는 이번 DEMO에 포함하지 않는다.
2026-10-06 재계획으로 그래프 SVG 시각화, 회사 핏 승인 화면, 기존 ID 직접 조회 API의 회사 경계 전수 점검(main 병합 전 별도 기능)도 뺐다.
기존 운영 범위와 향후 생애주기 목표는 폐기하지 않는다.

## 현재와 목표
현재 단일 활성 프로필·불변 근거·개요·회사 핏·심층검토 경로가 있다. 다회사/그래프는 목표다.
2026-10-09 로컬 참조 실행은 notice 179의 물리 4쪽만 승인해 LiteLLM 개요를 2회 호출로 완료했으며 `quality_status=unmeasured_reference`다.
이는 Luna 심층 보고서를 검증하지 않는다. 실제 Luna 완성 보고서 인수는 DEMO-03의 대표 1건과 DEMO-05의 3사·전체 인수 게이트에 남긴다.
