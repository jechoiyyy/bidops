# 1489번 실제 Luna 가정 분석 — 명세

작성: 2026-09-23. 상태: 구현 전 계약. [목적](intent.md) · [계획](plan.md).

## 입력과 계산

실제 입력은 1489번의 확정 문서 묶음·구조 스냅샷과 승인 회사 프로필이다. 미리보기에서
문서·프로필 버전과 hash, 이전 입력 대비 변경을 확인한다. 원본 접근 범위·객체 버전·hash
검사는 유지한다. 미확인 값을 추정하거나 최신 객체로 조용히 대체하지 않는다.

별도 불변 가정 버전에는 다음을 저장한다.

- 미확인 필수 참가 증빙이 유효하다고 가정한다.
- 담당·백업 인력을 확보했다고 가정한다.
- 근무시간 외 90분 안에 현장 도착할 체계를 확보했다고 가정한다.
- 부품·제조사 지원 확보 여부는 미확인으로 남긴다.
- 월 비용: PM 400,000원 + 담당 1,400,000원 + 백업 600,000원 + 당직 600,000원 = 3,000,000원.
- 초기 준비비 2,000,000원, 부품·제조사 지원비 시나리오 4,000,000원과 8,000,000원.

Decimal 코드로 3·6·12개월 × 가격 비율 90%·100% × 지원비 두 수준, 총 12행을 계산한다.
부가세 제외 매출 가정은 `35,199,815 / 1.1 × 가격 비율`, 원가는
`3,000,000 × 개월 + 2,000,000 + 지원비`다. 중간값은 반올림하지 않고 표시 시 원 단위
반올림 규칙을 명시한다. 차액의 명칭은 **가정상 잔액**이며 확정 이익이 아니다.
6·12개월은 실제 잔여 계약기간이 아닌 민감도 분석이다. 계산표는 서버가 소유하며
모델 숫자로 덮어쓰지 않는다. 모델 설명의 불일치는 해당 위치에 경고로 표시한다.

## 실행과 저장

기본 세 요청은 순차 실행한다.

| 단계 | 전달 자료 | 요구 결과 |
|---|---|---|
| 사업 조건 이해 | 실제 문서·원문 위치 | 과업·자격·평가·일정·계약 조건과 영향 |
| 회사 대조 | 문서·1차 결과·회사 사실·가정·계산표 | 적합성·수행 위험·경제성 |
| 판단과 행동 | 앞선 결과·근거·가정·계산표 | 종합 판단·다음 행동·판단 변경 조건·8절 완성 보고서 |

동일 문서 표현은 원문 위치 목록을 보존하면서 중복을 제거한다. 입력/출력 상한에
닿을 때만 문맥 단위로 나누고 모든 조각·호출을 기록한다. 조용한 잘림, 자동 재호출,
Qwen fallback은 없다. 한 문맥도 담지 못하거나 출력을 읽지 못하면 안전 코드로 실패한다.
effort 변경은 실제 지연·장황함·잘림을 확인하고 입력 중복/출력 요구부터 조정한 뒤
같은 모델의 지원 여부를 확인해 high, 필요 시 medium을 비교한다. 변경 이유·시간·품질
차이를 새 실행에 기록하고 과거 설정을 덮지 않는다.

가정 분석용 입력 버전·실행·단계 저장을 migration으로 추가한다. 입력·가정·프롬프트·
실행 설정을 불변 hash로 결속한다. 미리보기는 실행 승인이 아니며 승인 후에만 enqueue한다.
승인 시 현재 입력을 재검증하고 변경 시 새 미리보기를 요구한다. 동일 request ID는
같은 payload/담당자에만 멱등 응답하고 다른 payload면 충돌한다. 동일 공고 활성 실행은
하나다. 재실행은 새 승인·실행이며 과거 결과를 보존한다.

기존 문서·프로필·암호화 모델 응답 저장소·감사·큐 경계를 재사용한다. 합성 워커가
공용 슬롯을 소유하고 lease/heartbeat를 유지한다. 단계별 시작·종료·호출 수·소요 시간·
상태·안전 오류 코드를 저장한다. 원응답은 암호화 객체로 보존하고 일반 로그에 넣지 않는다.
실패한 단계 앞의 결과는 조회 가능하며 세 단계와 완성 보고서가 모두 있어야 완료다.

REST는 공고별 목록·미리보기·승인 실행 생성, 실행별 상태·부분 결과·보고서·근거 조회를
제공한다. 새 계약은 `bidops.assumption-analysis.v1`이며 기존 심층검토 API/정책 의미를
바꾸지 않는다. 구체적 DTO와 경로는 구현 시 이 문서에 확정한다.

## 검증과 근거

현행 Luna v3의 내용 검증 OFF는 모든 검사가 OFF라는 뜻이 아니다. 현행 코드는
승인/hash/lease/JSON schema/DB 식별자와 근거 FK/문서·프로필 소속/본문 보존 검사를
유지하고 있으며 실제 실행은 `dangling_evidence`로 중단된 기록이 있다.

| 처리 | 검사 |
|---|---|
| 차단 유지 | 자료 접근 범위, 승인 입력·hash·버전 무결성, 실행 식별, 중복/lease, 안전 렌더링 |
| 설명별 경고 | 인용·숫자 불일치, 누락, 잘못된 근거 연결, 내용 대조 미실시 |
| 미연결 보존 | 존재하지 않는 근거 ID는 실제 근거 FK로 저장하지 않고 원응답과 미연결 ID를 보존 |
| 단계 실패 | 읽을 수 없는 구조·잘림·외부 실패; 이전 단계 결과는 보존 |

선택적 관계 ID나 부수 형식 오류 하나로 읽을 수 있는 전체 본문을 폐기하지 않는다.
미연결·미확인·불일치를 검증된 사실로 표시하지 않는다. 실제 회사 사실, 실제 문서 사실,
사용자 가정, 모델 판단, 미확인을 구분하고 원문과 모델 인용을 나란히 확인할 수 있게 한다.

## A안 UI와 인수

사전규격 상세에 가정 분석 진입·미리보기·승인·상태·과거 실행 목록을 추가한다.
보고서는 기존 A안 구조를 실제 REST 데이터 컴포넌트로 연결한다. 왼쪽 8절 목차와 현재
위치, 넓은 설명형 본문·핵심 판단·대조표, 오른쪽 문서/회사/가정 근거를 제공한다.
집중 읽기·글자 확대·근거 닫기 후 초점 복귀·동일 본문 내려받기를 지원한다.

8절은 종합 판단·과업·회사 근거·수행 조건·평가·계약 및 경제성·다음 행동·판단 변경
조건이다. 조건 → 회사 영향 → 확인 사항 → 판단 변경의 연결을 읽을 수 있어야 한다.
제목·상태만으로 절이 완성됐다고 판단하지 않는다. 지원 viewport는 1280×800·1440×900이다.

최종 인수는 운영 웹에서 1489번 실제 생성 보고서 열기, 여덟 질문의 이유·영향 설명,
사실/가정/미확인 구분, 12행 계산 일치, 연결 원문과 미연결 표시, 두 폭 읽기 기능,
세 단계 및 완성 보고서 존재를 모두 확인한다. MOCK 통과는 실제 인수를 대신하지 않는다.

## 구현에서 확정한 세부 계약

- REST 경로·DTO는 [contracts.md](../contracts.md#1489번-가정-분석-v1-2026-09-23-운영-적용-전)에 고정했다.
- `assumption_input_version`, `assumption_run`, `assumption_stage` 세 표를 0033으로 추가한다.
  단계 표는 호출 종결 결과를 append하고 호출 시작 audit로 진행·시각·prompt hash를 보존한다.
- 입력 상한은 요청당 160,000자다. 기존 심층검토의 100,000자 상한은 바꾸지 않는다.
  원문 레지스트리에 전체 위치를 보존하며 프롬프트는 출처 ID·종류·본문·문서 순번/쪽
  인덱스로 전달한다. 마지막 요청은 앞선 결과가 참조한 출처와 모든 가정/미확인을 받는다.
  앞선 결과만으로 상한을 넘으면 `prior_context_too_large`, 문맥 하나가 넘으면
  `source_context_too_large`로 멈추며 자르지 않는다. 최종 종합이 여러 조각이면 부분
  결과를 보존하고 `report_incomplete`로 닫는다. 임의로 일부를 완성 보고서로 승격하지 않는다.
- 원 단위 표시는 ROUND_HALF_UP, Decimal precision 40이며 중간 반올림이 없다.
- 최소 설명 길이 검사는 빈 절/제목만의 결과를 막는 구조 검사일 뿐 의미 품질 통과가 아니다.
  숫자 토큰의 출처 미확인은 경고로 남기므로 표기 단위 차이도 경고일 수 있다.
- 현재 계약은 xhigh 고정이다. 낮은 effort 지원 여부·품질 비교는 실제 실행에서 필요성이
  확인된 뒤 새 불변 실행 설정으로 추가하며 아직 수행하지 않았다.
