## 검사 묶음

구현 시 아래 대상의 기존 테스트 파일에 회귀를 추가한다. 새 통합 검사는
`web/backend/tests/app/test_luna_deep_review.py`, 실행기 검사는
`web/backend/tests/deep_review/test_codex_runner.py`, UI 검사는
`web/frontend/tests/luna-deep-review.spec.ts`를 사용한다.

| 요구사항 | 입력·기대 결과 | 검사·증거 |
|---|---|---|
| 자동 생성 차단 | 개요/핏 완료·적재 → 심층 job 없음; 문서 준비·개요는 유지 | auto_preparation 관련 검사 |
| 요청 승인 | 정상, 누락, 다른 공고, 입력 변경, 다른 설정, 재실행 → 승인 결속 또는 명확한 거부 | 신규 app 검사·관련 Agent/API 검사 |
| 중복·이력 | 같은 요청 replay, 다른 요청 동시 제출, 실행 중 재요청 → 중복 실행 없음·과거 보고서 유지 | PostgreSQL 변형 포함 app 검사 |
| 실행 경계 | 고정 모델/effort, 제한된 env·파일, credential 미노출, 권위 schema 검증 | 실행기 검사; 가짜는 실제 CLI 계약과 대조 |
| 실패·종료 | 인증 실패·잘림·schema/근거 실패·timeout·lease 상실·늦은 결과 | 실행기/worker 검사; 실패 게시·process 정리 확인 |
| 저장→웹 | 합성 모델 결과 → 검증→DB→REST→보고서/근거·참조 표식 | app 산출 fixture를 UI에서 소비 |

백엔드 검사는 `BIDOPS_PRESPEC_OVERVIEW_ENABLED=false`를 기본으로 하고 자동화
사례만 명시적으로 켠다. API 응답 변경 검사는 `BIDOPS_TEST_POSTGRES_URL`을
일회용 PostgreSQL 17.11에 연결해 skip되지 않게 실행한다.

프런트는 production build 한 번과 관련 의미·구조 검사만 수행한다. 실패 원인이
코드인지 fixture인지 환경인지 분리하고 수정한 범위만 다시 검사한다. 검증 증거는
실행 후 `docs/validation-runs/20260922-luna-deep-review/`에 명령·결과·한계와 함께
남긴다. 실행 결과와 한계는 해당 경로의 [검증 기록](../validation-runs/20260922-luna-deep-review/README.md)을 따른다.

## 운영 적용·종료 기준

1. 기존 실행 상태, Codex 설치/인증 준비, 전송 입력, 적용할 정책·설정을 확인한다.
2. 백업·롤백 태그와 migration head를 기록한다. queued Qwen 작업의 감사 가능한
   중단 명령을 준비하고 running 작업은 종료를 기다린다.
3. migration·재배포·정책 적용·실제 모델 호출은 각각 직전 사람 확인 후 실행한다.
4. 실제 웹 요청에서 202, 진행 상태, 실제 provider/model, 검증된 보고서와 원문을
   확인한다. 순차 처리도 확인하고 개요검토가 계속 처리됨을 확인한다.
5. 실제 문서와 사람이 대조한다. 실행 성공을 의미 품질 측정이나 정책 활성화
   근거로 승격하지 않는다. 표본 실행 전에는 실제 연결 검증 완료로 쓰지 않는다.

적용 명령·백업·롤백·기존 queued 처리와 단계별 확인은 [적용 절차](apply.md)에 준비했다. 후속 사용자 요청으로 운영 migration·재배포·정책 적용과 무자료 모델 연결을 수행했다. 후속 승인을 받은 1489번은 실제 전송 뒤 주장 참조 검증 실패로 종료했다.

## 이번 구현의 검증 결과

- 일회용 PostgreSQL 17.11에서 신규 migration, 이전 head 승격, append-only, app/worker 권한, 동시 요청을 검사했다.
- 승인·입력 동결·3단계·보고서·근거·실패·lease 만료·fallback 차단을 합성 입력으로 검사했다. 초기 격리 검사에서는 Codex를 호출하지 않았다.
- 새 DB 산출 fixture를 연결한 UI 두 폭과 관련 보고서·문서 준비·사전규격 의미 검사를 실행했다.
- lease 만료 뒤 응답 수락 문제를 수정하고 해당 회귀를 재검사했다. 기존 자동 시작 테스트는 신규 기본값과 구분해 명시적으로 켰다.
- runner 이미지 빌드, 고정 CLI 버전, Compose 격리를 확인했다. 후속 실제 연결은 확인했다. 실제 두 건의 큐 대기→선행 실패 종료→후속 시작은 확인했다. 방화벽 allowlist와 개요 처리 재개는 미검증이다.
