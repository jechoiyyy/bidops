# Luna 심층검토 — 목표 명세

- 작성: 2026-09-22. 상태: 구현·운영 적용 완료, 공고 실자료 인수 대기. [목적](intent.md) · [계획](plan.md) · [결정](decision.md).

## 요청과 표시

1. 개요검토 완료, 확정 문서 묶음, 유효한 회사 프로필·분석 정책, 기존 수동
   심층검토 자격을 서버에서 확인한다. UI는 서버의 요청 불가 사유를 표시한다.
2. 기존 사전규격 상세에서 전송 미리보기를 만든다. 문서 내용·회사자료 범위,
   모델, 원문 대조 설정, 참조 분석·품질 미측정 표식을 확인하게 한다.
3. 담당자 입력과 최종 요청 제출을 해당 실행의 외부 전송 승인으로 기록한다.
   담당자는 감사 표식이며 인증으로 취급하지 않는다.
4. 요청은 202로 큐에 등록하고 합성 워커가 순차 처리한다. 목록·상세에
   대기/실행/완료/실패와 보고서 연결을 표시한다. 준비 부족은 실행 실패와 구분한다.
5. 동일 요청 ID 재전송은 같은 응답을 돌려준다. 대기·실행 중 중복 실행은 막는다.
6. 실패 사유는 안전한 코드로 표시한다. 새 요청은 새 실행 이력을 만들고,
   이전 완료 보고서·사람 수정·의견은 계속 조회할 수 있다.

## API와 저장 계약

- `POST /api/notices/{notice_id}/deep-review-previews`: 입력을 동결하고
  `preview_id`, 입력 해시, 전송 내용, 모델·정책·설정 정보를 반환한다.
- 기존 생성 및 재실행 API: `preview_id`를 받아 Luna 실행 승인을 연결한다.
  미리보기 없는 Luna 요청은 거부하고, 승인 시 입력 버전이 바뀌면 409로
  재확인을 요구한다. 직접 service/Agent 진입도 같은 검사를 통과해야 한다.
- 미리보기·승인 저장소는 migration으로 추가한다. 문서·프로필·정책·설정
  버전, 입력 해시, 승인자·시각, 실행 연결을 보존한다. 본문은 일반 감사 metadata에 넣지 않는다.
- 조회 응답에 provider·모델·추론 설정을 추가한다. 과거에 없는 값은 `null`로 둔다.
- 목록 상태는 페이지 단위 일괄 조회한다. 프런트에서 상태나 자격을 재판정하지 않는다.
- 응답 소비자인 Pydantic·Agent·TypeScript·fixture와 계약 문서를 함께 갱신한다.

## 자동화·정책 경계

- 심층검토 자동 시작 설정을 추가하고 기본값을 비활성으로 둔다. 개요 완료,
  회사 핏 완료, 적재 등 모든 자동 생성 진입점에 적용한다.
- 자동 시작 비활성은 정상적인 수동 요청 대기다. 문서 준비·개요검토를 끄거나
  완료된 개요를 실패로 바꾸지 않는다.
- 새 불변 Luna 정책은 provider `codex-exec`, 모델 `gpt-5.6-luna`, effort `xhigh`,
  stage/report v2, 품질 미측정과 timeout을 고정한다. Qwen 정책을 수정하지 않는다.
- 기존 Qwen 실행은 Luna로 자동 전환하지 않는다. 전환은 새 정책의 새 검토로 한다.

## 실행과 검증 경계

- 큐·잠금·lease·상태 전이·보고서 저장의 소유자는 기존 합성 워커다.
- 내부 Codex 실행 컨테이너는 합성 워커 요청만 처리한다. 별도 큐 소비자는 없다.
  DB·MinIO 자격증명·저장소·호스트 홈을 마운트하지 않는다.
- 별도 Compose overlay로 CLI 버전, 전용 인증 secret, 필요한 외부 통신을
  명시한다. web이나 기본 내부망에 광범위한 외부 통신을 추가하지 않는다.
- 고정 argv, 사용자 설정 배제, 임시 디렉터리, read-only sandbox, ephemeral,
  출력 schema를 사용한다. 사용자 입력을 shell command로 조립하지 않는다.
- 기존 입력 분할·3단계의 요청을 Luna 어댑터가 `InvocationResult`로 연결한다.
  vLLM 전용 생성 옵션은 전달하지 않는다. CLI용 출력 schema는 권위 stage v2에서
  파생하되 반환 결과는 기존 권위 schema·근거·숫자·입력 범위 검증을 통과해야 한다.
- 후속 입력에는 승인된 원천 입력과 같은 실행에서 검증된 선행 결과만 포함한다.
- 호출당 15분·검토 전체 2시간으로 제한한다. 자동 모델 재호출·자동 resume는
  하지 않는다. timeout·소유권 상실 시 하위 프로세스까지 종료하고 늦은 결과를 거부한다.
- 호출 중에도 lease를 갱신한다. lease가 만료된 작업은 실패로 닫고 사람이 재요청한다.
- 모델·추론 설정·CLI 버전·입출력 해시를 기록한다. 확인되지 않은 revision은 추정하지 않는다.
- 인증/모델 접근/timeout/잘림/schema/근거 실패를 구분한다. 일부 출력을 성공으로
  게시하지 않고 다른 모델로 fallback하지 않는다.
- 원응답은 기존 암호화 저장 경로로 보존한다. 입력·응답·인증은 일반 로그에
  남기지 않고 임시 파일은 종료 시 정리한다.

## 호환과 운영 적용

기존 stage/report v1·v2 읽기와 기존 Qwen 이력은 유지한다. 새 기능의 배포 전에
queued/running Qwen 작업을 조회하고, 실행 중 작업은 종료를 기다린다. 남은 대기는
감사가 남는 관리 명령으로 중단한다. SQL 수정이나 기존 작업의 provider 변경은 하지 않는다.

전체 백업·롤백 태그·migration 정보를 준비한 뒤 각 운영 단계 직전 확인을 받는다.
장애 시 신규 Luna 요청을 차단하고 기존 조회·수집·개요검토는 유지한다.
