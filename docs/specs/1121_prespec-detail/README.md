# 사전규격 상세 화면 재기획 시안 (2026-11-21)

사전규격 상세(`/pre-specs/:id`)를 실무자가 쓰는 정보만 남겨 다시 짠 시안이다. 분석 엔진(deep-agent)이 돌기 전 화면과 완료 뒤 화면 두 가지를 다룬다.

**상태: 시안, 승인 전.** 제품 코드·테스트·규칙 문서는 바꾸지 않았다. 화면 변경은 시안 승인 뒤에 구현한다(`docs/specs/0915_ui-redesign/decisions.md`).

| 파일 | 내용 |
|---|---|
| mockups/index.html(`docs/1121_prespec-detail/mockups/index.html`, git 이력) | 독립 HTML 시안. `?s=a1…b3`로 상태를 바꾸고 `?bar=0`으로 위쪽 안내 줄을 숨긴다 |

## 결정 (2026-11-21, jechoi)

| 항목 | 결정 |
|---|---|
| 가운데 정렬 | 본문 묶음에 읽기 폭(1040px)을 두고 패널 가운데에 놓는다. 패널 안 글자·표는 왼쪽 정렬 |

## 현재 화면에서 확인한 것 (운영 3753, 2026-11-21)

- 본문 길이는 1440 폭에서 5,494px이다. 구역별로 머리 335, 추적 결정 265, 주요 과업 488, 근거·첨부 733, 처리 이력·문서 준비 3,504, 참여 판정·회사 적합성 170이다.
- 처리 이력 구역의 3,504px는 대부분 개요 범위 확인 폼의 절 후보 38개 목록이다. 개요가 이미 완료된 건인데도 펼쳐져 있다.
- 개요 주장 10개가 주요 과업 구역과 근거·첨부 구역에 두 번 나온다. 사업 요약 첫 문장은 머리에도 한 번 더 나온다.
- 마감·SW사업대상·사업구분이 칩과 사실 줄에 두 번 나온다. "보류·추적 종료는 사업 추적에서 변경"도 두 번 나온다.
- 참여 판정·회사 적합성·위험 3칸은 3753에서 모두 "꺼짐"이나 "없음" 문구다. 발주계획 후보는 0건이다.
- 첨부 표는 "첨부 1 · 확장자 미확인 · 크기 미확인 · 본문 추출 미확인"으로 나온다. 같은 파일의 이름(`제안요청서.hwpx`)과 준비 상태는 문서 묶음 응답에 있다.

## 두 화면의 구성

공통: 셸 패널 헤더(`‹ 사전규격`, 작은 줄, 제목, 이전·다음)는 그대로 쓴다. 본문과 헤더 안쪽을 같은 읽기 폭(1040px)에 맞춰 가운데에 둔다. 구역은 제목 줄과 구역 사이 옅은 선 한 줄로 나눈다.

### 하단 결정 띠

패널 아래에 73px 높이로 고정한다. 추적 결정만 담고, 모든 상태에서 같은 자리에 있다. 화면의 주 버튼은 이 띠에 하나만 둔다.

| 상황 | 띠의 내용 |
|---|---|
| 분석 전 · 추적 미선택 | 상태 한 줄과 경계 문장 · 선택 사유 · [추적 시작하기] |
| 분석 완료 | 현재 추적 상태 · `결정 없이 확인만 기록` · 계속 추적 / 보류 / 종료 · 결정 사유 · [추적 결정 저장하기] |
| 분석 전 · 이미 추적 중 (시안에 없음) | 현재 상태 · 담당자 · 일시와 `사업 추적에서 상태 관리` 링크. 단추 없음 |
| 검토 제외·사업기회 미연결 (시안에 없음) | 결정할 수 없는 이유 한 줄. 단추 비활성 |

- 추적 외의 할 일은 띠에 넣지 않는다. 개요 범위 확정은 개요 구역 자리에, 분석 승인 대기는 사실 줄 아래 한 블록에 두고 단추는 보조 모양으로 그린다.
- 1280에서 근거 서랍은 띠 위까지만 덮는다. 근거를 보는 동안에도 결정 단추가 보인다.

### 분석 전

| 순서 | 구역 | 내용 |
|---|---|---|
| 1 | 사실 줄 | 의견 마감(D-n) · 사업 예산 · 구분 · 게시. 아래에 사전규격번호·나라장터 원문·본공고 |
| 2 | 사업 개요와 주요 과업 | 검토 범위·품질 표식 한 줄, 사업 개요, 주요 과업, 사업 규모와 일정. 주장마다 쪽 링크 |
| 3 | 원문·첨부 | 파일 · 형식 · 상태 · 열기 |

### 분석 완료

| 순서 | 구역 | 내용 |
|---|---|---|
| 1 | 사실 줄 | 분석 전과 같음 + 추적 상태 |
| 2 | 분석 결과 요약 | 건수 세 줄(자격 조건·요구사항·리스크)과 엔진 참고 의견을 나란히, 아래에 분석 기준 줄 |
| 3 | 차단·자격 조건 | 차단 → 위험 → 미확인. 충족은 접음 |
| 4 | 확인할 일 | 추적 판단을 바꾸는 확인, 수행 방안 확인. 배점 추정용 자료는 접음 |
| 5 | 요구사항 대응 | 필터(부족·미확인 / 부분 / 충족 / 전체). 행의 `근거 보기`로 근거 패널을 연다 |
| 6 | 리스크 | 상만 먼저, 중·하는 접음 |
| 7 | 인력·계약 조건 | 인력 표와 계약 조건 목록 |
| 8~10 | 사업 개요(접힘), 원문·첨부, 처리 상태·기술 정보(접힘) | |

- 헤더 탭 자리에 구역 이동 링크를 둔다. 내용을 숨기는 탭이 아니다.
- 근거 패널은 1440에서 표 옆에 열리고 회사 근거·조치 열을 숨긴다. 1280에서는 오른쪽 서랍이다. Esc로 닫으면 초점이 원래 단추로 돌아온다.
- 판정 표식은 글자가 상태 이름이다. 차단·부족은 오류색, 위험·미확인·부분은 주의색, 충족은 회색이다. 품질이 측정되지 않은 결과라 충족에 성공색을 쓰지 않았다. 엔진 참고 의견은 모델 판단 표식(보라)이다.

| 상태 | 내용 |
|---|---|
| b1 분석 완료 | 실제 규모. 차단 0건, 위험 1건, 미확인 1건. 쪽 번호 없는 근거 |
| b2 부분 결과 | 읽지 못한 범위 알림, 요구사항 `읽기 실패` 12건, 차단 1건, 쪽 번호 있는 근거, 이미 추적 중 |
| b3 근거 열림 | b1에서 요구사항 행의 근거 패널을 연 모습 |

## 실제 엔진 결과에서 확인해 설계에 반영한 것

저장소 밖 원본 엔진의 실제 결과 하나(자격 조건 7, 요구사항 41, 리스크 11, 확인 요청 63)를 구조와 건수의 기준으로 삼았다.

- **확인 요청 63건 중 58건은 배점 추정용 회사 필드 이름이다**(`company.founded` 같은 키). 평가 배점을 화면에 넣지 않기로 했으므로 접어 두었다. 추적 판단을 바꾸는 확인은 `assessment.provisional.conditions`(2건)와 수행 확인(5건)에서 가져왔다.
- **모든 근거에 쪽 번호가 없다.** 41건이 같은 절 하나를 가리키고 위치 상태가 `unavailable`이다. 그래서 b1은 쪽 대신 `근거 보기`로 원문 발췌를 연다.
- **필수 여부가 41건 모두 비어 있다.** 표에 필수 열을 두지 않았다. 2026-11-21 실사용 테스트(3건 모두 원문에 표기 없음) 뒤 필수 여부는 화면과 엔진 결과에서 제거하기로 했다(jechoi).
- **차단이 0건이다.** 판단을 가르는 것은 위험 1건(상주)과 미확인 1건이다. RL-11 시안의 "차단 1건이 머리 문장으로 나오는" 구성은 이 결과에서는 나오지 않는다.
- **엔진 의견은 판단 보류이고 잠정 의견이 따로 있다**(`assessment.state=abstain`, `provisional.decision`). 참고 의견 한 줄에 둘을 함께 적었다.
- **대응 상태는 네 값이다**(충족·부분·부족·미확인). RL-11 명세의 세 값에는 "부분"이 없다.

`shots/` 캡처와 시안 DOM 집계로 확인했다. 앱 빌드·화면 테스트는 돌리지 않았다(문서·시안만 바꿈).

| 가운데 배치 | 1440에서 본문과 헤더 제목이 같은 왼쪽 선(310px)에서 시작한다. 1280은 가용 폭(978px)이 읽기 폭보다 좁아 현재와 같다 |

확인하지 못한 것:

- 1920 폭 캡처는 찍지 않았다.
- 긴 제목(두 줄), 요구사항 100건 이상, 첨부 여러 개인 경우는 시안에 없다.
- 분석 전 화면의 "회사 관련성 참고" 구역(회사 적합성·RL 판정 값이 있을 때)은 그리지 않았다.

## 문제 상태 안내 (2026-11-21 추가, 사용자 확인 뒤 구현)

사용자(jechoi)가 시안 c1~c5를 확인하고 "확인했어 적용해줘"로 구현·운영 반영을 승인했다. 같은 날 "'원문 URL 없음'와 같은 안내문은 삭제해야지"에 따라 식별 줄의 원문 주소 없음 안내를 지웠다(사전규격 API는 상세 주소를 주지 않는다. 주소가 왔는데 쓸 수 없을 때만 `원문 링크 확인 불가`).

배포 뒤 운영 최근 200건(전체 1,258건)을 집계하니 개요 완료는 85건이고, 50건은 개요 실패·사람 확인 필요, 46건은 문서 준비 막힘으로 열린다. 이 상태들에서 화면 위쪽은 실제 사유를 말하지 않고(모두 "사유 코드 없음 — 결정적 선택기가 범위를 정하지 못했어요" 또는 "개요 검토 미시작") 처리 상태 구역 전체가 자동으로 열려 본문이 2,000~4,200px가 된다. 집계와 원인은 [findings](../../tracking/findings/model-review.md)에 있다.

시안은 `mockups/index.html`의 `?s=c1`~`c5`이고 캡처는 `shots/c*-{1440,1280}.png`, 처리 상태 구역을 연 모습은 `?open=1`(`shots/c*-open-*.png`)이다.
