# 엔진 회사 근거 입력 보완 — 실적 원문 발췌(1단계)와 업무 근거 지도 기반 판정(2단계) (2026-11-24)

## 배경

- 포트폴리오 엔진 분석 45건 중 44건이 관련 실적 상위 5건 중 1건만 읽었다. 위키 실적 넣기가 실적 페이지에 원문 요구사항 전체 목록을 붙여 페이지가 1만~2만2천 자가 됐고, 관련 실적 예산(16,000자)에 한 건밖에 들어가지 못했다.
- 같은 목록이 관련 실적 순위 계산(`수행한 요구 범위` 절의 단어 겹침)에도 들어가, 목록이 긴 실적이 거의 모든 공고에서 상위를 차지했다(P2025-08 43/44, P2026-01 40/44, 목록 없는 실적 15건은 한 번도 선택되지 않음).
- 엔진 규칙상 `GAP`(부족)은 회사 프로필의 명시적 부정값에서만 나온다. 45건 2,854개 판정 중 GAP은 20개(0.7%)이고 모두 상주 조건이다. "수행 기록 없음"은 판정으로 나오지 않는다.
- 2026-11-24 사용자 결정: 위키 실적 목록을 회사 수행 기록의 전부로 보고, 업무 근거 지도 기준 `기록 없음`을 `GAP`(수행 기록 없음)으로 판정할 수 있다. `UNKNOWN`(판단 자료 없음)과 구분한다.

## 2단계 — 업무 근거 지도 기반 근거 연결과 `수행 기록 없음` 판정 (설계)

### 2.1 지도의 실제 모습

- `company-bundle/rootlab/work-units.json`: 주제 38개, 업무 단위 263개(각 `covers`·`not` 설명), 근거 3,969건(`{project, req_id, unit}`), `no_record` 0건. 분류표 텍스트 약 25,900자.
- 업무 단위는 과거 수주 RFP 요구사항을 분류해 만들었으므로 **모든 단위에 근거 실적이 있다**(근거 0건 단위 없음). 따라서 "기록 없음"은 "새 공고 요구사항이 어느 업무 단위에도 해당하지 않음"으로 정의해야 한다.
- 지도에 들어간 실적은 **23건**이다. 회사 프로필 실적 58건 중 위키 페이지가 있는 것 38건, 원문 요구사항이 지도에 들어간 것 23건, 페이지 없이 프로필에만 있는 것 20건.

### 2.2 흐름

1. **공고 요구사항 분류(새 단계, 모델 1회)**: 위키 실적 넣기의 분류 규칙(`wiki_tools.build_ingest_prompt`의 분류표·규칙)을 재사용해 공고 요구사항마다 `units`(0개 이상)와 `uncovered`(어느 단위에도 들지 않는 부분의 짧은 구절)를 낸다. 새 단위 제안은 금지한다. 검사는 `validate_mapping` 규칙(요구사항 id 목록 일치, 분류표에 있는 단위만)을 쓰고 실패하면 수정 요청 1회(`build_repair_prompt`), 그래도 실패하면 이 단계 결과 없이 1단계 방식으로 진행한다(fail closed: GAP을 만들지 않는다).
2. **결정적 연결**: 단위 → 근거 `{project, req_id}`. 
   - 관련 실적 = 이 공고의 단위들을 뒷받침하는 실적을 근거 단위 수 내림차순으로(동점은 slug). 단어 겹침 순위를 대신해 순위 편향을 없앤다.
   - 발췌 = 그 실적의 근거 `req_id` 줄(단어 겹침이 아니라 지도가 가리키는 줄). 상한은 1단계와 같다.
3. **매칭 입력**: 요구사항마다 분류 결과(단위·근거 실적·`uncovered`)를 붙인다.
4. **판정 규칙(매칭 프롬프트에 추가, 사용자 기준 2026-11-22~24)**:
   - 모든 부분이 단위에 들고 각 단위에 근거가 있으면 `FULL`. 근거 실적이 여러 건이면 합쳐서 판단하고 `evidence_portfolio_ids`에 모두 적는다.
   - 일부만 단위에 들면(`uncovered` 있음) `PARTIAL`, `gap_action`은 `uncovered` 부분.
   - 어느 단위에도 들지 않으면 `GAP`, 근거 문장 "업무 근거 지도의 어느 업무 단위에도 해당하는 수행 기록이 없음" + 지도 기준(실적 n건)을 rationale에 쓴다.
   - 분류가 없거나 실패했으면 지금 규칙 그대로(`UNKNOWN` 가능, GAP은 프로필 부정값에서만).
   - 하드웨어 범위 규칙·상주 규칙·자격 판정은 지금과 같다.
5. **화면**: `부족` 표식을 `부족 · 수행 기록 없음`으로, `미확인`을 `미확인 · 판단 자료 없음`으로 나누어 쓰고, 부족의 기준(지도 실적 n건, 기준일)을 상세에 적는다.

### 2.3 사람 결정이 필요한 것

1. **지도 범위**: 지도는 실적 23건만 다룬다. "위키 실적 목록 = 회사 수행 기록 전부"라는 결정이 GAP의 근거가 되려면 (a) 나머지 실적(원문 RFP가 있는 것)을 지도에 넣거나, (b) GAP을 "지도에 있는 실적 23건 기준 수행 기록 없음"으로 범위를 밝혀 쓰고 지도 밖 실적 35건을 화면에 함께 밝힌다. 권장: (b)로 먼저 측정하고 (a)는 원문 RFP를 확보하는 만큼 늘린다.
2. **모델 호출 증가**: 공고당 분류 1회(+수정 1회 상한)가 늘어난다. 입력은 분류표 약 2만6천 자 + 요구사항.
3. **원본 엔진과의 관계**: 새 단계·프롬프트 규칙은 원본(bid-deep-agent)과 큰 차이가 된다. 원본 저장소에서 먼저 구현해 동기화하는 편이 ADR-0074에 맞다.
