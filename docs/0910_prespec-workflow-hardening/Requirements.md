# 사전규격 수집·개요 검토 안정화 요구사항

작성일: 2026-09-10 · 상태: 구현 전 · 결정 근거: [ADR](ADR.md)

## 목적과 대상

기획·사업개발 담당자가 사전규격 개요의 주장과 원문을 대조할 수 있게 하고, 재수집·모델 장애·작업 중지가 원본 보존과 현재 결과의 정확성을 해치지 않도록 한다. 검증 구간은 발주계획·사전규격의 독립 수집, 기존 판정·첨부 준비, 명시적 v4 개요 실행, 웹 조회까지다.

새 사실 검증은 v4 설명형 개요의 새 실행에 적용한다. 기존 권고형 개요는 읽기와 실행 호환성을 유지하되 모델 복구·다른 문서의 큐 처리 수정은 함께 적용한다.

## 기능 요구와 인수 조건

| 식별자 | 요구사항 | 인수 조건 |
|---|---|---|
| `collection.exclusive` | 새 회차만 생성 | 기존 빈 폴더·파일·symlink에 대한 실행이 파일 변경과 HTTP 호출 없이 실패한다. 같은 출력 경로를 경쟁하는 두 프로세스 중 하나만 회차를 획득한다. |
| `collection.reclassify` | 기존 raw 읽기와 새 결과 쓰기 분리 | 원본 hash가 유지되고 새 회차에 provenance와 raw가 보존된다. 웹 수집·재분류·스케줄 호출도 같은 계약을 따른다. |
| `collection.partial` | 부분 산출물을 완료와 구분 | 페이지 수집 중 실패하면 이미 쓴 raw는 남고 완전 수집으로 게시하지 않는다. 새 회차에서만 재실행할 수 있다. |
| `overview.freeze` | 모든 호출은 같은 동결 입력·승인 binding 사용 | document/PDF/page text/선택 범위/policy/prompt/model/activation hash가 추적된다. 변경·불명확한 입력으로 호출하거나 게시하지 않는다. |
| `overview.claims` | 모든 사실 문장을 주장으로 관리 | 사업 개요·과업·예산/기간·조건·검토 포인트의 사실이 빠짐없이 claim과 근거로 연결된다. 자유 문자열 필드로 검증을 우회할 수 없다. |
| `overview.grounding` | 인용과 수치 관계를 결정적으로 검사 | 기간→예산, 원→억원, 사업 주체·VAT·기산점·날짜·요구사항 ID의 뒤바꿈을 통과시키지 않는다. 모호한 표·단위·인용은 사람 검토로 간다. |
| `overview.semantic` | 별도 Qwen 호출로 의미 검토 | 모든 claim에 정확히 한 판정이 있고, 누락·중복·알 수 없는 ID·불확실·모순이면 통과하지 않는다. 결정적 실패에 대한 추가 의미 호출은 하지 않는다. |
| `overview.publication` | 전체 통과한 초안만 최종 구성 | 불일치가 하나라도 있으면 `needs_human_review`, `result_id=null`이다. 최종 사실 문장은 검증된 claim text와 일치한다. |
| `overview.budget` | 호출·시간 제한과 원응답 보존 | 정상 2회, 초안 형식 재시도 포함 최대 3회다. 사실 수정 반복·무한 재시도·hosted fallback이 없다. 실제 응답과 실패 이력이 암호화·불변 보존된다. |
| `worker.recovery` | 일시적 연결 장애에서 재기동 없이 복구 | fake clock에서 최초 identity 실패 후 지정 간격에 재확인하고, 복구 후 같은 승인 binding의 대기 작업이 진행된다. 대기 중 문서 payload 전송은 0회다. |
| `worker.dispatch` | 비활성 v4와 다른 문서의 기존 개요 분리 | OFF·binding 불일치·모델 대기 상태에서도 만료를 정리하고 처리 가능한 다른 문서를 배정한다. v4 예약 문서는 legacy로 우회하지 않는다. |
| `worker.stop` | 중지 이후 신규 실행과 결과 게시 차단 | queued/running을 취소하고 연결된 WorkJob을 닫는다. 중지와 완료가 경쟁해도 중지 확정 후 게시 0건이며 OFF→ON 뒤 늦은 결과도 차단한다. |
| `web.truthful` | 현재 상태·실패 주장·근거·이력 구분 | 최신 실패·중단을 과거 성공으로 대체하지 않는다. 인용은 정확한 문서의 물리 PDF 페이지로 열린다. 오래된 결과는 새 검증 통과로 표시하지 않는다. |
| `downstream.gate` | 검증 실패가 후속 분석에 사용되지 않음 | 새 계약의 현재 완료·전체 통과 결과만 후속 입력 후보가 된다. 회사 핏 활성화·추적 승인·Go/No-Go는 생성하지 않는다. |

## 보존·보안·운영 요구

- 기존 수집 파일, 입력 스냅숏, 모델 결과, 사람 리뷰는 덮어쓰지 않는다. `unknown`, `null`, 미기록 경고와 참조 품질 표식을 유지한다.
- 수집·판정 모듈은 기존 subprocess·파일 계약으로 연결한다. 웹이 skill 내부 함수를 import하거나 업무 규칙을 복제하지 않는다.
- 사설 vLLM은 `ModelClient.for_purpose("overview")`의 allowlist·64자 hex revision 게이트를 통과해야 한다. 초안과 의미 검토 모두 건별 승인 범위에 들어 있어야 한다.
- 원문 위치·자격증명·회사자료·원응답·모델 reasoning을 일반 로그나 오류 API에 노출하지 않는다. 웹의 실패 진단은 검증된 locator와 제한된 주장 텍스트만 제공하고, 미검증 상태를 명시한다.
- 서버의 응답 원문은 암호화 저장한다. 원응답 저장이나 검증 기록의 영속화가 실패하면 완료 결과를 게시하지 않는다.
- migration은 운영 서비스에서 자동 실행하지 않는다. 새 테이블의 app/worker 권한은 명시적으로 부여하며 원문 저장소 읽기 권한을 analysis-worker에 추가하지 않는다.
- 웹 지원 폭은 1280×800과 1440×900이다. 기존 Astryx·프로젝트 테마를 따른다.

## 검증 표본의 필수 사례

| 분류 | 반드시 포함할 사례 |
|---|---|
| 수치 관계 | `6개월`만 있는 원문에서 `6억원` 주장, 8천만원↔8억원, 감리 예산↔대상 개발사업 계약금액, VAT 포함↔제외, 계약일↔착수일 |
| 의미 관계 | 계획수립↔실제 구축, 감리↔개발, 금지↔허용, 협의 가능↔필수, 조건부↔무조건, 예시 일정↔확정 일정 |
| 인용 | 다른 문서·범위 밖 페이지·없는 구절·여러 위치에 중복된 구절·부정문 일부만 인용·문서 내 모델 지시문 |
| 완료와 장애 | 정상 통과, 형식 재시도 성공/실패, 결정적 실패, 의미 불확실, 의미 응답 누락, timeout, 원응답 저장 실패 |
| 동시성 | 같은 출력 경로 수집 경쟁, 중지↔claim, 중지↔게시, OFF→ON↔늦은 응답, lease 만료 후 응답, 기존 policy attempt 잔존 |
| 화면 | 현재 완료, 사람 검토, 실패, 취소, stale, 범위 확인 대기, 과거 v3·Luna 참조 결과와 새 결과 공존 |

## 완료의 구분

**구현 완료:** 위 요구를 검증하는 관련 collector·backend·임시 PostgreSQL·frontend 검사가 통과하고 계약·운영 문서가 코드와 일치한다. 미실행·skip은 남은 한계로 기록한다.

**실사용 참조 검증 완료:** 지정한 새 표본으로 사설 Qwen 실행, 원문과 주장 대조, 웹 확인, 호출 수·시간·실패 상태 기록을 마친다. 사람 판정은 모델 결과와 별도로 보존한다. 모델 품질의 운영 승인과 C-2 활성화 조건 충족은 별도의 판단이다.

현재 문서 작성은 두 완료 상태 중 어느 것도 의미하지 않는다. 추가 제품 결정에 대한 인터뷰는 남아 있지 않으며, live 실행 시점의 대상·환경·전송 승인 정보는 실행 준비물로 남는다.
